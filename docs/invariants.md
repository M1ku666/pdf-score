# 不变量 · PDF Score

**动代码前先读这一份。** 这里每一条写错了都会**算错数据**（不是风格问题），要改必须先把「会错成什么样」讲明白、等用户拍板，然后**先改文档再改代码**。

具体结构与算法见 `data-format.md` / `concepts.md`；组件内的细节见各文件头部注释。

---

## 1. 坐标：几何量一律 pt，y 的翻转在「渲染 / 命中」与「滚动落点」两处各做一次

- 存进 meta 的几何量**只有 PDF 原始点坐标 pt**（`pages[].width/height`、`systems[].y0/y1`、`bars[].x`），与显示缩放完全解耦。
- 屏幕坐标 = `pt × scale`，`scale = 显示 CSS 宽 / 页宽`（这一档里已经含了**谱面缩放倍数**，见 `docs/ui.md` §18.68）。**不要把屏幕 px 写回 meta**。overlay 的 `viewBox="0 0 页宽 页高"` 会自动换算，所以 overlay 里的描边宽度、字号也都是 pt。画出来的 y 还要在 **overlay 这一侧**就夹进 `[0, 页高]`（`ScorePage` 的 `clampY`：四类标记的本体上下都夹，行顶上方那套栈只夹上边，见 `docs/ui.md` §18.48）—— **夹的是画出来的位置，别把夹过的值写回 meta**。
- 同一页里 `systems` 按 `y0` **降序**（PDF 的 y 轴向上，第一行是 `y0` 最大的）、`bars` 按 `x` **升序**。`normalizePage` 与 `deriveStructure` 都会重排并依赖这一点；**任何插入路径都要自己重排**。
- **`y0` / `y1` 谁是上沿没有统一约定**：`addSystem` 写出来的行是「`y0` = 下沿、`y1` = 上沿」，自动识别写出来的是反的（「`y0` = 上沿、`y1` = 下沿」，见 `omr.js` 的 `toPt.y` 与 `toMetaSystems`）。所以**取一条行的上沿 / 下沿一律用 `Math.max` / `Math.min`** —— 排序用 `y0` 降序两种写法都对，但「量到这一行的哪一条边」照字面读 `y0` 只在其中一种写法上成立。**改错会怎样**：`PdfViewer.peekHeight()` 把 `y0` 当「下沿」量，自动识别的谱就只量到那一行的**上沿** —— 末行该露出的下一页第一行整条留在下方工具栏后面。
- meta 是 y-up、overlay 与 DOM 是 y-down，差一次 `y → 页高 − y` 的翻转：**凡是要拿 meta 的 y 算屏幕位置，都得翻一次**（写回 meta 时翻回来）。做这一翻的只有两处：渲染与命中在 `ScorePage` 的边界（读：渲染用的那几个 computed；写：`system-add` 抛出之前），滚动落点在 `PdfViewer.placeBand()`。schema / timeline / player 层**始终只见 meta 的 y-up 值**。
- **改错会怎样**：翻转漏做或做两次 → 整个标记层上下镜像、小节编号从下往上数，`placeBand()` 漏翻则「始终居中」把当前这一行摆到页面上下镜像的位置上；`height = y1 − y0` 在翻转后变负数、被夹成 0.5pt 直接看不见（必须写成 `Math.min` + `Math.abs`）。命中判定（`hitSystem` / `hitMeasure`）、ghost 预览、`.m-active` / `.m-sel` 这些矩形都要一起看。
  **跳转弧线那一层（`JumpArcs`）也一样**：它在页面之外按内容坐标画，两端的 y 也要走同一次翻转（页高 − `max(y0, y1)`）。

## 2. 「可视区」= 视口扣掉上下两条工具栏

- 底栏那对胶囊（`.bottom` → `reserved`）与顶部那两条（`.back-dock` / `.mini-dock` → `reservedTop`）都是**浮在谱面上**的。
- `PdfViewer` 里凡是拿「可视区」（= 视口 − `reserved` − `reservedTop`）的地方都要减掉这两段：
  `pageScale()`（贴合比例）、`paddings()`（上下垫的空白 —— 两种显示方式都从它出）、
  `placeBand()`（两种显示方式的落点：居中是把这一行的中线摆进这一段的正中，整页是把这一页完整摆进这一段）。
- **改错会怎样**：少减一个，页面就被压在胶囊底下 ——「整页」是页顶被顶栏吃掉一条，
  「居中」是这一行停在正中上方整整一个 `reservedTop`。

## 3. 首尾页靠「上下垫空白」摆位，不是靠算式

- `scrollTop` 被夹在 `[0, maxScroll]` 内，所以「把第一页往下挪到居中」「把最后一页往上挪到居中」**只能靠内容外面的 padding 撑出来**，算式再准也够不着边界。
- `paddings()` 是 padding 与落点算式的**唯一来源**：`measure()` 写进 `element.style` 的是它、`scrollToMeasure()` 拿来摆页面的也是它，**别再各写一份**。

## 4. 小节语义

- 一行里相邻两条小节线之间才是 1 个小节 → **一行 n 条线 = n−1 个小节**；标记时谱表最左和最右的竖线也必须标上。
- `barStartMeasure: Map<barId, no>` = 「这条小节线之后的小节号」；行末最后一条线指向下一行第一个小节，**全文最后一条线指向 `count + 1`（已越界，不能再当段落起点 / 跳转记号的起点或终点）**。
- **段落与跳转记号存的都是小节线 id**（`seg.barId` / `jump.startBarId` / `jump.endBarId`），**小节号一律现推**
  （`barStartMeasure` 查出来的那个号，就是用户看到的序号）。
- 同一个小节号可能对应**两条线**（上一行的行末线 + 下一行行首线），所以有三条落线限制
  （用户原话：**「段落禁止落在行末尾线，跳转起点禁止在行首线，跳转终点禁止在行尾线」**）：
  段落不许落在**行末线**上（`isRowEndBar`）；跳转起点不许落在**行首线**上（`isRowStartBar`）；
  跳转终点不许落在**行末线**上（`isRowEndBar`）。判据只在 `domain/timeline.js` 里各写一处。
- **改错会怎样**：小节数、段落与跳转的落点全部偏移一格。

## 5. 段落位置是「小节线 id + 拍号」两个字段

- `seg.barId` = 它挂靠的那条小节线（**不许是行末线**），`seg.beat` = 小节里的第几拍（整数、1 起）。
  **小节号不是数据**：它是 `barStartMeasure.get(seg.barId)` 现推出来的（`segmentMeasure()`）——
  所以删掉 / 新增一条小节线之后**记号留在原来那条线上**，变的只是它显示出来的号。
  没有「把两个值打包进一个数字」的编码，也就没有小数进位、两位小数、文本输入规整这一串东西。一拍时长 = `60 / bpm × 4 / beatUnit`。
- **`beat` 上限是这一段落自己的 `beatsPerBar`**（`fitBeat()`）：改拍号时拍号要跟着夹一次，别让它停在一个这一段落里不存在的拍上。
- **比较位置一律用 `comparePosition()`**（先小节、再拍号）：它比的是**解析出来**的 `measure` / `beat`（`resolveSegments` 补上的那两个），不是原始 meta 里的字段。

## 6. 始终有一条不能删的 `head` 段落

- `head: true`、`barId = null`、`beat = 1`、默认 120 BPM 4/4；它**永远挂在「编号第一小节起头的那条线」上**
  （`segmentBarId()` 对 head 不读自己的 `barId`，直接取 `measures[0].startBarId`）；全谱还没有小节时它没有落点。
  `createMeta` 最后调 `ensureHeadSegment`，没有就直接补一条（**不做旧数据兼容**）。
- **不能删除**（`removeSegment` 提示返回）、位置不可改（`updateSegment` 强制 `beat: 1 / barId: null`）。**默认速度就是它**，不是散落在各处的硬编码兜底。

## 7. 时间轴是逐拍累加出来的，两个方向**故意不对称**

- 按**演奏顺序**（含跳转展开）每拍一项；`byNo` **只保存每一遍的小节起始拍**，因此同一个小节号可能有多条记录。
- **`timeToPos`（播放走到哪）走展开后的顺序**：跳转算数；跳跃的落点在采样表里标了 `jumpTo`
  （界面拿它把目标小节闪一下，**只在播放中闪**）。
- **`posToTime`（跳转到哪一秒）不传 `nearTime` 时只认第一次出现** —— 手动点小节 / 跳段落「视作还没跳过」：
  不管现在播到跳转前还是跳转后，都从那一小节的第一遍接着走，后面的跳转该走还是会走。
  **循环区间 / 暂停回退这类「跟着当前位置走」的换算必须传 `nearTime`**（取离它最近的那一遍）。
- **`meta.audio.startPosition`（只认 1 / 2）决定 `startOffset` 对齐哪一小节**：1 = 第 1 小节（默认）、2 = 第 2 小节（第 1 小节是弱起，落在起点**之前**）。提前量按**弱起小节自己的拍数**逐拍累加，所以弱起小节想只提前一拍，就得给它一个拍号更少的段落（例如 1 拍）；`startPosition` 越界时按 1 处理，别把整首曲子的时长当成弱起小节。**改错会怎样**：对齐错一小节 → 全曲播放位置整体偏移一个小节，跳转 / 节拍器 / 自动翻页跟着一起错。
- **音频 0 秒之前那一段（弱起前导）位置是负数，绝不许夹到 0**：`<audio>` 与 AudioContext 只认 ≥ 0，
  所以负数位置寄存在 `clock.leadPos` 上（`OutputClock.now` 优先读它），`<audio>` 停在 0 秒等位置走到 0 秒再起播
  （前导期间 `engine.on('time')` **必须忽略**，它每帧报的 0 会把负数顶掉）。
  **改错会怎样**：夹到 0 → 点第 1 小节会从小节的半截开始（弱起被吃掉一段），谱面位置 / 节拍器 / 进度全对不上。
- **一切回跳（循环回跳、跳转、暂停回退）都走上层的 `seek()`，不许让时钟 / `<audio>` 自己 seek**：
  它们只认 ≥ 0，负起点会被夹到 0。`handleLoopEnd` 因此**两条路都返回 `true`**（开预备拍的一条数完再 seek，
  没开的一条立刻 `seek` + `playFrom()`）—— 少了这条就是「循环段跳回第一段时从音频位置开始，而不是从头」。
- **打开乐谱后的默认位置 = 时间轴第一拍的 `time`**（`store/player.js` 的 `timelineStart`，`open()` 里 seek 过去）：
  有弱起时它是负数。「打开 → 按播放」必须也能走完整个弱起小节，**绝不能改成固定的 0**。
- **不要把时间轴手动缓存到别处**：派生数据都在 `store/player.js` 的 computed 里，改 meta 后自动重算。
- **改错会怎样**：`posToTime` 也按「当前遍数」取 → 手动跳转会莫名落到别的遍；反过来把 `nearTime` 去掉 →
  第二遍框选第 2 小节会把播放头甩回第一遍，框选区间与播放头对不上。

## 8. 不做向后兼容

项目还在早期、格式会频繁变。除非明确要求，不要为「旧版本写出的数据」写迁移 / 兜底代码；需要兼容时**先问**。

## 9. 存储与包格式

- IndexedDB 库名 `pdf-score`，两个 store：`scores` + `files`。`files` 的键固定为 **`<id>/pdf`、`<id>/audio`、`<id>/peaks`**，删乐谱要一起删；替换 / 删除音频要同步处理 `audio` 与 `peaks`。
- **`.psz` = 单张乐谱的包，`.zip` = 装多张 psz 的容器**。包内容在**根目录**（`score.json` / `score.pdf` / `audio.*` / `peaks.f32` / `cover.*`）。
- 封面反色只看 **`coverCustom`**，**不要用 `!!thumb` 推断**（默认封面也是一张图）。
- **改错会怎样**：键约定错了会留下孤儿数据、导出包读不回来、深色模式下封面反色反错。

## 10. 播放能力只看「有没有东西可走」

- `canPlay = player.hasAudio || timeline.duration > 0`。**节拍器音量绝不允许参与这个判断** —— 它是声源开关，不是播放开关。
- 静音也能走带；预备拍走独立音量（`cueVolume`），节拍器拉到 0 时预备拍照样响。

## 11. UI 硬线

- 颜色一律走 CSS 变量（硬编码只有白名单那几处）；可点元素 ≥ 46px；尺寸只用 `--tap` / `--tap-min`。
- 设置即改即生效，**不设「保存」按钮**；面板关闭只是导航，不代表放弃修改。
- **一件事只有一个实现**：动手前先查 `docs/ui.md` 与 `docs/UI-COMPONENTS.md`，别再造第二个同语义的东西。

## 12. 验证归属

- **自动化测试默认不主动跑**（`test:unit` 也不跑，端到端脚本已删）：**要跑先问用户**。改完只说明「改了哪些文件、期望看到什么」。
- 唯一的例外是**动算法时提醒一句**：碰了 `src/domain/*` 就加一句「建议跑 `npm run test:unit`（纯 node，几秒）」——只提醒，不擅自跑。
- 纯逻辑（`src/domain/*`）该跑 `npm run test:unit`；构建 / 路由 / 依赖 / pdf.js 资源该 `npm run build && npm run preview` 后手工点一遍。
- **UI / 交互改动不要自己跑自动化**：说明「改了哪些文件、期望看到什么」，交用户手工验证。
