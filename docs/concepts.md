# 领域概念与算法 · PDF Score

时间轴怎么算出来、播放时钟怎么走、谱面怎么自动识别。**硬约定（写错会算错数据的那种）见 `invariants.md`**；数据形状见 `data-format.md`；组件内的细节见各文件头部注释。

## 1. 小节是怎么数出来的

结构推导（`domain/timeline.js` 的 `deriveStructure`）走三步：

1. 一行里相邻两条小节线之间就是一个小节，按「页 → 行（自上而下）→ 小节（自左向右）」连续编号；
2. 给每条小节线记下「从它开始的小节号」（`barStartMeasure`）；
3. 行不成行（`bars.length < 2`）就跳过 —— 所以**没画小节线的行一个小节都没有**，这也正是行工具 hover 要用 `hitSystem` 而不是 `hitMeasure` 命中的原因（见 `ScorePage.vue` 头部注释）。

反复结束线的结束小节 = `startAt − 1`；正文最后一条小节线指向 `count + 1`（越界，不能当段落 / 反复的起点）。

**行末那条线**（每行最右边一条）与**下一行行首那条线**指向**同一个小节** —— 两条线在 `barStartMeasure` 里是同一个号。
所以：**每行的最后一条小节线上只允许反复记号结束标记**，段落 / 反复开始 / 房子 1 起点都不许落在这里；
被挡住时要改点**下一行行首那条线**，小节号完全一样、语义不变。**行首那条线没有对称限制。**
判据只有一处：`domain/timeline.js` 的 `isRowEndBar`。

## 2. 时间轴：逐拍累加

1. **结构**：见上（页 → 行 → 小节连续编号）。
2. **调速**：段落是调速点，从它的位置（第 `measure` 小节第 `beat` 拍）起生效的 BPM 与拍号；一拍时长 = `60 / bpm × 4 / beatUnit`。
3. **反复**：按反复标记把小节序列展开成实际演奏顺序（`expandRepeats`）—— 房子 n 只在第 n 遍演奏，其余遍跳过。
4. **采样表**：沿演奏顺序逐拍累加时间，得到「小节位置 ↔ 音频时间」的双向映射（`buildTimeline`）。段落若设了**时间锚点** `time`，会在第一遍经过时把时间强制对齐到该秒数，用来消除累计误差。

因此：点击小节跳转、节拍器、自动翻页、框选循环，**全部来自同一张时间表**（`store/player.js` 的 computed，改 meta 后自动重算，别手动缓存）。

**反复（含房子 1 / 房子 2）** —— 播放**按展开后的顺序走**（该跳就跳），但**手动跳转视作还没反复过**：

| | 走法 | 例（房子起点在第 3 小节） |
| --- | --- | --- |
| **没房子** | 两遍都走整段 | `‖: 1 2 3 4 :‖ 5 6` → `1 2 3 4 \| 1 2 3 4 \| 5 6` |
| **有房子** | 房子那段只有第一遍走；第二遍**碰到房子起点就跳到反复结尾之后** | `‖: 1 2 [3 4] :‖ 5 6` → `1 2 3 4 \| 1 2 5 6` |

- 一对反复**只走两遍**（`passes` 一律按 2 算），跳跃只有两种：**终点跳回起点**、**碰到房子起点跳到反复结尾之后**。
  跳跃的落点在 `expandRepeats` 里标了 `jumpTo`，界面上那一小节的背景会**闪一下**（只在播放中闪）。
- **手动跳转（点小节 / 跳段落）取那一小节的第一次出现** —— 不管现在播到反复前还是反复后，
  都从「还没反复过」的状态接着走，后面的反复该走还是会走（`posToTime` 不传 `nearTime` 就是这个意思）。
  循环区间、暂停回退这类「跟着当前位置走」的换算**要传 `nearTime`**，取离它最近的那一遍。

### 反复标记：三种标记，房子 2 是样式不是标记

谱面上能落下的反复标记**只有三种**：`start`、`end`、`house1`。房子 2 没有自己的数据，它是从结束线往右推出来的显示。

- **配对**（`matchRepeatBlocks`）：按落点顺序扫一遍，遇到 `end` 就配给**它左边最近的那个还没配对的 `start`**。
  所以「先开始后结束」和「先结束后开始」都能配对，而且**支持嵌套**（嵌套区块的演奏顺序由 `expandRepeats` 的 `endAt` + `passDone` 决定）。
  返回的配对里**没配上的标记也在**（`end: null`）—— 落点判定要靠它们看「哪一段还敞着口」；演奏与渲染只认配好对的。
  单独一条 `end`（没有 `start` 可配）**什么也不做**，只画出来、能被点掉 —— **绝不回到第 1 小节**。
- **类型靠落点推**（`decideRepeatTap`）：默认 `start`；这一笔落在某个「还没结束的区块」里时 —— 这一段里已经有 `house1` 就是 `end`，
  还没有就是 `house1`；落在**已经配好对的区块内部**也是如此 —— 这一段已经有 `house1` 就把那一条**搬到这一笔落点**
  （`house1-move`，一对里始终只有一个房子起点），还没有就新增一条。
- **行末那条小节线只接受「反复结束」**：这一笔没配对待定起点时，它只可能是起点 / 房子起点，一律拒绝
  （`decideRepeatTap` 的 `row-end`）；**带着待定起点点上去时它照旧是结束线** —— 一对反复正好「这一行开头 → 这一行末尾」。
  起点 / 房子起点要改点**下一行行首那条线**（同一个小节，见 §1）。
- **删除靠再点一次**：点 `house1` 只删它自己；点 `start` / `end` 删掉整段反复（配对的另一条 + 区块里的 `house1` 一起）。
  **「点 `house1`」有两条等价的路**（用户要的「线和括号都删房子 1 起点标记」）：点那条细竖条（标记本体），
  或者点**房子括号**（谱面上更显眼的那条）—— 括号那条热区在 `ScorePage.vue` 的 `hitHouseBracket`，
  房子 2 的括号删的也是同一个「房子 1 起点」（它自己没有标记）。
- **房子跨度**（`deriveRepeatBlocks`）：
  - 房子 1 = 从 `house1` 那条线到**结束线**（第一遍走它）；
  - 房子 2 = 第二遍**跳过房子 1 之后落地的那一小节** —— **只画这一个小节**（「2.」是起点标记、不是覆盖范围）；
    两者**首尾相接、不重叠**，正是用户要的「房子 1 是这个起点到反复结尾，后面就是房子 2」。
    （那一遍真实走到哪另有 `fullEndMeasure` 记着，渲染不看它。）
  - 演奏顺序还是 `expandRepeats` 那套区块模型算的 —— **房子括号只是把顺序画出来**，不参与算法。
  - **没有 `house1` 起点线就没有房子 2**：房子 2 的起点本来就是「第二遍**跳过房子 1** 之后落下来的那条线」，
    没有房子 1 就无从谈起 —— 那时按顺序推出来的东西落在区块自己身上，画出来只是一条凭空冒出来的「2.」，
    所以整条不推、不画。
  - 第一遍就要跳过整个区块时（例如区块外面还有一层反复）第二遍可能不再经过它，那时不画房子 2。
- **房子括号的形状**（`ScorePage.vue` 的 `houseBrackets`）：房子 1 **两头都收尾**（左右各一条竖钩）；
  房子 2 **只起笔、不收尾**（右边敞着口 —— 它的覆盖范围一直到曲末，画条收尾的竖钩等于说「到此为止」）；
  两个房子的跨度共用一条结束线，所以房子 2 的起笔再往右让出 `HOUSE_GAP_X`（4pt），两条之间留一条缝，
  **房子 1 的跨度一点不动**（它按约定就是「起点线 → 结束线」）。

脚本里造数据仍然可以写 `kind: 'house2'`（老版本的编辑器设过它）：`expandRepeats` 会把「房子 2」解释成
「**结束线所在的那一小节**起到区块末尾」（与面板的自动值一致），所以 `scripts/unit-test.mjs` 里那条用例
（`‖: 1 2 [1.] :‖ [2.]` 展开成 `1 2 3 1 2 4 …`）照旧成立；`deriveRepeatBlocks` 的 `houses` 不认它（渲染不画）。

`samples[]` 每一拍一项（`{no, beat, pos, time, bpm}`），`order[]` 是展开后的实际演奏小节序列；`byNo` 只存每一遍的小节起始拍，所以同一个小节号可能有多条（按 `nearTime` 选最近的一遍）。

## 3. 播放时钟：三条分支，同一套语义

**没有音频文件也能播放**（只响节拍器 / 预备拍）—— 播放能力只看「有没有东西可走」：

- **有音频** → 时钟读 `<audio>.currentTime`；
- **无音频** → 时钟读 Web Audio 的 `ctx.currentTime`（`OutputClock`）；
- **连 AudioContext 都建不起来** → 退回墙上时钟。

三种都走「音频硬件时钟」这套语义，节拍器才能和位置落在同一条时间线上。静音也能走带（进度条 / 播放头 / 自动翻页都在动），音量只影响声音。

**「有没有音频」这条分支只看 `engine.ready`（主元素有没有 `src`），不是 `player.hasAudio`**：
所以**每一次导入音频（第一次往没有音频的乐谱里导入，也算）都必须 `engine.load(url)`** ——
`store/player.js` 的 `importAudio` 少调一次，`player.hasAudio` 已经是真、两只 `<audio>` 却都没有地址：
试听报「试听失败：无音频」，按播放**一声不响、播放头也不走**（`playFrom()` 只调 `engine.play()`，
它在没有 `src` 时直接 `return false`）。`engine.load` 同时管主元素与试听那只。

**弱起前导（位置可以是负数）**：记谱的弱起小节比音频里那段弱起长时（更一般地，`startOffset` 为负时），
音频 0 秒**之前**还有内容 —— 那一段只有乐谱、节拍器和进度，`<audio>` 里没有声音。
这时**不能把位置夹到 0**：夹完就落在小节的半截上，现象是「点第 1 小节却从后半小节开始播放」。
做法是**位置从负数走起**：`store/player.js` 的 `startLead` / `leadTick` 每帧算出
`起播位置 + 已走过的时间 × 倍速`，写进 `player.currentTime` 与 `clock.leadPos`，`<audio>` 钉在 0 秒；
走到 0 秒才 `seek()` 到 0 并 `play()` —— 也就是「**让音频晚一点开始**」。由此：

- 底层的 `<audio>` / AudioContext 时钟**永远只看得到 ≥ 0**，负数只存在于 `clock.leadPos`（`now` 优先读它）；
- 暂停就停在当时那个负数位置上（`stopLead` 只停走时），再按播放从那儿接着走；`close()` / 跳到非负位置会停掉它；
- 前导期间 `<audio>` 自己每帧还在报 0 秒，所以 `engine.on('time')` 在前导期间**一律忽略**，否则会把负数顶掉。
- **循环回跳（`handleLoopEnd`）也必须走上层的 `seek()` + `playFrom()`**：让时钟 / `<audio>` 自己回跳时
  它们只认 ≥ 0，负起点会被夹到 0 —— 现象是「**循环段跳回第一段时从音频位置开始，而不是从头**」。
  所以它**两条路都返回 `true`（= 已接管）**：开预备拍的一条数完再 `seek`，没开的一条立刻 `seek` + `playFrom()`。

**无音频那两条分支的读数公式**（`OutputClock`，改错就是「位置算错」，实测见 `npm run test:unit` 的 `[15]`）：

- **有 AudioContext 时**（节拍器建起来了）：`读数 = origin + (ctx.currentTime − _ac) × rate`。
  三处都不能动：**是加 `origin`**（写成减的话 `seek(6)` 之后读数一直贴着 0、要等 12 秒才追到 6 ——
  无音频时「跳小节 / 暂停一下」位置就归零）；**倍速乘在这里**（和墙上分支、
  和 `<audio>` 的 `playbackRate` 一个意思）；**暂停时读 `origin`**（AudioContext 是节拍器共用的，
  暂停期间它照样在走，现算会把暂停时间算成进度）。
- `_ac` 要在 **`seek` / `play` / `pause` / `resync` 四处重新钉住**；`resync()`（`metronome.reset()` 会调）
  必须**先 `origin = now` 再钉 `_ac`**，否则中途拉一下节拍器音量，位置会当场弹回上一次 seek 的落点。
- **连 AudioContext 都建不起来**时的那条墙上时钟分支照旧（`_pn` 为 0 = 还没起播过）。

`domain/audio-engine.js` 里 `AudioEngine` 负责 `<audio>` 的播放 / 跳转 / 倍速 / 循环，`MediaClock` 负责时间外推。**`OutputClock` 的墙上时钟兜底分支有三个坑**（都在文件注释里标了），改它时都要留住：`now` 里必须是 `this.origin`（写成 `_origin` 会得到 NaN 并污染整个起点）；`play()` 要在读 `before` **之前**把 `_pn` 钉住；`pause()` 要先把已走过的时间折进 `origin` 再清 `_pn`。

### 3.1 音频起点那一屏的「试听」是第二只 `<audio>`，不进播放流程

- **试听不和谱面走同一个播放流程**（要求原文：「试听不和谱面走同一个播放流程！试听只是单独放那个音频文件」）：
  `AudioEngine` 除主元素 `el` 外还有一只**试听专用**的 `previewEl`，试听只动它。
  所以下面这些**一个都不碰**：`player.currentTime`（谱面播放位置）、`player.playing`（播放键、
  顶栏隐藏那套「播放中」界面）、`OutputClock`、节拍器、预备拍、循环、自动翻页。
- 试听的位置单独报：`previewEl` 每帧发 `previewTime` → `store/player.js` 写进 `player.previewTime`
  （**音频文件自己的时间轴**，秒），频谱里那颗播放头读它。**别把它和 `player.currentTime` 混用** ——
  那两个数在有 `startOffset` 时差着一整个偏移量。
- 试听那只元素**不报** `play` / `pause` / `time`：那三个事件是「谱面在不在走带」的开关与播放头，
  借它试听一次，谱面位置就被挪走了，也说不清「这算不算在播放」。
- 起播失败（文件放不出来 / 浏览器拒绝）时 `previewPlay()` 返回 false、`startPreview` 退回未试听，
  并且由**引擎发 `previewError`**（带错误对象；连地址都没有那种兜底发 `null`）→ `store/player.js` 弹一条
  **可复制的报错**（`errorToast`，危险色，正文「试听失败：错误原文」）。**试听失败不许发 `error`**：
  那个事件是「谱面播放出错」（正文「音频播放出错：错误原文」），借它会变成同一次失败报两条；
  所以 `AudioOffsetPicker` 自己**不弹**任何提示：`startPreview` 的返回值只说明「放起来了没有」，
  **别拿它再补一条提示**（那就是两条）。
- **不自动停**（要求原文：「试听不要自动停止，用户不点击停止就播放到音频结束」）：不设时限、也不跟频谱那 5 秒的
  视野走 —— 点到就一直放到音频结束。**停下来的只有两种情况**（要求原文：「就只有弹窗关闭、用户点停止这两种情况
  会停止试听」）：**关掉那一屏**（「设置音频起点」这个状态被收起：点「返回音频设置」、关音频面板、被别的面板顶掉）、
  以及**点「停止试听」**。放到头也收尾（`previewEl` 的 `ended` 报一次 `previewEnded`，上层把「试听中」收掉 ——
  那是没得放了，不是「停」；不报的话按钮会挂在一个没有声音的「停止试听」上）。
  实现只有一处：`store/player.js` 的 `startPreview` / `stopPreview`。
- **进这一屏先把谱面停下来**（要求原文：「当用户打开了「设置音频起点」的sheet时要把播放中的乐谱给暂停」）：
  `AudioOffsetPicker` 挂载时调 `store/player.js` 的 `pausePlayback()`（暂停的唯一入口，与进编辑模式同一条），
  这样听到的就只有那个音频文件。**它只停谱面、不停试听**（两件事互不影响）。

## 4. 节拍器与预备拍

- **前瞻调度**：`Metronome._tick` 每 25ms 向 `beatsBetween(t0, t1)` 取未来 `0.25 × rate` 秒内的拍点，用 Web Audio 提前排程。**seek / 循环回跳后必须 `metronome.reset()`**，否则会补发过期拍子。
  前瞻与「这一拍等多久」都是 `0.25 × rate` / `÷ rate`（时间轴秒 ↔ 真实秒的换算，换算成真实时间恒为 0.25 秒），
  连**「位置往回跳了」那道兜底判据**（`now < lastScheduled − 前瞻`）也要用同一支算式：
  **判据里的 0.25 写死的话，倍速 > 1 时它每 25ms 都命中** —— `lastScheduled` 正常就落在 `now + 0.25 × 倍速` 上，
  于是同一批拍子被反复排程，**节拍器变成每 tick 一下（约 40 下/秒、与段落 BPM 无关），而且暂停也停不下来**
  （`now` 冻住，判据照样命中，已排进 Web Audio 的点击声一直往外冒）。
  `clock.rate` 报的是**真实走带速度**（有音频时 = `<audio>` 的 `playbackRate`，无音频时 = 倍速），别让时钟与引擎各说各的。
- **音量即开关**：`setMetronomeVolume(0)` 只影响声音，**不会停掉播放**。
- **预备拍与节拍器音量解耦**：`countIn()` 只看 `cueVolume`，走独立的 `cueGain` 节点 —— 节拍器拉到 0 时预备拍照样响（这正是「只响预备拍」要的）。
- **预备拍进行中要有一个进 store 的镜像 `player.cueing`**：`metronome.countInActive` 是读定时器的 getter，
  **不是响应式数据**，而谱面要按「在不在打预备拍」决定显不显示跳跃闪烁（见 `docs/ui.md` §18.54）。
  所以 `store/player.js` 里预备拍一律走 `startCountIn(landing, onDone)`：排程时置真（**同时把
  `player.playing` 也置真 —— 预备拍算播放中，播放键要显示成「暂停」供用户暂停**，见 `docs/ui.md` §18.54 第 139 条）、
  倒数结束的回调里把 `cueing` 置假，`pausePlayback()` / `close()` 一起归位；`landing`（要点亮的那一拍）给了就顺手把
  落点点亮（跳转预备拍 = 目标小节、循环段预备拍 = 框选起点、**播放预备拍 = 播放头现在那一小节**），
  **别绕开它直接调 `metronome.countIn`**。
  打预备拍那次「停」是刻意压住的（`suppressRewind`），`engine.on('pause')` 见到它就**不退出播放态**。
- **预备拍只在「这次跳转要接着走带」时才打**（判据在 `seekToPosition`）：**走带 = 「跳转自动播放」开着
  或 此刻本来就在走带中**（`player.playing` —— 预备拍期间它也为真）；**预备拍 = 「跳转预备拍」开着 且
  上面那条成立**。所以「播放中点跳转」即使没开自动播放也要数一小节再接着走，而「暂停着 + 没开自动播放」则
  **既不自动播、也不打预备拍**。`startPlayback` 只管「打不打预备拍」。
- **两种跳跃闪烁各占一个槽位**（`player.jumpFlash` / `player.jumpAfter`，谱面画两层）：
  `jumpFlash` = 每拍一下、重复一整个小节（自动跳的预告 + **循环区间回跳**的预告 + **预备拍倒数**期间
  点住落点）；`jumpAfter` = 落点上闪一下就完（见下一条的时机）。**播放预备拍**（没有跳跃）也会闪
  `jumpFlash` —— 它点亮的是播放头现在那一小节（马上要从那儿接着走）。
- **能预见要跳就闪「跳转前」，而且只闪一个小节的时长**：自动跳看「下一小节的起点就是落点」；
  **循环区间回跳看「走进区间最后一小节」**（`loopingToLastMeasure`）；预备拍倒数期间点的是落点本身。
  · 预闪的拍数 / 拍长按**当前正在播的那一小节**算（`beforeJumpTiming` → `measureDuration / 每小节拍数`，
    再 **÷ `player.rate`** 换成真实毫秒，跟预备拍一样吃倍速；下限 160ms 夹在除完之后），
    按落点算会闪多、跨到下一小节去；
  · **这次回跳要打循环段预备拍时预闪一律不点**（只在预备拍里闪）—— 否则「最后一小节预闪 + 倒数那一小节」
    就是**闪两小节**；
  · **重叠时点循环起点、不点反复记号**（循环优先，闪烁跟着实际发生的那一跳走，见 `docs/ui.md` §18.57）。
  「本小节末尾要回跳」（`loopingToLastMeasure`）与「谁来闪」（`armLoopLandingIfLastMeasure`）是**两件事**：
  打了预备拍时前者照样成立（反复那一跳的预报必须被挡掉），只是闪的人换成预备拍。
  判断「循环起点是哪一遍」要取**引擎手里那份区间**（`clock.loop`），不能用 `loopRegion` computed 重算
  （它的 `nearTime` 跟着播放头漂，反复里会选到下一遍去）。
- **带预备拍的地方都是「先数完一小节，再跳」**（手动跳转 / 框选起播 / 循环回跳都一样）：
  倒数这一小节里播放头钉在原地不动、只有落点那串「跳转前」在闪；数完才 `seek` → 闪「跳转后」→ 起播。
  **「跳转后闪烁」的时机永远是「播放头跳转那一刻」**：打了预备拍就是倒数演完那一下，
  没打预备拍（暂停着点跳转 / 预备拍关着）就是 `seek` 之后当刻，自动跳是落地那一拍。
- **按暂停 = 当刻停**：倒数一次把一整小节排进 Web Audio，撤不掉，所以 `Metronome` 里有一道
  **倒数闸门**（`cueGain → cueGate → master`）——`cancelCountIn()` 把它关到 0，剩下的几下当刻静音。
- **预备拍打的拍子与落点闪烁的节奏是同一份**（`countInTiming(sample)` → `{beats, beatMs}`，
  从落点那一拍的时间轴记录取，`beatMs` 下限 160ms）：预备拍打 `beats` 下、间隔 `beatMs`，
  落点闪 `beats` 下、每下 `beatMs`。**预备拍也吃倍速**：`beatMs` 是**真实**毫秒，
  由 `beatDuration()`（时间轴秒）× 1000 **÷ `player.rate`** 得来 ——
  倍速是走带速度，一拍的真实长度就是它除完那么多；下限夹在除完之后。
  两处各取一份速度（一处按段落、一处按小节）迟早就一个快一个慢
  —— 表现是「预备拍和预备拍闪烁的逻辑不一致」。**打预备拍先把声源停住**（`stopSources()`）：
  倒数这一小节里播放头必须**钉在原地**不动（带预备拍的地方都是数完才跳，见上），
  否则音乐压在倒数底下继续放、位置走开，落点那串闪烁也会被收掉；
  **倒数演完顺手撤掉落点那串「跳转前」**（它演满一小节了，留着会让「当前小节」的底一直让位）；
  **倒数期间 `engine.on('time')` 报的位置一律忽略**（真机 `<audio>` 的异步 seek 会先报旧位置，
  位置一抖就会把倒数那串闪烁清掉，见 §18.54 第 142 条）。

## 5. 音频起点与波形

- 音频起点 `meta.audio.startOffset` 表示「第 `startPosition` 小节对应的音频时间」，**可以为负**（第一小节在音频开始前就开始数）。
- `startPosition` 只有 1 / 2 两个取值，由音频起点选择器里的**「添加弱起小节」开关**写：**关 = 1**（第 1 小节对齐起点）、
  **开 = 2**（第 2 小节对齐起点，第 1 小节是弱起、落在起点之前）。时间轴那一头在 `buildTimeline` 里按
  **弱起小节自己的拍数**把初始时间往前推（`startMeasure` / `pickupLeadIn`）—— 所以弱起小节要标成几拍，
  就给它加一个拍号更少的段落（例如 1 拍），提前量跟着一起变；`order` 里找不到 `startPosition` 时不提前，
  免得把整首曲子的时长当成弱起小节。覆盖这一条的是 `npm run test:unit` 的 `[5] 音频起点偏移与时间锚点`。
- 弱起那段在音频里**没有声音**时（记谱的弱起小节比音频里那段长，第 1 小节整段落在 `startOffset` 之前）：
  位置从那一段走起、`<audio>` 等到 0 秒才出声 —— 见上面 §3 的「弱起前导」。**别改成把位置夹到 0**。
- **打开乐谱后的默认位置 = 谱面真正的开头**（`store/player.js` 的 `timelineStart` = 时间轴第一拍的
  `time`，`open()` 里 seek 过去）：有弱起时它就是负数 —— 于是「打开 → 按播放」也会先把整个弱起小节走完，
  而不是一上来就落在小节半截上。
- 峰值数组的形状与归一化见 `data-format.md`；绘制与配色由 `AudioOffsetPicker` / 波形相关组件负责（`store/ui.js` 的 `readPalette()` 在系统主题切换时要重绘）。

## 6. 谱面自动识别（`domain/omr.js`）

输入是「已经栅格化的页面墨点图」，输出可直接写进 `meta.pages[].systems` 的标记（**PDF 原始点坐标 pt**）。**只用位图、不看 PDF 矢量路径** —— 大量乐谱 PDF（扫描件、图片导出、Pillow 拼图）整页就是一张位图，`getOperatorList()` 里一条路径都没有，矢量方案在它们身上完全失效。

判据是五个，每一步都刻意用「相对这一页（或这一条谱表）自己」的量，不写死绝对像素 / 占比（同一批谱子里，谱线墨迹占比 0.64~0.9、行距 11~25px、行内间距 47~95px 都有）：

1. **谱线行 = 细而突出的行**：门槛是本页最强行的 `linePeakRatio` 倍，再按「局部最强行的比例」筛突出度 —— 符杠、歌词、密集符头能堆出一片高墨迹区，堆不出一根又细又尖的行；
2. **谱表 = 等间距的一组谱线**：轮着试几个间距容差取覆盖最好的那一套，再按等间距外推把**没认出来的那条线**补回来（少一条线，谱表包围盒就短一截，小节线的判据会跟着一起错）。外推补线**两端各只推一格**，而且那一行要**像这一条谱表自己的谱线**（墨迹 ≥ 本谱表已有谱线墨迹中位数的 `lineFillStaff` 倍）：谱表外沿那一行常常正是歌词 / 排练号 / 加线，只按全页相对力度判会把它们认成第 6 条谱线，包围盒往外长一截，同一行的小节线整批落选；
3. **行 = 由「有东西连起来」的谱表合成**：主判据是两谱表之间的空隙里**有一根竖线贯穿过去**（行首括号 / 系统小节线），没有括号时退回一个卡得很紧的间距判据。间距的倍数、全页中位数、分布拐点三种写法都试过，每一种都能在另一份谱子上并错或拆错；
4. **小节线 = 每条谱表的谱表高度里都被一段墨填满**：逐条谱表单独判、取最弱的那条，符干在音符上下各留一段自然落选；小核纵向闭运算补扫描件的断线；门槛取**这一行第 4 强的候选竖线**（`barRefRank`）乘 `barRatio`，**不拿最强那一列当基准** —— 反复记号 / 终止线那种又粗又长的双竖线比普通小节线高出三成，拿它当基准会让同一行其余小节线全部落选、整行只剩一两条线；最后把贴得太近的（< `mergeRatio` × 行距）合并成一条；
5. **行两端缺的那条补回来**（`closeRowEnds`）：行首那条线常和行号 / 谱号 / 调号 / 拍号挤在一起（数字谱里常常干脆不画，行首第一眼看到的是拍号），行尾那条可能被反复记号 / 终止线画得又粗又花，判据一保守两头就丢 —— 丢一条就少一个小节（n 条线 = n−1 个小节）。做法是拿**这一行谱线自己的墨迹端点**（不是 `system.x0 / x1` —— 那是含行首大括号、行号的并集，能撑到谱表外 96px）往里量：首（末）线已经贴着边就不动；离得远就在「谱表边界 ~ 已有首（末）线」之间找那条漏掉的竖线（那一列的连续墨段要够一条谱表高），**一列都没有就补在谱表边界上**。补出来的线**离已有首（末）线不足 `mergeRatio` × 行距时整条不补**（反复记号的双竖线那两笔相差十几像素，补上去就是两条小节线贴在一起），**只给「已经认出一条真线」的行补**（一条都没有的行整行不留，见下）。

**导入 PDF 时会自动跑一遍**，把识别出的行与小节线直接写进这份乐谱的 `meta.pages[].systems`（**没有开关、无条件跑**，所以新导入的谱一打开就是标好的；认错了手工删即可）。接线在 `store/library.js` 的 `createScore`：`syncPages` 之后调 `autoMarkPdf`，识别入口是 `omr.js` 的 `detectPdfPages`。

- **只在没标记时跑**：`systems` 已经有内容（JSON / psz 里带的标记）就整份跳过 —— 自动识别不会盖掉用户的成果。
- **行的去留只看「有没有认出一条真小节线」**：`minBarsPerSystem` 在行端补线**之后**才筛，所以只认出一条线的行补完是 3 条线、留得住 —— 收尾那种只有一两个小节的短行不会再被整行丢掉；一条真线都没有的行不留（那要么根本不是一行，要么整条谱表没认出来）。
- **失败不连累导入**：识别认不出来就当没有 `systems`，PDF 照旧存进去、照旧能手动标。
- 栅格化固定 **200 DPI**（`OMR_DPI`）：谱线间距在 150 DPI 下只剩几个像素，细谱线一断整条谱表就丢；300 DPI 只是更慢更吃内存，结果与 200 几乎一致。**换了它，`staffSpacePx` 那一串判据要跟着重调。**
- 一次只留一页的位图与积分图（200 DPI 的 A4 积分图约 53MB），**渲染一页 → 识别一页 → 立刻释放**，不整本驻留。

**新建一行时也会跑一遍**（只跑这一页）：行工具松手落下一行之后，`store/player.js` 的 `addSystem` 调 `detectPdfPage(pdfBlob, 页号)`，把识别结果里 y 范围与这一行相交的那几条的小节线填给这一行（`detectRowBars`，按页缓存在 `omrPageCache` 里）。

- **整页跑，不是把那一行裁出来跑**：行那一步的判据全是相对整页的（门槛是本页最强行的 `linePeakRatio` 倍、谱表要够页宽的 0.3 倍、补线的力度取自全页 99.9 分位的墨迹占比），裁一小块等于把这些分母全换掉，认出来的东西与导入时那一套对不上。
- **按页缓存**：识别只看 PDF 像素、与 `meta` 无关，同一页认一次就够，连着新建几条行不必把整页重跑几遍（缓存里存的是**那一次识别的 promise**，前一条还没认完就又划一条时两次等的是同一件事）；打开另一份乐谱时清掉（坐标是上一份 PDF 的）。
- **认不出来就什么都不加**，失败只 `console.warn`：新建这一行不依赖识别，手工补线照旧。识别落笔前会按 id 重查一次那一条行（这段时间里它可能已经被删掉 / 被撤销换掉），行上已经有小节线时也不写。

本模块（`omr.js`）自己不碰 DOM、不引 pdf.js / i18n，`scripts/unit-test.mjs` 可以直接跑；栅格化那一步由本文件末尾那两个入口现成包好（把 PDF 页渲染到 canvas 取 `getImageData`）——`detectPdfPages` 整本、`detectPdfPage` 单页，两者共用同一段「一页」的实现；`pdf.js` 在那里是**动态 import** —— 写成顶层静态 import 的话纯 node 一加载本模块就炸。
