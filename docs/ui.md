# UI 规范 · PDF Score

> 本文是界面规范的**唯一一份**：设计令牌、尺寸档位、颜色、交互状态、全局布局约定，以及「怎么改才对」。
> **组件有哪些、属于哪一层**见 [`UI-COMPONENTS.md`](./UI-COMPONENTS.md)。
> **每个控件自己的长相与行为写在对应组件 / 模块的头部注释里**，本文不重复。
> 会算错数据的那几条硬约定见 [`invariants.md`](./invariants.md)。

## 1. 已定稿的规范（5 条）

| # | 条目 | 决定 |
| --- | --- | --- |
| 1 | 触控尺寸下限 | 所有可点元素**一律 ≥ 46px**，没有例外 |

| 5 | 死代码 | **删除**，不保留「以后可能用」 |

## 2. 设计令牌

完整取值表在 [`UI-COMPONENTS.md` §L0](./UI-COMPONENTS.md)。这里只记分组原则：

| 分组 | 令牌 | 选择原则 |
| --- | --- | --- |
| 主题色 | `--accent` `--accent-weak` `--accent-line` `--accent-strong` `--accent-mid` `--accent-deep` `--on-accent` | 唯一的强调色；标记、波形、进度、选中态都用它。**谱面标记本体（含悬停）就是实色 `--accent`**，标记列表点名时的闪烁高峰用 `--accent-strong`（§6 / §18.42）—— **没有「高亮专用」令牌**。`--accent-strong` 也是主题色填充控件的**悬停**色，`--accent-mid` 只给主题色浅底的**按下**用，`--accent-deep` 只给主题色**文字**的按下用（唯一使用者：撤销条的 `.undo-btn`，见 §18.31 第 104 条） |
| 危险色 | `--danger` `--danger-weak` `--danger-mid` `--danger-line` | **只用于不可恢复的删除**；不得当装饰色，不得用于普通强调。`--danger-mid` 是危险按钮的按下底 |
| 表面 | `--surface-page` `--surface-card` `--surface-float` `--surface-control` `--surface-sunken` `--surface-hover` `--surface-active` | 按**角色**挑，不按明暗挑：「这是什么面」决定用哪个，不要因为「想再亮一点」而换档。`--surface-hover` 是中性控件悬停时的底，`--surface-active` 是**按下**时的底（比悬停再重一档）；`--surface-sunken` 只留给下凹的轨道（滑杆、进度、开关） |
| 描边 | `--stroke-strong` `--stroke-soft` | 强描边用于输入框与浮层外框，弱描边用于分隔线 |
| 文字 | `--text-strong` `--text-soft` `--text-muted` | 主 / 次 / 弱三级，不要用透明度模拟层级 |
| 专用面 | `--page-bg` `--page-paper` `--wave-bg` `--scrim` `--pdf-invert` | 谱面工作区、纸张、频谱、遮罩、反色滤镜 |
| 标记灰 | `--mark-muted` `--mark-muted-line` `--mark-muted-fill` | 谱面灰：编辑模式里给「当前没在编辑的那几类标记」用，**非编辑模式只有一处在用** —— 框选（循环区间）的浅底（§6 / §18.32）。**独立一组，不与界面灰共用**（要压在 PDF 纸上，明度要求不同）。后两档是 `color-mix` 减淡出来的**半透明**色（线 ≈ 55% 不透明度、底 ≈ 16%）：**标记本体走实色 `--accent`，灰要也是不透明实色，两边就分不出「现在在改哪一类」了** |

**新增颜色必须先加变量**，除 §7 白名单外不允许出现颜色字面量。

## 3. 尺寸：两档 + 圆角

### 3.1 可点尺寸两档

| 档位 | 令牌 | 值 | 归属 |
| --- | --- | --- | --- |
| 基准 | `--tap` | 46px | `.btn`、`.icon-btn`、`.cap-btn`（胶囊内）、`.text-input`、`NumberPad` 默认 |
| 硬下限 | `--tap-min` | **46px**（与 `--tap` 同值） | `.btn.sm`、`.tag-chip`、`.lib-filter`、`.clear-btn`、`.slider`、`NumberPad.sm`、`.unit-btn`（拍号分母，见 §18.20） |

**胶囊不在可点尺寸这两档里**：`.capsule` 是容器，跟着里面的圆钮走（高度 = 圆钮 46 + 上下 `--cap-pad` + 1px 描边 ≈ 58，已提成 `--cap-h`，见 §18.16 / §18.17）；底栏、总览条、左上那颗走的都是「胶囊 + `.cap-btn`」。
**没有第三档**：只有 `--tap` / `--tap-min`，`--float` 不存在（§18.26）。

规则：**新组件不许再写裸 px 尺寸**，先看能不能归到这两档；归不进去就在本文补一档并说明场景。
两档数值相同（都是 46），**名字标的是用途** —— 要整体调大调小时，改哪一档只影响它管的那批控件。

非交互元素的尺寸（`.onum` 24、行内多选圈 24、`.switch` 48×28、滑杆头 30）不在此约束内，
但**它们的可点父级必须 ≥46px**（`.set-row`、卡片、滑轨容器都是整块可点）。

### 3.2 圆角

| 值 | 用途 |
| --- | --- |
| `999px` | 药丸：胶囊、chip、标签、**toast 与撤销条（`.notice`，含里面那颗撤销按钮）**、搜索框 |
| `--radius-lg` 22 | 底部抽屉上圆角（**横屏只圆右上角**，见 §13「抽屉 = 面板」与 §18.35） |
| `--radius` 14 | 悬浮面板、九宫格键盘、库卡片缩略图 |
| `--radius-sm` 10 | 按钮、输入框、选项行、面板内区块 |
| `50%` | 一切圆形按钮与圆点 |
| 8 / 6 / 5 / 2（裸值） | ⚠️ 未 token 化：分段项 8、页面与顺序数字 6、紧凑缩略图 5、拖拽把手 2 |

**谱面上的圆角只有 `ACTIVE_RADIUS` 这一档**（`ScorePage.vue` 里的常量，**3pt**，随谱面缩放；
不是上面界面那几档 `--radius-*`）：当前小节与框选（循环区间）共用它，谱面上其余标记一律直角。

## 5. 交互状态词表

| 状态 | 表达方式 | 用到的令牌 |
| --- | --- | --- |
| 选中（选项 / 工具 / 分段） | 底 `--accent-weak` + 前景 `--accent` | accent 族 |
| 选中（**标签**） | **不填底色**：`--accent` 描边 + `--accent` 文字（一排标签默认全选中，填色会糊成一堵色块） | accent 族 |
| 选中（库卡片） | 缩略图描边 `--accent` + `0 0 0 2px` 外光晕 | accent |
| 主操作 | 底 `--accent` + 前景 `--on-accent` | accent |
| **危险操作（删除）** | 透明底 + `--danger` 文字与 `--danger-line` 描边；悬停 `--danger-weak`、按下 `--danger-mid` 底 | danger 族 |
| 按下 | **底色必须比悬停更重**：中性控件换 `--surface-active`（不能和悬停共用同一个值），主题色浅底换 `--accent-mid`，危险按钮换 `--danger-mid`；再叠 `transform: scale(0.93~0.98)`。**唯一的例外**是撤销条里那颗 `.undo-btn`（它三个状态都没有底色）：按下改成**字色加深** `--accent-deep`，重量的对比由「深色文字 + scale」给出（见 §18.31 第 104 条④） | 中性 / accent / danger 族 |
| 禁用 | 降透明度（现存三套值：`.3` 九宫格键、`.4` 按钮、`.45` 输入框） | ⚠️ 未统一 |
| 悬停 | **通用的桌面端交互态：所有可点元素都要有**。一律包在 `@media (hover: hover)` 里 —— **手机（触屏）不匹配，所以点完不会残留悬停态**；只改颜色 / 描边 / 阴影（中性面铺 `--surface-hover`、主题色填充控件用 `--accent-strong`、已选中（`.on`）的用 `filter: brightness(1.12)`、毛玻璃圆钮用 `--accent-line` 描边 + `--accent-weak` 光晕），**不改尺寸与布局**，且要一眼看得出来（「差一档灰」不算提示）。写在对应 `:active` **前面**（否则按下时会被 hover 盖住）；谱面则是 JS 命中（只认鼠标，高亮悬停小节） | `--surface-hover`、`--accent-strong`、`--accent-weak`、`--accent-line` |
| 聚焦 | 仅描边变 `--accent`（`.text-input:focus`、`NumberPad:focus-within`） | accent |
| 当前播放位置 | 当前小节**四角小圆角**（`ACTIVE_RADIUS` **3pt**）+ 一条竖直进度线标出这一小节里走到哪一拍；**两种模式都没有描边**。**它不属于「播放中」那一组状态**：暂停 / 停止 / 预备拍只要有位置就画，只有编辑模式不画（见 §18.40 第 128 条） | accent |
| 框选（循环区间） | **谱面灰浅底 `--mark-muted-fill`、不描边**；**同一行里连续的小节合并成一块**，块的四角同用 `ACTIVE_RADIUS` **3pt** 小圆角，跨行时行首 / 行尾保持直角（见 §18.32 第 103 条） | 谱面灰 |

过渡时长散落（`0.08 / 0.1 / 0.12 / 0.15 / 0.16 / 0.18 / 0.22s`），未 token 化。

## 6. 标记层配色

编辑模式下的行、小节线、段落、反复、房子**一律走主题色**，靠**形状**区分
（**全站不做虚实线区分** —— 虚实线混用看着像两套制图规范），不各自配色：

- **标记常态 = 实色 `--accent`**（**不 hover 的时候就得有 accent 那么重**）；
  **非当前工具的标记**降级成半透明的谱面灰 `--mark-muted-line`。
  压字的底（小节号圆饼 / 段落名牌）既然是实色，上面的字就用 `--on-accent`（灰态用 `--surface-page`）。
- **悬停到的那一条**：颜色**不变**，差别是**加粗主线（3pt）与放大圆点（r 3.2）**，行底换成 `--accent-mid`。
- **在「标记列表」里点过、正在闪的那一条**：高峰帧用 `--accent-strong`（比常态再重一档），
  低峰与末帧回到常态的 `--accent` —— **末帧必须等于常态色**，否则闪完会留下一个常亮的高亮。
- **行底是唯一的例外**：它是一层铺满整行的底，不跟着标记本体那档实色走 ——
  常态 `--accent-weak` → 悬停 `--accent-mid`，列表点名时按 `@keyframes sys-flash-fill`
  在 `--accent` 与 `--accent-weak` 之间闪两下。
- **`.bar-line.ghost`（小节线左边那条淡辅助线）仍用 `--accent-line` + `opacity: .6`**：
  它是「这是一条小节线」的**形状提示**、不是标记本体，故意比主线轻一档。
- **「当前小节」不在这一组里**：它只有一层浅底（`--accent-weak`），是**状态**不是标记。

**唯一的例外是「框选」（循环区间）** —— 它表达的是
「这一段在循环」这个**播放状态**、不是一条编辑标记，所以走谱面灰 `--mark-muted-fill`、
**不描边**（见下表最后一行与 §18.32）：

| 标记 | 区分手段 |
| --- | --- |
| 行（划行） | 主题色浅底 + 上下两条边线（**不画左右竖边**） |
| 小节线 | 实线 + 左侧淡虚影 + 上端点圆 |
| 段落 | **一根长得像小节线的竖线**（落在 `position` 的**拍**上，上端穿过小节号圆饼一直伸到名牌底边）+ 挂在**圆饼上方**的一块**横向名牌**（左边缘贴住线、向右展开；牌宽随名字长短收放） |
| 行顶往上的竖向层序 | **固定的三层栈**（从下到上）：**小节号圆饼 → 2pt 缝 → 段落名牌 → 2pt 缝 → 房子括号**。各层各占各的，互不避让；数值全在 `ScorePage.vue` 的 `DISC_*` / `SEG_*` / `HOUSE_*` 常量里，改一层上面跟着挪（见 §18.40） |
| 反复开始 / 结束 | 实线 + 一条细线 + 两个圆点（位置区分开始/结束） |
| 房子 1 的起点 | 一条细竖条（**和「反复」同一类标记**，落点自动定成它） |
| 房子 1 / 2 的括号 | **段落名牌上方**的括号线 + 文字标签（**没有对应的标记**：括号是从「房子 1 起点 + 反复结束线」推出来的样式） |
| 当前小节 | **只有主题色浅底 + 四角很小的圆角**（`ACTIVE_RADIUS` **3pt**），**两种模式都没有描边**（它是「状态」不是「标记」）；进度由一条竖直进度线表达。**只看「有没有位置」，不看「在不在播」**（暂停 / 停止 / 预备拍都画，编辑模式不画，见 §18.40 第 128 条） |
| 框选（循环区间） | **谱面灰浅底 `--mark-muted-fill`、不描边**；**同一行里连续的小节合并成一块**（段内没有背靠背的凹口），块的四角同用 `ACTIVE_RADIUS` **3pt**，**跨行时行首 / 行尾保持直角**；它是谱面上唯一用 `--mark-muted-*` 的**非编辑模式**元素 |

> **没有颜色语义**：`segment.color`、反复三色（`#fb923c`/`#4ade80`/`#a78bfa`）与房子色都不存在；
> `GotoDialog` 里的段落圆点用 `var(--accent)`。

## 7. 允许硬编码颜色的白名单

这些值**必须与主题无关**，换成变量反而会错，因此例外允许：

| 位置 | 值 | 为什么必须硬编码 |
| --- | --- | --- |
| `domain/pdf.js` | `#ffffff` | PDF 纸面永远按白渲染，深浅色统一交给 `--pdf-invert` |
| `ScorePage.vue` 骨架屏 | `#fff` / `#f4f5f7` | 它挂在 `--pdf-invert` 上，要模拟「白纸被反色」，用主题变量会被反两次 |
| `store/library.js` `imageToCover()` | `#ffffff` | 透明 PNG 转 JPEG 必须铺白底，不能跟着主题走 |
| `SwitchRow.vue` 开关滑块 | `#fff` | 深浅两色的轨道（`--surface-sunken` 与 `--accent`）上都要成立 |
| `store/ui.js` `readPalette()` | `#0b0d10` `#4c9dff` `#333` `#888` | canvas 读取失败时的兜底 |
| `index.html` / `public/favicon.svg` | `theme-color` 与图标配色 | 浏览器外壳，早于 CSS 加载 |

除以上各处，任何新增的十六进制 / `rgba()` 字面量都应先提成变量。

## 8. 设置即改即生效，一律不设「保存」按钮

- 偏好类（工具栏文字 / 显示方式 / 滚动动画 / 侧栏宽度 / 总览宽度 / 预备拍与跳转）由 `store/settings.js` 的 deep watch 立刻落 localStorage。
- 乐谱数据类（标题、标签、音频起点、段落 / 反复 / 标记）直接写库或标记 `markDirty()` 走防抖自动保存。
- 需要打字的字段（乐谱标题、段落名）**在失焦或回车时提交**，既不为每个字符写库，也不加保存按钮。
- 因此面板的关闭（× / 遮罩 / Esc）**只是导航，不代表放弃修改**。只有**不可恢复的确认**（删除确认、删除标记）才保留按钮。

## 9. 触屏优先：尺寸只用两档

- 所有可点元素 ≥ 46px；尺寸只用两个变量 —— `--tap`（46，基准：按钮、图标钮、胶囊内按钮、输入框）、`--tap-min`（**46**，硬下限：小按钮、chip、预设键、分段项）。
- **两档数值相同（都是 46）**，名字标的是用途（改哪一档只影响它管的那批控件）；**不要写新的裸 px 尺寸**。**没有第三档**（`--float` 不存在）。
- **不提供左右翻页键**，翻页靠垂直滚动 + 自动翻页。
- **不提供右键菜单 —— 右键 / 长按都不算交互入口（全项目）**：`contextmenu` 不能挂上任何功能，
  也不能出现在任何「怎么用它」的说明里。右键在触屏上根本不存在，长按又被 `-webkit-touch-callout`
  吞掉（§11）—— 两个手势加起来只服务桌面端的一部分人，等于每个动作都有一条只有鼠标用户才走得通的路。
  - 「针对某个对象的一组动作」的**唯一入口是可见的按钮**：卡片是右侧那个 `.icon-btn.flat` 的「⋯」，
    点它弹 `ContextMenu`（见 §14）。菜单的 `anchor` 就是那个按钮，`x` / `y` 只用来让浮层贴住触发点，
    **不要**把 `contextmenu` 事件接到 `openMenu` 上（`LibraryPanel` 里**没有** `@contextmenu.prevent`）。
  - 浮层与遮罩仍然照旧吃掉 `contextmenu`（`@contextmenu.prevent`）—— 那是**阻止浏览器原生菜单**
    冒出来，不是给应用加功能，改的时候别混为一谈。
  - 需要「就地快捷方式」时用**按钮或长按以外的可见控件**，别复活右键：这一条没有例外，
    新增手势前先看 `prompt.txt` 的「不要左右键和鼠标悬停」。
- **不提供文字选择**：全站 `user-select: none` —— `main.css` 的 `html` 上**一条**（含 `-webkit-` 前缀与 `-webkit-touch-callout: none`），**组件里不许再各写一份**；触屏上划行 / 拖滑杆 / 拖侧栏把手因此不会扫出蓝底与选择手柄。**只有 `input` / `textarea` 例外**（改标题、标签、段落名时要能在框里选字）。代价与边界见 §18.33。
- 单位：高度用 `dvh`（`100dvh`、`--wave-h: clamp(76px, 20dvh, 148px)`），安全区用 `env(safe-area-inset-*)`（`--safe-t/b/l/r`），并考虑横屏矮屏（`@media (max-height: 520px)`）。

## 10. hover 与按下（词表见 §5）

- **hover 是通用的桌面端交互态 —— 所有可点元素都要有**。
- 一律包在 `@media (hover: hover)` 里（**手机 / 触屏根本不匹配，所以点完不会残留悬停态**）。
- 只改颜色 / 描边 / 阴影（中性控件铺一档 `--surface-hover`、主题色填充控件用 `--accent-strong`、毛玻璃悬浮控件用主题色描边 + 光晕），**不改尺寸、不改布局**，且要一眼看得出来（把描边调成半透明的 `--accent-line` 这种「差一档灰」不算提示）。
- **按下必须比 hover 更重，而且要重得看得出来**：中性控件换 `--surface-active`（**不能**和 hover 用同一个 `--surface-sunken` 值糊过去）、主题色浅底与文字按钮换 `--accent-mid`、危险按钮换 `--danger-mid`；`scale` 只是附带的手感，**不能拿它当唯一的按下反馈**。
  - **唯一一处不用底色表达按下的是撤销条里那颗 `.undo-btn`**：它常态 / 悬停 / 按下都不铺底色（同理见上面 hover 那条的例外），按下改把**字色加深到 `--accent-deep`** —— 仍然是「按下比悬停重」，只是重量落在文字上（§18.31 第 104 条④）。
- **hover 规则写在对应 `:active` 前面**，否则按下时 `:hover` 也成立、会把按下态盖掉。

## 11. 配色

深浅色跟随系统（`prefers-color-scheme`），除黑白灰外**只允许两种语义色**：

- `--accent`（主题）：配套 `--accent-weak` / `--accent-line` / `--accent-strong`（悬停）/ `--accent-mid`（按下）/ `--accent-deep`（**文字**按下）/ `--on-accent`。
- `--danger`（危险）：配套 `--danger-weak` / `--danger-mid`（按下）/ `--danger-line`，**只用于不可恢复的删除**，不得当装饰色。

其余颜色一律按**角色**命名的变量取用，不要按明暗挑：表面 `--surface-page` / `--surface-card` / `--surface-float` / `--surface-control` / `--surface-sunken`（下凹面、轨道）/ `--surface-hover` / `--surface-active`，描边 `--stroke-strong` / `--stroke-soft`，文字 `--text-strong` / `--text-soft` / `--text-muted`。

- **所有颜色走 CSS 变量**，不要在组件里硬编码。Canvas 绘制要从 `getComputedStyle(documentElement)` 读变量（`store/ui.js` 的 `readPalette`），并在系统主题切换时重绘。
- **段落 / 反复 / 小节线等标记不各自配色**，一律 `var(--accent)`，靠形状与虚实区分。

**允许硬编码颜色的白名单**（这些值必须与主题无关，走变量反而会错，与 §7 是同一份）：

- `domain/pdf.js` 的 `#ffffff` —— PDF 纸面永远按白渲染，反色交给 `--pdf-invert`；
- `ScorePage.vue` 骨架屏的 `#fff` / `#f4f5f7` —— 它挂在 `--pdf-invert` 上，要模拟「白纸被反色」；
- `SwitchRow.vue` 开关滑块 `#fff`（要同时在深浅两色的轨道上都成立；这一行原来长在 `LibrarySettings.vue` 里，现在全项目只有这一份），以及 `store/library.js` `imageToCover()` 里给封面铺的白底 `#ffffff`（透明 PNG 转 JPEG 必须铺白）；
- `store/ui.js` 的 `readPalette()` 兜底值、`index.html` 的 `theme-color`、`public/favicon.svg`。

除以上各处，任何新增的十六进制 / `rgba()` 字面量都应先提成变量。

## 12. 浮在谱面上的东西：两条工具栏与四周留白

- 浮在谱面上的工具栏有两组：**底栏那对胶囊**（`PlayerView` 的 `.bottom` → `PdfViewer` 的 `reserved`）与**顶部那两条**（左上 `.back-dock`、右上 `.mini-dock` → `reservedTop`）。
- **四条边距只有一处定义**：`main.css` 的 `--glass-inset-t/b/l/r`（裸数值是 `--glass-gap-t/b/l/r`，供 `PdfViewer` 读）。所有浮动控件都从这里取，**别再各写一份 `calc(safe-x + Npx)`**。
- `PdfViewer` 量出它们的真实高度并扣掉，页面才不会压在胶囊底下 —— 细节见 [`invariants.md`](./invariants.md) §2 / §3。
- **顶栏可以整体平移出屏幕**（`settings.hideTopBar`「播放时隐藏顶栏」，实现见 §18.35）：
  被藏起来的顶栏 = 左上 `.back-dock`、右上 `.mini-dock`、乐谱库侧栏（`.side-bar`）、顶部两条提示（`.undo-stack`）。
  **底栏那对胶囊永远不动** —— 播放 / 停止还得按得到。而**「可视区」仍然按顶栏在的时候算**
  （`reservedTop` 不跟着变成 0）：否则每次开关顶栏整本谱都会重新排版、页面在手里跳一下。
  顶栏回来之后，`PdfViewer` 的 `barsObserver` 会量到新位置、把 `reservedTop` 补回来（见 §18.35）。

## 13. 浮层：两套布局 + 一个宿主

### 侧栏 = 乐谱库（`layout.library`）

- 横竖屏**都是左边那一条**、**占谱面宽度**（`settings.sideWidth`，夹在 `SIDE_MIN` ~ `SIDE_MAX`）；它是 `.player` 这个 flex 行里的子项，**不是浮层**。
- **只有「展开 / 收起」两态，没有「关闭」**：常驻 DOM，收起 = 宽度归零 + 过渡，内容由 `.side-clip` 裁切 —— 列表的搜索词 / 排序 / 多选都留着。
- 收起之后左上会出现一颗「乐谱库」胶囊当回头路（`.back-dock`），**别删它**。这条胶囊**常驻**（收起 / 展开都在），
  里面两钮：收起 / 展开切换钮 + 「设置」（见 §18.35）。侧栏标题栏里**没有**收起钮 —— 那一栏自己的控件就是这条胶囊。

### 抽屉 = 面板（`layout.panel`，一次只有一个）

- 面板 Teleport 到页面里的 `#sheet-slot`，**永远从底部升起**，高度固定 `85dvh`（不给拖）；位置 / 宽度由页面的 `slotStyle()` 用 CSS 变量给（横屏贴左边、宽度与侧栏一致；竖屏整幅宽、≤ 620 居中）。
- **打开新的会把旧的关掉**；**抽屉是模态的**：外面那层遮罩横竖屏都有、点一下就关（`closeCurrentDrawer()`，走面板登记过的 close）。横屏用从左到右的渐变遮罩（只压住抽屉那一列），竖屏是平遮罩。
- 侧栏与抽屉**互不影响**；唯一例外是 `toLibrary()` —— 导入完成那几处会顺手收掉抽屉，免得它压着列表。
- `store/ui.js` 的 API：派生 `libraryOpen` / `drawerOpen`；动作 `expandLibrary` / `collapseLibrary` / `toLibrary` / `openDrawer` / `closeDrawer` / `closeCurrentDrawer` / `resetLayout`。
- **没有「栈」这个东西**：`layout.stack` / `pushPanel` / `popPanel` / `topKey` / `hostOpen` / `libraryShown` / `clearStack` / `#side-slot` 都不存在，别往回加。
- **抽屉里一行只放一个动作按钮**：内容区里「按下去做一件事」的按钮（`.btn` 这类）**一行一个、各占满整行**，不许并排。
  抽屉最窄时就是整幅宽的手机屏，并排两颗各剩不到半行 —— 字被挤断、还容易点错。
  落地：`EditorPanel` 的「删除」独占整行、乐谱信息面板的封面 / 恢复默认各占一行，音频面板的「设置起点 / 更换音频」
  与起点选择器的「试听」都照这条（见 §18.40）。纵向 flex 容器里靠拉伸撑满即可，**别加 `.block`**（见 §14）。
- **不算「动作按钮」的，该一行多个还在一行**：滑杆、开关行（`SwitchRow`）、标签 chip、列表项 / 选项行（`.opt`）、
  九宫格键盘的按键（**没有**「成对包着数值的步进箭头算一颗控件」这条 —— 起点选择器已经没有 `◀ 值 ▶`，见 §18.42）。
  **九宫格键盘是浮层不是抽屉**，那条「取消 / 确定」并排是有意为之；**`center` 的居中确认弹窗也不归这条管**
  （它不传 `follow-layout`，不是抽屉，footer 里「取消 + 删除」并排照旧）。

### 浮层统一用 `AppSheet`

- 形态**一处决定**：同时传了 `follow-layout` 和唯一 `panel-key` 的面板 = 抽屉；`center` 的确认类弹窗**不要**传 `follow-layout`，它始终是居中模态卡片。
- **圆角按朝向分**：竖屏（整幅宽的底部抽屉）是**上边两个角**；横屏（贴左边、与侧栏同占一列）**只有右上角是圆的** ——
  上边和右边在横屏都是贴屏幕的实边，左上角圆着会与侧栏那条直边对不上（§18.35）。
- **不要在 CSS 里另按宽度判断形态**（`@media (max-width: 720px)` 的降级规则与横屏判据不一致时，「宽 > 720 的竖屏」下面板位置会错乱）。

### 把手（侧栏右边缘、总览左边缘共用的规则）

- 宽度 ≥ 最小值时 **1:1 跟手**；**比最小值还窄时只看拖动方向**（往收拢方向拖 = 收起、往展开方向拖 = 展开），两个方向都**只改状态**、让宽度走**同一段过渡**；指针一回到最小值以上**立刻恢复跟手**，别在方向模式里锁死。判向留 **3px 基准**，否则手抖会来回翻。
- **拖进最小值以内不会「变红警告」**：越界罩危险色 + 叉号那套 `.close-veil` 已经随「收起 / 展开」模型一起删了，**别再把那层遮罩加回来**。

## 14. 一件事只有一个实现

动手前先查 [`UI-COMPONENTS.md`](./UI-COMPONENTS.md) 和这份文档，别再造第二个同语义的东西：

- **互斥选择按场景选、不要混**：面板 / 浮层里的选项列表用 `.opt-list` + `.opt`；锚在按钮上的**短单选**（排序方式、拍号分母）用 `ContextMenu`。**不要再造并排的分段按钮**（**没有** `.segmented`）。
- **「针对某个对象的几个动作」用 `ContextMenu`**（卡片「⋯」），**不要用 `AppSheet` 装动作菜单** —— 那会撑出第二个抽屉。要表单、要说明、条目多的才用面板。
- **操作反馈一律用 `toast()`**（`store/ui.js`）—— 顶部提示条，排在撤销 banner 下面，外观走 `.glass`。**不要再自建第二套提示机制**。
- 毛玻璃悬浮容器 → 布局类 + `.glass`；**单颗浮动按钮 → 只有一个 `.cap-btn` 的胶囊**（**没有** `.cap-circle`）。
- 药丸标签 → `.chip`（可点加 `.tap`）；搜索 / 筛选药丸 → `.search-bar`；遮罩 → `.scrim` / `.scrim-bare`；空状态 → `.empty`；表单信息块 → `.info`；单选勾 → `.tick`。
- 选择文件 / 导入入口 → `.btn`（**纵向 flex 容器里别加 `.block`**：靠拉伸撑满即可，`width: 100%` 会连同左右 margin 一起溢出）；**不要再造虚线的「上传框」** —— 局部不收拖入。
- 侧边栏编辑器外壳 → `EditorPanel`（段落 / 反复就是这么共用的）。

### 16.1 图标是独立文件

可直接被图标集文件覆盖。

### 16.3 浮层与面板统一到「一个宿主」

- 浮层与面板由 `store/ui.js` 的 `layout` 管（现行为见 §13：**侧栏 = 乐谱库**、**抽屉 = 面板**）。
- 宿主同一时刻只显示一个面板，新面板上来会先把上一个关掉（所以各组件的 `open` 状态不会残留成
  「看不见但还开着」）；关闭动作的异步时序不能把刚上来的新面板清掉。
- 关掉宿主时先关面板（收起侧栏、关掉乐谱库抽屉都是），否则托管中的面板会「掉出来」变成独立浮层。

**上下文菜单**：适合放「针对某个对象的几个动作」的地方用 `ContextMenu` ——
卡片「⋯」的 信息 / 选择 / 删除，以及锚在排序按钮上的短单选。
**入口只有「⋯」**（全项目不用右键，见 §9）。
它**不参与面板宿主**，所以从抽屉里弹出来也不会叠第二层抽屉，而且不画遮罩（不该把整页压暗）。
要表单、要说明、条目多的（设置 / 筛选 / 新增 / 信息 / 倍速）用面板。

### 16.4 乐谱库统一成一种列表 + 卡片「⋯」+ 自定义封面

- **列表只有一种样子**：横屏侧栏里与竖屏抽屉里**同一套行式列表**：
  `封面(固定正方形，图等比缩放完整放进) + 标题(单行省略) + 右侧动作位`；**没有卡片网格**。
- **行内动作走「⋯」按钮**：每行右侧固定一个 `.icon-btn.flat` 的「⋯」，点它弹出 `ContextMenu`
  （锚在按钮下方）。多选模式下「⋯」就地换成勾选圈，行宽不变。
  多选圈是普通行内元素，直接用 `--stroke-strong` / `--accent` / `--on-accent`，**不在 §7 白名单里**。
- **自定义封面**：信息面板里「封面」一行 —— 预览 + 「选图片」+（仅自定义时出现）「恢复默认」。
  实现在 `store/library.js` 的 `setScoreCover(id, file)`：图片等比缩到 420px 宽、铺白底后存成 JPEG
  dataURL，并记 `coverCustom = true`；传 `null` 就用 PDF 首页重新生成（也就是「恢复默认」）。卡片与预览里的
  `img.custom` **不挂 `--pdf-invert`** —— 用户自己的图片不跟着深色模式反色。

### 16.5 信息面板排布 + 整页拖入 + pmz

- **信息面板**：标签**只能回车添加**（没有「添加」按钮），且标签列表在**输入框下面**；
  详细信息**每样一行**（页数 / 小节数 / 音频时长 / 占用大小 / 创建时间 / 更新时间），
  不把两项挤在一行、也不用 `·`、`/` 当分隔符；
  「占用大小」只有一个总数，`scoreFileInfo()` 也只返回一个总数。
  封面框见 §18.6 第 38 条（整行宽虚线框 + 框内 68×68 预览）。
- **列表里标出当前打开的乐谱**：`.card.current` 给整行加 `--surface-control` 底色、标题用主题色。
  由 `PlayerView` 传 `current-id` 进来，`LibraryPanel` 不直接读播放器状态。
- **整页拖入统一到 `PlayerView`**：`LibraryPanel` 只负责列表与面板，**不自己监听拖放**。
  提示层 `.drop-veil` + `.drop-card` 是整页虚框，
  `dragenter/dragleave` 用计数器（子元素之间移动会连发），被局部 `stop` 掉的 drop
  由 window **捕获阶段**的 `resetDrag` 收尾，否则提示层会卡住不消失。
- **分流规则**（分类在 `domain/zip.js` 的 `classifyFiles`，纯逻辑、有单测）：
  pdf / zip / pmz 建新谱；音频没音频就直接加、已有则确认后替换；JSON 确认后覆盖当前配置；
  图片确认后换封面（不可恢复的覆盖用 `btn danger`）。没打开乐谱时除图片外都能自成新谱。
- **`.pmz`**：一张乐谱打成一个改了后缀的 zip，内容在**根目录**。
  单张导出就是这单个 `.pmz`，多张导出再打一层外层 zip、里面每张各是一个 `.pmz`；
  读取时把嵌套的 zip / pmz 递归摊平（展开到「以该条目文件名命名的子目录」，所以不会串味），
  旧版「每张一个子目录」的 zip 仍然读得进来。

### 16.6 术语澄清 + 设置瘦身 + 标签行 + 封面随包

- **术语定死**：**`.pmz` = 单张乐谱的压缩包**（改了后缀的 zip，内容在根目录），
  **`.zip` = 装多张 pmz 的容器**。代码注释、文档、界面文案统一按这个说法，不把两者混着叫「压缩包」。
- **设置面板只有偏好**：没有「导入 zip / pmz」按钮、没有 DEV 的「生成示例」按钮、也没有它们上面那条
  `hr.divider`。导入入口只有乐谱库底部那个按钮（§18.15 / §18.21）。
- **标签行**：**紧贴搜索框下面的一行**，不换行、**横向滚动**；
  最左边的 **「全部」** `flex: none` 固定在原地，管所有标签的选中状态（已全选 / 没筛 → 清空，否则全选上）。
- **导入按钮的位置**：乐谱库底部整宽按钮占住 `.library` 纵向 flex 的最后一个子节点 ——
  横屏落在侧栏底部、竖屏落在抽屉底部，跟着乐谱库走，不是整页右下角。
- **自定义封面进 pmz**：`buildScoreArchive` 会把记录里 `thumb`（dataURL）的原始字节写成 `cover.<ext>`
  （**只有 `coverCustom` 为真才写**，自动生成的缩略图不带）；`readZip` 认 `cover.*` 并返回 Blob，
  导入时用 `applyCoverData` 直接写回记录（不再过一遍 canvas），所以封面能一进一出。
- **拖入成功后自动打开到该文件对应的配置处**：pdf / pmz / zip → `openGallery()`（先 `closePanel()`
  让列表露出来，横屏展开侧栏 / 竖屏拉起抽屉）；JSON → 打开「乐谱信息」+ 进编辑模式；图片 → 打开
  「乐谱信息」；音频 → 「设置音频起点」。「打开某张谱的信息面板」走 `PlayerView` 的
  `infoRequest = { id, tick }` prop，`LibraryPanel` `watch` 到就 `openInfo()` —— 面板状态仍留在组件自己手里。

### 16.7 封面框整行宽 + 滚动动画开关 + 设置去标题

- **封面框**：`.pick.cover-pick` 是**整行宽**（`width: 100%` + `padding: 12px`），
  里面横排「**68×68 正方形**预览 + 提示文字」，提示文字在框内；「恢复默认」同样占满整行。
- **滚动动画**：开关是 `settings.scrollAnim`（布尔）。`PdfViewer.scrollToY` 只判一次：
  关掉就直接 `scrollTop = target`，开着就 340ms 缓动；**没有** `SCROLL_SPEEDS` / 分段档位。
- **设置面板里没有标题性文字**：没有 `field-label`（乐谱显示方式 / 滚动速度 / 预备拍与跳转），
  面板就是一串自解释的行；多开关的 `.set-block` 带 8px 行距（单选那一组的标题仍保留，见 §18.11）。
- 术语见 §18.5，拖入自动打开的验证见 §18.5。

### 16.8 设置面板：单选标题 + 开关去掉卡片 + 统一行距

- **`.set-row` 没有卡片外观**：**没有** `background: var(--surface-card)` 与圆角。深色下 `--surface-card`
  （#14171b）比浮层面 `--surface-float`（#191d22）更暗，套上去就是「一个开关一张卡片」；浅色下两者都是白色，
  根本看不出来 —— 于是深浅色看起来不一样。两边都是干净的「文字 + 开关」行，
  靠 `.set-row { min-height: var(--tap-min); padding: 2px 0 }` 保证触控高度。
- **单选那一组保留小标题**：「乐谱显示方式」（只有这一组用 `.set-block` + `field-label`），
  开关行没有标题。
- **统一行距**：开关行全部是 `.settings` 的直接子节点，
  「滚动动画 → 播放预备拍」之间**没有**多出来的 20px 间距；`.settings { gap: 6px }`，
  只有带标题的 `.set-block` 用 `margin: 8px 0` 稍微隔开。

### 16.9 圆钮与所有按钮同尺寸

- **没有 `--float` / `.cap-circle` / `.back-circle` / `.fab`**：三个悬浮圆钮（底栏「编辑 / 完成」、
  左上返回 / 侧栏开关、乐谱库左下角）现在与普通按钮一样大（**46**），不单独放大一档；
  单颗按钮一律是「只有一个 `.cap-btn` 的胶囊」。
- **胶囊容器不写死高度**：`.capsule` **不设 `height`**、
  `padding` 按 §18.16 的 5px，高度跟着里面的圆钮走（46 + 上下 padding + 上下 1px 描边 = `--cap-h` ≈ 58）。
  ⚠️ 一旦写死 `height`，`box-sizing: border-box` 下内容盒只剩 `46 − padding − 描边`，会把圆钮裁掉一圈。
- `--hint-top` = `calc(var(--safe-t) + var(--cap-h) + 16px)`；`PlayerView` 的 `--dock-pad` = **110px**。
- 仍然**没归到两档**的裸值（待办）：`.btn.lg` 的 54、九宫格按键的 52、`.opt` 的 56。

### 16.10 硬下限与基准同值

- **`--tap-min` 与 `--tap` 同值（都是 46px）**。走硬下限的控件：`.btn.sm`、`.chip.tap`（可点标签）、
  九宫格键、上下文菜单项、`.set-row`（设置里的开关行）、音量滑杆、`NumberPad` 输入框。
- **令牌名不合并**：名字标的是**用途**（基准 / 硬下限），
  想整体调大调小时改哪一档只影响它管的那批控件；§3.1 与 §9 都写着「两档同值」。
- 仍然没归到两档的裸值：`.btn.lg` 的 54、九宫格按键的 52、`.opt`（浮层选项行）的 56、
  卡片封面正方形的 44（那不是按钮，只是个装饰方块）。

### 16.11 反复没有编辑器：类型靠落点自动识别

- **标记类型只有「开始」「结束」「房子 1 起点」三种**，房子 2 不是一个标记，它只是显示在乐谱上的一个样式。
- **反复标记没有面板**：`store/player.js` 的 `addRepeatAt` 落点即定类型，再点一次就是删除。
- 三种线的视觉区分：开始 = 实线 + 细线 + 圆点朝右、结束 = 同样但圆点朝左、房子起点 = 一条细竖条；
  房子括号是「括号 + 1. / 2.」。
- 房子括号的形状：房子 1 两头都收尾；**房子 2 只起笔、不收尾**（右边敞着口），
  且它的起笔比共用那条结束线再右让 `HOUSE_GAP_X`（4pt），两条括号之间留一条缝。
  **没有「房子 1 起点」时房子 2 整条不画**（`deriveRepeatBlocks` 里就不推它）。
- 房子括号也是**删除热区**：反复工具下点括号（含「1. / 2.」标签那一块）就删掉这一块的「房子 1 起点」——
  那条细竖条只有 2pt、太难点中，而括号是房子 1 最显眼的形状。悬停到括号时高亮那条细竖条，
  「点它会删掉什么」看得见（命中在 `ScorePage.vue` 的 `hitHouseBracket`）。
- **反复区块的配对逻辑只有一份**：`domain/timeline.js` 的 `matchRepeatBlocks` / `deriveRepeatBlocks`，
  **时间轴、谱面渲染、落点判定、删除范围共用**（一件事只有一个实现）。
- **反复工具没有「打开」这个动作**，所以工具提示里不写「可设反复开始/结束/房子 1/房子 2」。
- 两条互补的规则另见 §18.42（两次点击成对 + 待定起点）与 §18.42
  （播放按反复走 + 跳跃落点闪烁 + 进编辑模式停播）。
- 配对、落点决策、房子跨度、展开顺序、跳转取哪一遍这些纯逻辑有 `npm run test:unit` 兜着。

## 18. 人工验证清单（UI 改动必须由人过一遍）

> 清单按**要验证的东西**读，一条条都是「现在应该长什么样 / 应该怎么动」。
> 自动化只能兜住纯逻辑那半边；UI / 触屏表现按 `invariants.md` §12 一律交人工（真机或 DevTools 触屏模拟，
> 鼠标模拟不出触屏手势）。

### 18.1 令牌 / 尺寸 / 危险色

1. **段落设置面板**：拍号分母那颗钮打开的是短单选菜单，**没有**「在进度条上显示」勾选框。
2. **跳转浮层的段落圆点**：跟随主题色（深色下是亮蓝、浅色下是深蓝），不是固定的另一个蓝。
3. **左上那颗胶囊**：与底栏 / 右上那几条**同高同形**（内含 46 的 `.cap-btn`）。
4. **删除按钮**（段落、删除确认弹窗）：**红色**文字与描边，按下时有淡红底。
5. **触控手感**：库顶栏图标钮、筛选药丸、标签 chip、九宫格键、`.btn.sm`、搜索清除键**都 ≥ 46px**。
6. **深浅色都过一遍**：没有哪个面变成一片同色（令牌完整性的检查）。

### 18.2 去重（一件事只有一个实现）

7. **设置面板**：面板里**没有说明小字** —— 包括「预备拍与跳转」几个开关下面那行、以及「工具栏显示文字」下面那行。
8. **操作反馈（重点）**：以前完全看不见的提示现在会冒出来，位置在**顶部、撤销条下面**，
   毛玻璃药丸、从上方滑入。最容易撞见的三条：
   - 段落/反复工具点到**最后一条小节线** → 「这条小节线后面没有小节，无法…」
   - 删「开头」段落 → 「「开头」是固定段落，不能删除…」
   - 导入音频/PDF、设音频起点、删除标记、跳转段落 → 各自的确认语
   删除段落/反复时会**同时**出现顶部撤销条 + 其下的 toast，这是预期的。
9. **两条提示的毛玻璃同一套参数**：撤销条、toast、左上胶囊、总览胶囊外观一致（`.glass`）。
10. **浮层里的搜索框**：**填充药丸、没有描边**，与顶栏筛选按钮一致；清除键 46。
11. **「新增乐谱」里三个文件行**：高度 46，与 zip 导入行同一套外观，**有按下态**。
12. **空状态文字**（未打开文件 / 无 PDF / 加载出错）：用弱文字色，比正文略淡一点。
13. **底栏那两个胶囊**：毛玻璃、**不是透明底**，边框与阴影都在。
14. **浮层形态**：段落与反复面板**一律从底部弹出**，与跳转 / 倍速 / 音频一致。
    横屏（宽 > 高且宽 ≥ 700）不受影响，全部贴在左侧栏位置弹出。
15. **横屏下的乐谱库菜单**：从侧栏打开 筛选 / 排序 / 设置 / 动作菜单〔即卡片「⋯」〕/ 信息，
    **贴在侧栏位置**弹出，与跳转 / 倍速 / 音频 / 编辑面板一致。
    「删除乐谱」的确认弹窗仍然居中。
16. **横屏的核心规则（重点验证）**：项目里所有面板（跳转 / 倍速 / 音频 / 段落 / 筛选 / 排序 /
    设置 / 动作菜单〔即卡片「⋯」〕/ 信息）**都显示在左侧栏里**，不再有遮罩、不再盖住谱面：
    - 打开任意面板 → 乐谱列表让位，面板出现；关掉（面板右上角的 ×）→ 列表回来。
      **左上圆钮永远是「收起 / 展开侧栏」**（收起时顺带关掉面板），不显示 ×、也不只关面板。
    - 面板开着时**谱面仍然可见可点**（试着点另一条小节线切段落、或点某小节跳转）。
    - 面板开着时再开另一个（例如设置 → 点倍速）→ 前一个自动关掉，侧栏换成新的那个。
    - 侧栏收起状态下点倍速 / 音频 → 侧栏会自动展开并显示面板。
    - 把侧栏拖窄到最小 → 侧栏收起，同时面板被关掉，不会留下"面板还在但看不见"的状态。
    - **竖屏**：以上面板是底部抽屉 / 居中弹窗。
17. **侧栏收起 / 展开的手感（重点）**：
    - 点左上圆钮，或把侧栏往左拖到最窄 → 侧栏**带动画滑走**（不是瞬间消失），右边框同步淡出。
    - 收起后**屏幕左边缘留一根竖条**：鼠标移上去变蓝变长；**按住往右拖，侧栏从边缘长出来**。
    - 展开状态下把鼠标停在侧栏右边缘 → **和按下时长得一样、只是灰的**：中间那根竖条变长变粗，整条边框线跟着亮起。
    - 按住拖动 → 同样的形状换成主题色，右边缘再亮一条线。移开鼠标立刻回到 1px 弱灰边框 + 中间小竖条。
    - **收起后，左边缘那根把手点一下就展开**（不用拖），宽度沿用上次的。
    - 拖动时**一进最小宽度（280px）以内就立刻收起**（不等松手）；松手后不会停在 40px 这种没法用的宽度。
    - 收起后继续往右拖、越过 280px → 侧栏重新拉出来，宽度跟着指针，边缘始终跟着手指。
    - 触屏没有 hover，但按下 / 拖动中的变色与边缘亮线仍然可见。
18. **竖屏不叠两个抽屉（重点）**：
    - 打开乐谱库 → 点卡片右边的「⋯」→ 出现的是**贴着按钮的小菜单**（信息 / 选择 / 删除），
      **不是**第二个底部抽屉；点空白处关掉。
    - 点顶栏的排序图标 → 同样是**贴在按钮下方的小菜单**（4 项、当前项带勾），也不是抽屉。
    - 抽屉里点「设置」/「筛选」→ **在同一个抽屉里换内容**：标题变、列表让位；
      关掉面板 → 回到乐谱列表，抽屉不关。
    - 关掉抽屉（点遮罩 / 右上角 ×）时，里面的面板会先被关掉，不会「掉出来」变成独立浮层。
19. **横屏**：所有面板（含乐谱库的几个）都落在左侧栏里，谱面全程可见可操作。
20. **设置没有保存按钮**：
    - 「乐谱信息」面板：底部**没有 取消 / 保存**。改标题后**点别处或回车**即生效（关掉面板也不算放弃）；
      加标签、点标签上的 × 删标签，都是**立刻生效**。
    - 「音频起点」：底部只有「返回音频设置」。拖动频谱 / 滚轮**立刻改掉** `meta.audio.startOffset`
      （「添加弱起小节」开关立刻改 `startPosition`），可以直接播放听效果；关掉面板不会回退。
    - 仍然保留按钮的只有：删除乐谱确认的「删除」、删除标记确认的「删除」—— 那是不可恢复的确认，不是设置。
21. **多选时顶栏整条被替换**：从卡片菜单进多选后，
    **顶栏上的「搜索/筛选 + 排序 + 设置」整条消失**，换成「全选（选满时变「清空」）/ 导出 / 删除 / 完成」。
    **不显示选中数量**；四个按钮**始终平分整条顶栏**（`flex: 1` + `min-width: 0`，没有最小宽度、不横向滚动），
    且与搜索药丸**同高 46px**，所以切进切出顶栏不跳。四个标签都是 2 个字，侧栏拖到很窄也不会被裁。
22. **宽窗口用侧栏**：窗口**比底部抽屉的最大宽度（620px）还宽**时，不管高宽比一律用侧栏布局。
    例如 700×1400 的窄高桌面窗口，左上出现乐谱栏、面板落在侧栏里，而不是底部抽屉。
    抽屉上限 620px 是 `AppSheet` 的 `.sheet-panel.bottom`，判据常量是 `SHEET_MAX_W`。
23. **顶部两条提示按窗口居中**：撤销条与 toast 都是 `fixed`、**两条都按整个窗口居中**，
    横屏侧栏开着时也不会偏向一边。

### 18.3 乐谱库列表 + 「⋯」+ 自定义封面

24. **两侧宿主一种样子（重点）**：横屏侧栏里的乐谱库与竖屏抽屉里的乐谱库**长得完全一样** ——
    一行一张：左边小封面（**44×44 正方形**）、中间标题（长了就省略号，不换行两行）、右边一个「⋯」。
    **没有卡片网格**。
25. **卡片动作从「⋯」进（重点）**：
    - 每行右侧的「⋯」→ 菜单**贴在按钮下方**，三项：信息 / 选择 / 删除；点空白或 Esc 关掉。
    - **长按没有任何效果**，也不会出现「松手后又触发一次点击」。
    - **右键什么都不发生**（全项目不用右键，见 §9）。
    - 点卡片本身 = 打开这张乐谱（多选模式下 = 勾选 / 取消勾选）。
26. **多选时「⋯」变成勾选圈**：进多选（菜单里的「选择」）后，右侧的「⋯」就地变成圆圈，
    选中的是**实心主题色 + 白勾**、未选中是灰色空心圈；整行有主题色浅底。
    **行宽不变**（不会因为切进多选而抖动）。
27. **自定义封面**：卡片「⋯」→「信息」→「封面」：
    - 点封面框挑一张本地图片 → 预览与卡片缩略图**立刻换成它**（不需要保存）。
    - 换完之后会多出一个「恢复默认」按钮（**占满整行**），点它回到自动封面。
    - **深色模式**下：自定义封面**不反色**（它本来就是彩图），而 PDF 首页生成的封面
      仍旧反色成深色纸面。
    - 没有 PDF 的乐谱点「恢复默认」→ 封面变成占位图标。

### 18.4 信息面板 / 整页拖入 / pmz

28. **「乐谱信息」面板的排布（重点）**：
    - 「标签」只有**一个输入框在上、标签列表在下**，**没有「添加」按钮** —— 打字后**回车**才加进去。
    - 「封面」是一个**撑满整行**的虚线上传框（形态见 §18.6 第 39 条），点框 = 选图片；
      把图片**拖到这个框上** = 走整页那条路（不会触发框内局部换封面）。
    - 「详细信息」**每样一行**：页数、小节数、音频时长、占用大小、创建时间、更新时间。
      没有「小节 / 页数」「创建 / 更新」这种一行两项，也没有 `·`、`/` 分隔符；
      「占用大小」只有一个总数（不显示 PDF / 音频 / 波形各自的体积）。
      **整个面板里没有任何分割线**（见 §18.7 第 41 条：`hr.divider` 与明细行的下边框都没有）。
29. **列表里当前打开的那张有底色**：打开一张乐谱再看乐谱库，那一行有一层浅灰底、
    标题是主题色。打开另一张，底色跟着换过去。
30. **整页拖入（重点，拖到窗口任意位置都算）**：
    - 拖动时整页出现虚框提示层，写明「松开即可导入」和当前会怎么处理；松手后提示层立刻消失
      （**不要出现拖过侧栏/浮层后提示层卡住不消失**的情况）。
    - **每种都处理成功后自动打开到对应位置**（不用自己再去找）：
      - 拖 **PDF** → 乐谱库多一张新谱，并**打开乐谱库**（横屏展开侧栏、竖屏拉起抽屉）。
      - 拖 **pmz / zip** → 导入成新乐谱，同样**打开乐谱库**（zip 里有多少张就导入多少张）。
      - 拖 **音频** 到当前谱面：本来没音频 → 直接加上；**已经有音频 → 先弹确认框**，确认后替换，
        两种都会**直接打开「设置音频起点」**的频谱图。
      - 拖 **JSON** 到当前谱面 → 弹确认框，确认后当前谱面的标记（小节线 / 段落 / 反复 / 标签）
        被这份 JSON 覆盖（**PDF 与音频保留**，页数仍按当前 PDF 对齐），然后**打开「乐谱信息」并进入编辑模式**。
      - 拖 **图片** 到当前谱面 → 弹确认框，确认后换成封面，然后**打开「乐谱信息」**（封面就在那一屏）。
    - **没打开任何乐谱时**：PDF / pmz / zip / 音频 / JSON 都会新建乐谱并打开乐谱库；
      只拖图片会提示「图片要打开一份乐谱后才能当封面」。
31. **导出是 pmz**：选中多张导出 → 下载的是一个 zip，**解开后里面每张乐谱各是一个 `.pmz`**
    （不是一堆 `score.json`/`score.pdf` 散文件）。只选一张导出 → 直接下载单个 `<标题>.pmz`。
    把这个 pmz（或整个 zip）再拖回页面，应该能原样导入回来。

### 18.5 术语 / 设置 / 标签行 / 封面随包

32. **术语**：`.pmz` = 单张乐谱的包，`.zip` = 装多张 pmz 的容器。界面与文档都按这个说法。
33. **设置面板只有偏好**：齿轮里**只有**「工具栏显示文字 / 显示整页·始终居中 / 滚动动画 / 四个预备拍与跳转开关」，
    底部没有「导入 zip / pmz」「生成示例」，也没有那条分割线。导入入口只有乐谱库底部那个按钮。
34. **标签行**：
    - 搜索框**紧下面**就是一行标签，**不换行、可以左右滑动**。
    - 最左边的**「全部」固定在原地不跟着滚**。它亮着 = 没有标签筛选（显示全部）。
    - 点「全部」：如果所有标签都已经选上（或本来没筛）→ 清空筛选；否则一次把**所有标签**都选上。
    - 单个标签点一下切换选中。
35. **导入按钮在乐谱库底部**：横屏时在**侧栏底部**、竖屏时在**抽屉底部**，
    跟着乐谱库走，不是整页右下角（谱面区域右下角没有按钮）。多选时隐藏。
36. **封面随 pmz 一起走**：
    - 给某张谱换过自定义封面 → 导出这张（pmz）→ 删掉这张 → 再把这个 pmz 拖回来：
      **封面应该还是你那张图**（深色模式下也不反色）。
    - 没换过封面的谱导出时不写 `cover.*`，导入回来仍是 PDF 首页生成的封面。
37. **拖入成功后自动打开到该配置处**：
    - 拖 **PDF / pmz / zip** → 乐谱库自动打开（横屏是侧栏展开，竖屏是抽屉弹出），
      能看到刚进来的谱；**不会**把你带进某一张谱里。
    - 拖 **JSON** → 覆盖完自动打开「乐谱信息」，**同时底栏已经进入编辑模式**（能直接在谱面上核对标记）。
    - 拖 **图片** → 换完封面自动打开「乐谱信息」，一进去就能看到新封面。
    - 拖 **音频** → 处理完直接落在「设置音频起点」。

### 18.6 封面上传框

38. **封面框**：
    - 它是一个**撑满容器宽度**的虚线上传框，四周有 12px 内边距。
    - 框里**横排**：左边 **68×68 正方形**小预览（没有封面时是灰色占位图标），右边是提示文字
      「点击上传替换封面」（**文字在框里**，不挂在框下面）。
    - 点框 = 选图片；把图片拖到框上走整页拖放那条路（见 §18.21 第 67 条）。
    - 换过封面后，框**下面**出现一个**同样占满整行**的「恢复默认」按钮，
      点它回到 PDF 首页生成的封面。

### 18.7 滚动动画开关 + 设置里没有标题文字

39. **「滚动动画」开关**：设置面板里是**一行开关**（和「工具栏显示文字」长得一样）。
    开着 = 跟随播放滚动时 340ms 缓动；**关掉 = 直接跳到位**。自己拖动谱面、点小节跳转不受影响。
    `settings.scrollAnim`（旧 localStorage 里的 `scrollSpeed` 会被忽略，开关回到默认「开」）。
40. **设置面板里没有标题性文字**：从上到下就是：工具栏显示文字 / 显示整页·始终居中 / 滚动动画 /
    播放预备拍 / 跳转预备拍 / 循环段预备拍 / 跳转自动播放，一行一项，**没有分组标题**
    （唯一例外见 §18.11）。
41. **「乐谱信息」里一条分割线都没有**：标题 / 标签 / 封面 / 详细信息之间只靠 `.form` 的 16px 间距分开，
    明细行之间只靠 5px 行内边距分开，**整块面板看不到任何横线**。

### 18.8 封面固定正方形

42. **封面一律是固定正方形，图完整放进去**：
    - 列表里每行左边的小封面是**正方形 44×44**；
      信息面板封面框里的预览是**正方形 68×68**。
    - 图按**等比缩放完整放进方框、不裁切**：自定义封面什么比例都行，**不会把图裁掉一块**。
    - 方框**不铺底**，留空是透明的（见 §18.19 第 65 条）。
    - PDF 首页生成的封面也照这个规则显示（竖版 A4 会完整缩进方框）。

### 18.9 点「⋯」不带动整行

43. **按行内按钮时只有按钮自己有按下动画**：整行的按下态带排除条件
    （`:active:not(:has(.icon-btn:active))`）：**按「⋯」时只有那个圆钮自己缩小变底、整行不动**；
    按行的其它地方（打开乐谱 / 多选时勾选）是整行缩放。

### 18.10 深色模式封面反色
44. **反色只跟「是不是自定义封面」有关**：
    - **深色模式下**：默认封面（PDF 首页生成的）**反色**成深色纸面；
      只有自己换的封面**不反色**（彩色图原样显示）。
    - ⚠️ **`coverCustom` 必须显式传值，不能靠「有没有图」推断**：推断错的话，点过「恢复默认」的乐谱
      会把它错记成 `true`，默认封面在深色模式下就不再反色。
    - **已经中招的乐谱**：打开它的「乐谱信息」，此时会看到「恢复默认」按钮 ——
      **再点一次**就把标志修正回来了（换一次封面再恢复默认也一样）。

### 18.11 设置面板的两条形态规则

45. **单选那一组有小标题**：「乐谱显示方式」写在 `.segmented`（显示整页 / 始终居中）上面 ——
    光看两个按钮不知道在说什么。**开关行**（工具栏显示文字 / 滚动动画 / 预备拍开关）没有小标题，
    它们的文字自己就说清了。
46. **开关行一律没有背景**：**没有** `background: var(--surface-card)` 那种圆角卡片 —— 深色下 `--surface-card`
    （#14171b）比面板底 `--surface-float`（#191d22）还暗，套上去看起来像一格格的卡片；
    浅色下两者都是白色、看不出来 —— 深浅色就不一致了。深浅色都是「一行文字 + 一个开关」。
47. **开关之间同一套间距**：所有开关行都是 `.settings` 的子节点，
    「滚动动画 → 播放预备拍」之间**没有**多出来的一段间距；只有带小标题的那组用 `.set-block` 稍微隔开。

### 18.12 收起侧栏 + 筛选搬进列表 + 导入按钮

48. **左上圆钮只管「收起 / 展开侧栏」，收起不关掉面板**：
    - 收起侧栏（点左上圆钮、或把侧栏往左拖到最窄）只是把它**藏起来**：托管在里面的面板
      （设置 / 信息 / 段落 / 倍速…）**保持打开**，再展开侧栏还回到那个面板，不会被踢回乐谱列表。
    - 想回列表就关掉面板自己（面板头部的 ×）；左上圆钮**永远不显示 ×**，也永远不「只关面板」。
    - 竖屏抽屉不一样：关掉抽屉时会先把面板关掉（抽屉一关宿主就没了，面板会掉出来变成独立浮层）。
49. **搜索与标签筛选在乐谱库列表里**：
    - 顶栏是一个**真的搜索框**（带清除键），**打字就过滤**，不用先开浮层。
    - 搜索框**下面一行**就是标签：不换行、**横向滚动**；最左边的**「全部」固定不动**，
      管所有标签的选中状态（已全选或没筛 → 清空，否则一次全选上）；单个标签点一下切换。
    - 两者都是**实时生效**，列表就在下面，边筛边看。多选模式下标签行跟着顶栏一起让位。
    - **没有第二套搜索入口**（没有「搜索与筛选」浮层）。
50. **导入按钮在乐谱库底部**：它是绝对定位在乐谱库左下角的，而竖屏抽屉的内容区（`.sheet-body`）默认是
    块级 + 内边距，里面的 `height: 100%` 会退化成「内容高度」，把按钮跟着列表一起推到最底下。
    所以抽屉的 `AppSheet` 要传 `flush`（内容区零内边距 + flex 撑满），`.library` 才有确定高度 ——
    **横屏在侧栏左下、竖屏在抽屉左下**，两种情况都稳稳贴着左下角不滚动。
51. **标签永远是「长胶囊」**：可点药丸（`.chip.tap`）有**最小宽度 `--tap × 2`（≈92px）**。
    否则「全部」这种一两个字的标签只有约 50px 宽、却有 46px 高，看起来是个**圆球 / 椭圆**；
    现在不管标签多短，都是一条**明显比高度长的胶囊**，文字与数量居中显示；
    长标签（如「练习曲 12」）按内容继续变宽。信息面板里那排可点标签同样受益。
52. **标签块在分割线下面，标题行写「标签」二字**：
    - 顶栏只有一行（搜索框 + 排序 + 设置），它的下边框就是**分割线**；
      **标签整块在线下面**：标题行左边「标签」、右边一个文本按钮，下面才是那排胶囊。
    - **「无标签」当成一个特殊标签**：排在标签行**最前面**，筛出**所有一个标签都没有的乐谱**，
      所以「练习」+「无标签」这样选，就是「有练习标签的 **或** 还没打标签的」（标签之间是「或」）。
      它只在库里真有这种乐谱时出现。
    - 没有真实标签时整块不显示（避免空库也挂一排没用的筛选）。
53. **标签默认全部勾上，「全选 / 清空」是标题行右边的纯文本按钮**：
    - 打开乐谱库时，标签行里**每一个标签都是勾上的**，此时列表不筛任何东西。
    - **勾上的样子是「主题色浅底 + 主题色描边 + 主题色文字」，也就是 `.chip.accent` 那一套外观**（`.chip.on`）；未勾的是普通胶囊（`--surface-control` 控件灰底 + `--text-soft` 文字）。这样**乐谱库标签行与信息面板里的标签长得完全一样**（信息面板那排是常亮选中态）。
      胶囊自带 1px 透明描边占位，所以勾上 / 取消时宽度不会跳。
    - 「全部」那个胶囊**不存在**，它是标题行右边的**一个纯文本按钮**（`.btn.text`：**没有边框、没有底色**，
      只有主题色文字）：已经有没勾上的显示「**全选**」，全都勾着就显示「**清空**」，点一下就在这两种状态之间切。
    - **勾选状态就是筛选条件本身**：全勾 = 全留下；点「清空」= 一个标签都没勾 = **谁都不符合**，
      列表会走到**「没有符合条件的乐谱」**的空状态（不是「不过滤」）。
    - 中间状态（只勾了一部分）就是真筛选：列表只留下命中所勾标签的乐谱（标签之间是「或」）。
    - **新出现的标签自动勾上**（导入带新标签的乐谱、给某张谱加新标签），
      而**手动取消过的标签不会被自动勾回来**。

### 18.13 圆钮与所有按钮同尺寸

54. **所有圆钮都是 46**：左上返回 / 侧栏圆钮、底栏右边的编辑 / 完成圆钮、乐谱库底部的导入入口 ——
    与播放 / 小节 / 倍速那些胶囊内圆钮**完全同尺寸**。
55. **底栏两个胶囊同高**：胶囊容器不写死高度、跟着圆钮走（46 + 上下 `--cap-pad` 5 + 上下 1px 描边
    = `--cap-h` ≈ 58），并且**圆钮与胶囊上下边缘齐平**（不再有 5px 内缩）。
56. **硬下限与基准同值（都是 46）**：`.btn.sm`、可点标签
    （`.chip.tap`）、设置里的分段项、九宫格键、上下文菜单项、设置里的开关行、音量滑杆、
    `NumberPad` 输入框 —— 都和普通按钮一样高。

### 18.14 选中标签的底色是主题色浅底

57. **勾上的标签用 `.chip.accent` 那一套外观**：`.chip.on` 是
    **`--accent-weak` 浅底 + `--accent` 描边 + `--accent` 文字**，未选中是普通 `.chip`（控件灰底 + 浅文字）。
    只点描边与文字、底色不动的话，一排默认全勾的标签里只有一圈细描边在说话，太弱；
    而项目里「主题色浅底 = 选中」已经有 `.accent` / `.icon-btn.on` / `.opt.on` 三处先例，跟着它们走更一致。
    **信息面板里的标签因此与乐谱库标签行完全同款**（那边是 `.chip.tap.on` 常亮 —— 它列出的就是这张谱已有的标签）。
    ⚠️ **悬停不能把底掉回灰色**：`.chip.tap.on:hover` 必须重申 `--accent-weak`（通用 `.chip.tap:hover` 写的是
    `--surface-hover`），否则鼠标一放上去选中态就消失；按下仍是 `--accent-mid`，比浅底重一档。
    宽度不会跳（`.chip` 自带 1px 透明描边占位）。

### 18.15 乐谱库底部的导入入口

58. **乐谱库底部是导入按钮**：
    - 列表**下面**一个整宽的按钮（`.btn.primary` + `.lib-import`）：图标 + 「导入文件」，
      **不列「支持 PDF / pmz / zip / 音频 / JSON」这类格式说明**。
    - 它是 `.library` 这个纵向 flex 容器的**最后一个子节点**，所以列表在上面滚、它原地不动。
      多选模式下跟标签块一起让位。
    - 走的是与整页拖放**同一条** `importFiles` 通道，所以「拖进窗口」和「点这个按钮选文件」结果一致。

### 18.16 胶囊的内缩

59. **`.capsule` 的 `padding: 5px`**：**真正裁圆钮的是写死的 `height`** —— `box-sizing: border-box` 下
    `height: var(--float)` 会把内容盒压成 `46 − padding − 描边`。容器**不写 `height`**，
    所以 padding 只是把它撑高：`--cap-h` **58 = 圆钮 46 + 上下 10 + 上下 1px 描边**，
    里面的 `.cap-btn` 仍是 46×46，四边各内缩 6px（1 描边 + 5 padding）不贴边。
    - 同一行里如果出现一颗**不在胶囊里**的 46 圆钮，它会比胶囊矮一圈 —— 所以圆钮一律装进胶囊（§18.17）。
    - `--dock-pad` = 110 够用（底栏 58 + 8 偏移）。
    - 验证：430×932 / 360×740、有文字 / 无文字 / 编辑模式四种组合下，
      圆钮都是 46×46、四边内缩 6px、胶囊都不横向溢出。

### 18.17 底栏两个胶囊同高同形 + 进出编辑模式的过渡

60. **「编辑 / 完成」也是一条胶囊，与另一个胶囊同高同形**：
    - 圆钮套一层 `.capsule`（5px 内边距 + 描边 = 58），里面的按钮用**胶囊内圆钮 `.cap-btn`**。
    - 于是普通模式 = 「4 钮胶囊 + 1 钮胶囊」，编辑模式 = 「1 钮胶囊 + 4 钮胶囊」，
      **两套总宽完全一样、四条胶囊全是 58 高**；单个按钮的那个胶囊因为等宽等高 +
      `border-radius: 999px`，渲染出来就是一个 58 的圆。
    - **`scale` 不能用在胶囊上**：它会把胶囊里的图标和文字一起压扁。
61. **进出编辑模式只动两个胶囊的宽度**：两个模式是**同一对胶囊换内容**
    （左边 4 钮 ↔ 1 钮、右边反过来），两套总宽完全一样（202 + 间隔 10 + 58），
    所以给 `.capsule` 加 `transition: width` 就是两颗胶囊互相让位。
    - 宽度**必须显式算出来**：`.cap-w1` / `.cap-w4` =
      `n × --tap + (n−1) × --cap-gap + 2 × --cap-pad + 2px 描边`。`auto` 宽度过渡不起来，
      所以胶囊的内边距与间隔是令牌 `--cap-pad`(5) / `--cap-gap`(2)，算式跟着令牌走。
    - 两个胶囊是普通 / 编辑**共用**的同一对 DOM 节点（只用 `v-if` 换里面的内容，胶囊本身不重建），
      否则节点一重建宽度过渡就没了。
    - 验证：左胶囊宽度 `202 → 112.6 → 75 → 62.2 → 58.3 → 58`、右胶囊同步走向 202；
      整行的宽 / 右边界 / 高全程不动（406 / 418 / 58）；
      胶囊的 `transform` 始终是 `none`；无文字模式宽度仍是 202 / 58。

### 18.18 全站 hover + 谱面悬停高亮

62. **所有可点元素都有 hover**，统一用两个令牌 —— `--surface-hover`（中性控件的悬停底）与
    `--accent-strong`（主题色填充控件的悬停色）。
    - 覆盖范围：`.btn`（含 primary / ghost / text / danger）、`.icon-btn`（含 flat / on）、`.chip.tap`、
      `.cap-btn`（含 primary / on）、`.cap-circle`、`.segmented > button`、`.opt`、`.ctx-item`、`.seg-item`、
      `.kind`、`.card`、`.set-row`、`.pad-key`、`.pad-presets button`、`.slider` 的滑块、`.pick`、
      `.spec`（音频起点频谱）、空状态里的「导入 PDF / 返回」按钮。
    - 全部包在 `@media (hover: hover)` 里：**手机 / 触屏根本不匹配，所以点完不会残留悬停态**。
      只改颜色 / 描边 / 阴影，**不改尺寸与布局**。
    - 验证（桌面）：鼠标扫过上面每一类控件 → 都能明显看出底色 / 颜色变化；
      按住不放 → 进按下态，且**不会被 hover 盖掉**。
    - 验证（手机 / 触屏）：点一下任何一个控件（按钮、卡片、标签胶囊、九宫格键、设置开关行）→
      **松手后不残留悬停态**（底色与描边立刻回到常态）。
63. **谱面也能 hover**：鼠标停在哪一小节，那一小节就铺一层 `--accent-weak` 浅底（**不描边**），
    和「当前小节」「框选」一眼区分开；鼠标移出谱面立刻消失。
    - 三者都**只有底色**，靠「主题色浅底 / 主题色浅底带小圆角 / 谱面灰浅底带小圆角」区分：
      圆角这一档 `ACTIVE_RADIUS`（3pt）由**当前小节与框选共用**，谱面 hover 那层不带圆角（§3.2 / §6）。
    - 谱面上没有 DOM 命中区（标记是 canvas 之上那层 `pointer-events: none` 的 SVG），
      所以命中和点击一样是在 `pointermove` 里自己算的，**只认 `pointerType === 'mouse'`**，触屏不参与。
    - 验证：桌面移动鼠标扫过谱面 → 只有光标所在那一小节变浅蓝底，移出谱面即消失；
      手机点按 / 长按拖动 → 不出现残留的浅蓝底。

### 18.19 按下比悬停重一档 + 封面框不再补成正方形

64. **「按下」必须比悬停重一档**：三级 —— 悬停 `--surface-hover` → 按下 `--surface-active`
    （深色更亮 / 浅色更暗一档）；主题色浅底与文字按钮按下用 `--accent-mid`，危险按钮用 `--danger-mid`。
    ⚠️ **悬停与按下共用同一个值、只靠 `scale` 区分是不行的**：看颜色完全分不出来（上传框尤其明显）。
    - 上传框（`.pick`）按下额外叠一条 inset 主题色描边：`--accent` 虚线框 + `--accent-mid` 底 + 内描边 + `scale(0.98)`，
      和悬停的「`--accent` 虚框 + `--accent-weak` 底」一眼能分开。**不直接铺满 `--accent`**：
      框里还有一行 `small.muted` 说明文字，铺满主题色后那行字对比度不够。
    - 覆盖：`.btn`（含 ghost / text / danger）、`.icon-btn`（含 flat / on）、`.chip.tap`（含 on）、`.pick`、
      `.card`、`.set-row`、`.cap-btn`（含 on）、`.cap-circle`（描边提到满色）、`.segmented > button`、
      `.opt`（含 on）、`.ctx-item`、`.seg-item`、`.kind`（含 on）、`.pad-key`、`.pad-presets button`。
    - 验证：鼠标**悬停**一个控件 → 看颜色；**按住不放** → 底色明显再深/再亮一档（不是只有缩放），
      松手回到悬停色。重点看乐谱库底部的「导入文件」按钮、底栏圆钮、标签胶囊、设置开关行、九宫格键。
65. **封面框只当尺寸约束**：`.thumb`（卡片 44×44）**没有**
    `background: var(--page-paper)` 与描边，`.cover-thumb`（信息面板 68×68）只在**没有图**时铺
    `--surface-control` 占位底（有图就用 `:has(img)` 撤掉）。图仍然 `object-fit: contain` 完整放进方框。
    - 于是 3:4 的封面就是 3:4 的样子，四周留空是**透明**的，不是一张「被补成方块」的图。
    - `.thumb-empty`（没有 PDF / 音频时的占位图标）保持灰底方框 —— 它是占位符，不是封面图。
    - 验证：给一张明显不是正方形的图当封面 → 卡片和「乐谱信息」里的预览都保持原比例，
      四周没有底色方块；PDF 自动封面（竖版 A4）同样是竖的；删掉封面 / 没有 PDF 时才回到灰色占位方框。

### 18.20 数字键盘不列备选数字 + 拍号分母用上下文菜单

66. **`NumberPad` 没有预设键**：九宫格上面**没有**那排「备选数字」（没有 `.pad-presets`、
    没有 `presets` prop）—— 它既占掉键盘一半高度，又暗示「只该填这几个值」。
    改成两行说明：**取值范围由 `min`/`max` 自动生成**（`20 – 400`、`≤ 16`、`只能填 1`），
    说不清格式的字段再传 `hint`（位置：「小节.拍：4.03 = 第 4 小节第 3 拍」；BPM：「可输入小数，例如 90.5」；
    总遍数：「2 = 演奏两遍」）。`hint` 还同时落到输入框的原生 `title` 上（桌面端悬停可见）。
    - 说明文字用 `.pad-hint`（`--text-muted`，范围那截用 `--text-soft` + 等宽），排在标题行与九宫格之间。
    - 验证（触屏）：点开 BPM / 位置 / 总遍数的九宫格 → 上面没有一排备选数字，只有范围与格式说明；
      点开「小节」这类只有范围的字段 → 只显示范围。
67. **段落「拍号」的分母是短单选菜单**：分母只有 1 / 2 / 4 / 8 / 16（`schema.js` 的合法集合），
    用 `NumberPad` 敲数字既慢又能敲出非法值。它是一个 `.unit-btn`（长得像 `NumberPad` 的框，
    **按钮上只有一个数字**，没有箭头图标），
    点开就是**乐谱库「排序方式」那套 `ContextMenu`**，
    每项是「n 分音符」、当前值带勾。分子仍然是 `NumberPad`。
    - `.unit-btn` 走 `--tap-min` 高、`--radius-sm`、`--stroke-strong` 描边，hover 换 `--surface-hover` +
      `--accent-line` 描边，按下换 `--surface-active` + `--accent` 描边（与其它中性控件同一套）。
    - 验证（触屏 / 桌面都点一下）：拍号那个 `4` 打开的是贴着按钮的菜单（不是九宫格、不是抽屉），
      点「8 分音符」→ 摘要行变成 `4/8`，菜单关闭；菜单在侧栏里也是贴在按钮下方弹出（不叠第二层抽屉）。

### 18.21 导入入口一律是按钮，拖放只留整页那一处

67. **所有「导入文件」入口都是按钮、只能点**：虚线框长得像拖放落点，而整页拖放已经能处理全部类型，
    局部落点只是重复。三处入口：
    - 乐谱库底部：`.btn.primary` + `.lib-import`（图标 + 「导入文件」）；
      **不列「支持 PDF / pmz / zip / 音频 / JSON」这类格式说明**。
    - 音频浮层（没有音频时）：`.btn.primary.block`（图标 + 「导入音频文件」），同样不列格式。
      （那一处能安全用 `.block`：`.audio` 没有左右外边距。）
    - 信息面板封面：`.btn.ghost.cover-pick`（整行宽、左对齐、`padding: 10px 12px`），里面是
      68×68 预览 + 提示文字「**点击上传替换封面**」。
    - 所以**没有**全局 `.pick` 与它的 `.on` / `.solid` / `.stack` 变体（`main.css`），
      `LibraryPanel` 里**没有** `onCoverDrop` / `@dragover` / `@drop`（也就没有局部的 `classifyFiles` 导入）。
      `PlayerView` 捕获阶段的 `resetDrag` **必须留着**（保证任何一次 drop 都把 `.drop-veil` 收掉）。
    - 验证：三处入口点一下都能打开选择文件的系统弹窗；把 PDF / 音频 / 图片拖到**封面按钮上**
      → 走整页那条路（图片 = 确认后换封面），**没有**「框内直接换」的局部行为；
      拖到窗口任意位置仍出现 `.drop-veil` 并按类型分流。

### 18.22 数字键盘是「全平台一套交互」

68. **桌面端也弹九宫格，触屏与桌面只差「屏不屏蔽输入法」**：鼠标点进来也是九宫格，
    **只有一条路**：点一下（触屏 / 鼠标都一样）弹九宫格，值一律在键盘里敲。
    - `input` **只当显示用、不接收原生编辑**：没有 `sanitize` / `onInput` / `commitText` /
      `onFocus` / `onBlur`，也没有 `focused` / `text` 两个 ref（原生输入那条路不可达，留着就是第二套实现）。
      物理键盘仍可用 —— 键盘打开时 `onKey` 在 window 上收数字 / 退格 / 回车 / Esc / 上下箭头。
    - **唯一的设备差异**是触屏把 `input` 设 `readonly` + `inputmode="none"`（不唤起系统输入法）；
      桌面端不设，但也没有原生编辑路径。`pointerType === 'touch' | 'pen'` 时更新 `touchMode` 并 `blur()`，
      混合设备（触屏笔记本）上手指点按也因此不会弹输入法。
    - **框里不挂「点我弹键盘」的角标图标**（`.nkey` 与 `keypad.svg` 都不存在）：
      框本身就是那个按钮。`.nfield` 有 hover（`--surface-hover` + `--accent-line` 描边）与
      按下（`--surface-active` + `--accent` 描边），`:focus-within`（键盘开着 / Tab 进来）亮 `--accent` 描边，
      三条按 hover → active → focus 的顺序排列；`.ntap` 透明按钮**常驻**（不是只在触屏渲染），
      Tab 也能聚焦到它、回车即打开键盘。
    - 验证（桌面）：鼠标点任意数字框（小节 / 拍 / BPM / 位置 / 总遍数…）→ 弹出的是九宫格，
      框里没有键盘角标；用物理键盘敲数字 / 退格 / 回车 → 键盘上的大数字跟着变、回车提交；
      鼠标悬停框有底色变化、按住更深一档，键盘开着时框的描边是主题色。
    - 验证（触屏）：点数字框 → 弹九宫格且**不弹系统输入法**；外观与桌面完全一致。

### 18.23 数字键盘：范围并进标题块，值旁边不写单位

69. **取值范围与标题上下两行**：范围既不能和格式说明挤在一行（`flex-wrap`
    会串行），也不该单占一整行把键盘撑高。`.pad-head` 左边是一块 `.pad-head-text`
    （`.pad-title` 上、`.pad-range` 下，`flex-direction: column`），右边还是那个大数字，
    `align-items: **center**` 让值与左边这一块**垂直居中**（不是跟某一行对齐）—— 顶部两行的高度差被这一块自己吸收。
    - **没有 min/max 的字段范围那一行不渲染**（`v-if="rangeText"`），标题块自然回到一行。
    - 三层各自的字色/字号：**标题** 14px / 600 / `--text-strong`（近黑，是这一栏的主角），
      **值** 22px / 700 / `--text-strong`，**范围** 12.5px / 600 / `--text-muted`（灰一档，别跟标题抢），
      **格式说明** 12px / 400 / `--text-muted`（`.pad-hint`，仍在标题块下面单独一行，需要才出现）。
    - 验证：点开 BPM / 位置 / 总遍数 → 左边「标题」下面紧跟一行灰范围（如 `20 – 400`），
      大数字在右侧、上下正好对着这两行的中间，格式说明在下面独立一行；点开没有范围限制的字段 →
      只有标题一行。
70. **输入框与键盘上都不显示单位**：**没有** `.nsuffix`（框里值右侧的「BPM / 小节 / 拍 / 遍」）、
    **没有** `.pad-buf i`（键盘大数字后面的单位），`NumberPad` **没有** `suffix` prop ——
    单位**只由字段的 label 表达**（「BPM（速度）」「位置（小节.拍）」「总遍数」「小节」「拍」），
    同一个单位不在标题和值里各写一遍。
    - 值因此是干净的：`120`、`4.03` 直接靠右对齐，不被单位挤窄；跳转浮层那两个框的「小节 / 拍」
      由 label 承担。
    - 验证：点开任何数字框 → 框里只有数字（如 `120`），键盘上的大数字后面也没有单位；
      每个字段的单位都能在它自己的 label 上读到。

### 18.24 谱面总览：卡片、缩略图内缩、三钮胶囊、圆钮带小字

71. **总览条是一张浮起来的圆角卡片，缩略图左右各内缩 5px**：如果这一列齐边，
    位图外面那圈 `box-shadow` 描边与投影会被滚动容器的 `overflow-x: hidden` 裁掉，看上去「左右边界
    和阴影都没显示出来」。所以 `k` 按 `内容宽 − 2 × PAD_X`（`PAD_X = 5`）算、页 `left: PAD_X`，
    小节带与蓝框也跟着左右对齐；卡片自己 `border: 1px solid var(--stroke-soft)` +
    `border-radius: var(--radius)` + `--shadow-2`，`right: safe-r + 12`（和底栏那对胶囊对齐）、
    `bottom: safe-b + 140px`（让开自己那条胶囊 58 + 8 与底栏胶囊 58 + 8）。
    - 裁切层 `.mini-clip` 自己带 `border-radius`：**`overflow: hidden` 不能放到 `.mini-panel` 上**，
      否则会把它外面那个调宽把手（`left: -7px`）一起裁掉。
    - 收起 = 宽度归零 **+ 边框归零**（`.mini-panel.collapsed { border-width: 0 }`），否则会剩一条 1px 竖线。
    - 验证：拖宽 / 拖窄总览 → 每一页左右都能看到一道描边和一点投影；收起后屏幕上除了把手不留任何痕迹。

72. **总览条自带一条三钮胶囊**：`.mini-dock` = `.capsule.glass`，
    浮在底栏胶囊上面（`bottom: safe-b + 74px`、`z-index: 25`），里面三个 `.cap-btn`：
    **整页 / 居中**（切 `settings.scrollMode`，图标 `file` / `list` 跟着换）、
    **抓手 / 指针**（手势模式，见 §18.35）、**收起 / 展开**（`toggleOpen()`）。
    - 它是**独立的浮层、不属于面板**：收起侧栏后面板没了，这条胶囊还在 —— 不然就没法再展开了。
    - 显示方式复用胶囊里已有的 `.cap-btn`（上图标 + 下小字），调显示方式时能直接看到谱面。
    - 验证：点最左那颗 → 图标与文字在「显示整页 / 始终居中」之间切换、谱面跟着换形态；
      点中间那颗 → 图标与文字在「抓手 / 指针」之间切换（见 §18.35）；
      点最右那颗 → 总览收起、胶囊与把手都留着。

73. **设置面板里没有「乐谱显示方式」这一组**：`LibraryPanel` 的设置浮层**没有**
    `.set-block` + `field-label` + `.segmented`，也没有 `SCROLL_MODES`。设置面板**全是开关行、没有任何分组标题**。

74. **左上圆钮也带小字**：一个光秃秃的箭头没人知道是干嘛的，它和胶囊里的圆钮一样
    「上图标 + 下小字」：横屏是「收起 / 展开」（`common.collapse` / `common.expand`），
    竖屏是「乐谱库」（`view.library.title`）。`.back-circle` 是 `flex-direction: column`，
    小字走 `.cap-label`。

75. **没有 `.segmented`**：显示方式搬走之后它已无任何使用者，按 §1 第 5 条「死代码删除，不保留『以后可能用』」
    整条删除；所以 §14 那条规则是「面板 / 浮层用 `.opt-list` + `.opt`、锚在按钮上的短单选用
    `ContextMenu`，**不要再造并排分段按钮**」，§3.1 的 `--tap-min` 归属里也没有它。

76. **显示方式那颗钮：两个字、不要常驻底色**：`.cap-btn` 的 `.on` 是给「工具选中」用的，
    而这里没有选中态要表达 —— 图标（`file` / `list`）加两个字已经说清现在是哪一种。文字是
    「**整页 / 居中**」（`minimap.modePage` / `modeCenter`），不加 `:class="{ on }"`。

77. **总览条是「贴右边的抽屉」，三钮胶囊在它上面**：
    - 胶囊在总览**上面**（`top: safe-t + 8`）；横向边距不跟总览走，而是**与右下角那对底栏胶囊完全一样**
      （`right: safe-r + 12`，见 §18.25 第 79 条）。
    - 总览自己：`right: var(--safe-r)` + **右边不留边距**、`border-radius: var(--radius) 0 0 var(--radius)`
      （**只有左边两个角圆**）、`border-right: 0`（那条线会正好压在屏幕最外一列像素上，像脏边），
      `top: safe-t + 74`（让开上面那条胶囊）、`bottom: safe-b + 74`（让开底栏胶囊）。
      `.mini-clip` 的圆角跟着只圆左边。
    - 验证：总览右边与屏幕右边齐平、右侧两个角是直角、左边两个角是圆的；胶囊在总览正上方；
      收起总览后胶囊留在原位。

78. **大 PDF 没有浏览器滚动条**：`PdfViewer` 的 `.viewer` 带
    `scrollbar-width: none` + `::-webkit-scrollbar { width: 0; display: none }`。右侧总览里那条
    （同样是浏览器原生、也能拖）才是可视的把手，两条并排纯属重复，深色下那条浅槽还格外抢眼。
    滚动本身不受影响（滚轮 / 触控板 / 键盘 / 拖总览都在），而且它**恒不显示** → 内容宽恒定，
    量出来的布局不会因为它出现 / 消失而抖。
    - 验证：桌面端打开一张长谱 → 谱面区右边不再有浏览器滚动条；滚轮、PageDown、拖右侧总览
      都照旧能滚，页宽与居中位置没有偏移。

### 18.25 总览胶囊的边距与底栏胶囊一致

81. **三钮胶囊与右下角那对底栏胶囊同一套边距**：底栏那条是 `.bottom`
    （`PlayerView`）给的 —— `bottom: safe-b + 8` + 左右 `safe-r + 12`。总览胶囊用
    `right: calc(var(--safe-r) + 12px)`、`top: calc(var(--safe-t) + 8px)`，

    所以胶囊会比它略往里 12px —— 这是刻意的：胶囊属于「浮动控件」，跟底栏那对一套边距。
    - 验证：桌面端总览胶囊的右边与底栏胶囊的右边在同一条竖线上；上边距与底栏的下边距视觉上等宽。

    <div class="capsule glass back-dock">

    - 于是三处悬浮控件**完全同形同高**（≈58）、同一套 hover（`:hover` 铺 `--surface-hover`）与

    - `PlayerView` 的 scoped 样式只剩定位：`.back-dock { top: safe-t + 8; left: safe-l + 12 }`
      —— **和底栏那条 `.bottom`、右上那颗 `.mini-dock` 是同一套边距**（8 / 12）。
      小字字号来自全局的 `.cap-btn .cap-label`，不再本地写一份。
    - **没有 `.cap-circle`，也没有 `.back-circle`**（含 `.cap-circle` 的 `:hover` 光晕与 `:active` 描边）：
      按 §1 第 5 条「死代码删除，不保留『以后可能用』」处理。左上那颗的类名是 `.back-dock`
      （「一条胶囊的定位」）。
    - **没有 `--float`**：它只被 `.cap-circle` 用过，令牌本体、`main.css` 的注释、§1 第 2 条与 §3.1

      撤销条 / toast 不会压到那颗胶囊上。
    - 验证：左上那颗与底栏、右上总览条**同高同形**（都是胶囊，内含 46 圆钮），悬停时底色变化一致；
      横屏显示「收起」、收起后显示「展开」，竖屏显示「乐谱库」；把窗口缩到很窄，撤销条与 toast
      仍从那颗胶囊下面出来、不重叠。

    - 验证：打开一张谱 → 右侧总览条里只有一页页纸和中间一个蓝框，播放时不会出现蓝色横带；

### 18.28 横竖屏只有一套开关 + 侧栏「拖到底关闭」（**只针对「侧栏」，悬浮侧栏另一套**）
> **术语**（见 [`UI-COMPONENTS.md`](./UI-COMPONENTS.md) 的术语表）：左边装乐谱库的那条叫**侧栏**，
> 右边浮着的谱面总览（`Minimap`）叫**悬浮侧栏**。两者行为不同，写文档 / 注释必须分开叫。
> 本节讲的是**侧栏**；「悬浮侧栏」是另一套（三钮胶囊、收起 / 展开态、把手）。
>
> ⚠️ **本节以下直到 §18.30 讲的是「拖到最窄松手即关闭」那一版侧栏；侧栏现行规则是
> 「收起 / 展开」两态** —— 见 §18.31 第 98 条。

84. **横竖屏共用一个开关**：**只有一个 `libraryOpen`**：宽屏它决定侧栏开不开，窄屏它决定抽屉开不开，
    **同一个状态的两种长相**；`isLandscape` 只由 `syncOrientation` 写，切模式时**不碰任何开关**。
    ⚠️ **绝不能一个开关管侧栏、另一个管抽屉**：两个状态必然分叉（「侧栏里明明开着乐谱库，拖窄窗口乐谱库就没了」）。
    - 派生量全部从这两个值算出来：`sheetHost = libraryOpen && !isLandscape`（窄屏抽屉才是浮层宿主）、
      模板里的 `v-if="isLandscape && libraryOpen"`。
    - 打开 / 关闭只有一对函数 `openLibrary()` / `closeLibrary()`，**调用方一律不判横竖屏**
      （`onCircle` 与 `openGallery` 都直接调 `openLibrary()`）。
    - 验证：
      1. 宽屏打开乐谱库 → 拖窄到 620px 以下 → 抽屉**自动是开着的**（状态跟着过来）；再拖宽 → 侧栏也是开着的。
      2. 宽屏关掉乐谱库 → 拖窄 → 抽屉**仍是关着的**；再拖宽 → 侧栏仍是关着的。
      3. 窄屏打开抽屉 → 拖宽 → 侧栏**自动是开着的**；再拖窄 → 抽屉仍是开着的。
      4. 反复拖来拖去，乐谱库的开 / 关**始终跟着上一次的操作**，不会自己冒出来或消失。
85. **侧栏最小宽度 280px**：`SIDE_MIN` = **280**（内容自然宽）、`SIDE_DEFAULT` = 300。
    老版本存过 150~279 与 0（= 用默认宽度），载入时统一补成默认宽度，
    否则一打开就是被夹到最窄的样子。
    - `MINIMAP_MIN` / `MINIMAP_DEFAULT`（悬浮侧栏）是另一套，仍是 56 / 96。
86. **侧栏「拖到最窄松手即关闭」**（现行版是「收起 / 展开」，见 §18.31 第 98 条）：
    - **关掉 = `v-if` 卸载**整个宿主。没有 `collapsed` 类、没有宽度归零动画，
      也没有「收起后把手贴屏幕左边缘再拉出来」那套手势。
    - **把手只管调宽**：往左拖进 `SIDE_MIN` 以内不会立刻收起，而是弹出侧栏自己的红色提示
      （见第 88 条），**真正关闭在 `pointerup`** —— 拖过头还能拖回来反悔。
      `pointercancel`（系统打断手势）只撤销提示、**绝不关闭**；只点一下没拖动也不关闭。
    - 关掉前先 `closePanel()`：面板槽跟着宿主一起从 DOM 消失，不关的话面板会「掉出来」变成独立浮层。
    - **打开侧栏只有一条路**：左上那颗胶囊。
      ⚠️ `common.collapse` / `common.expand` 与 `minimap.expandAria` **必须保留** ——
      悬浮侧栏的收起 / 展开按钮还在用它们。
87. **「一个宿主、两种长相」要落到同一个元素上**：
    宿主是**同一个** `<aside class="lib-host">`，宽屏加 `as-side`、窄屏加 `as-sheet`，
    **横竖屏只换这个类**。DOM 结构、`LibraryPanel`、面板槽 `#lib-slot` 全程是同一份，
    换朝向时连面板的 Teleport 目标都没变 → **面板连 DOM 都没动过**，自然不会被关掉；
    列表的搜索 / 排序 / 多选也一并留住了。
    ⚠️ **宽屏一个 `<aside>` + 窄屏一个 `AppSheet` 抽屉、各挂一份 `LibraryPanel` 是不行的**：
    换朝向时窄屏那一份被 `v-if` 卸载、宽屏那份重建，**LibraryPanel 内部的状态全丢**
    （横屏打开「设置」、拖成竖屏，设置就被关掉了）。
    - `ui.js` 的 `layout.sideMode` / `sheetHost` 合成一个 **`layout.host`**（`setHost`）：
      面板只认「乐谱库开着没有」，**不关心横竖屏**。`AppSheet.hostId` 因此是一行
      `layout.host ? 'lib-slot' : ''`；**没有** `hideHeader` / `flush` 两个 prop。
    - **不能「有面板就把乐谱库拉出来」**（那会让两种模式行为不一致）。
      需要列表的面板自己先 `openLibrary()` —— `requestScoreInfo()` 就是这么做的
      （先开乐谱库、`await nextTick()` 等它挂载，再发 `infoRequest`，否则 watch 收不到）。
    - **头部（标题 + 关闭 ×）横竖屏都有**，由宿主义务渲染（`v-if="!layout.panel"` 给面板让位）。
      否则横屏的乐谱库就没有关闭按钮（只有窄屏的 `AppSheet` 抽屉带头部）。
    - **左上那颗「乐谱库」胶囊在乐谱库开着时整颗隐藏**（`v-if="!libraryOpen"`）：
      关闭入口就是宿主头部的 ×，留着那颗是重复入口。
    - 验证：
      1. 宽屏打开乐谱库 → 打开「设置」→ 拖窄成抽屉 → **「设置」还开着**（内容、滚动位置都在）；再拖宽回来也一样。
      2. 宽屏的乐谱库**头部有 ×**，点它能关掉；关掉后左上那颗「乐谱库」胶囊才出现。
      3. 乐谱库开着时左上**没有**那颗胶囊；关掉后出现，点它乐谱库回来。
      4. 窄屏抽屉：点遮罩、点头部 × 都能关；宽屏：拖到 280 以内松手能关。
      5. 两种长相下头部、列表、贴底的导入按钮位置一致，只是**摆的地方**不同。
88. **关闭提示只罩侧栏，不罩整个窗口**：`.close-veil` 是容器内的 `position: absolute; inset: 0`（不是 `fixed`），
    `background` 用 `color-mix(in srgb, var(--danger) 38%, transparent)` —— **危险色给遮罩本身**
    （它就是「要关掉了」这件事），**文字用 `--text-strong` 而不是危险色**（红底配红字看不清）。
    浓度按越过 `SIDE_MIN` 的深度从 0.55 涨到 1，`pointer-events: none`（别截断正在进行的拖动）。

### 18.29 侧栏容器是「一个栈」

89. **`layout.stack` 是侧栏容器的唯一状态**（底 → 顶）：空栈 = 容器关着，
    栈顶 = 容器显示谁。`LIBRARY = 'library'` 是栈里**一个普通成员**，
    和 `settings` / `info` / `rate` / `audio` / `goto` / `segment` 完全平级。
    ⚠️ **宿主不能就是乐谱库**（`layout.host = libraryOpen`、面板槽在乐谱库的 DOM 里面）：
    那样面板是「乐谱库里的东西」，主从关系还在，而且面板**没资格**把侧栏叫出来
    （侧栏关着时点倍速只能从底部另弹一个浮层）。
    - 派生量全部算出来、不另外存：`topKey`（栈顶）、`hostOpen`（栈非空 = 容器可见 = 可托管）、
      `libraryShown`（栈顶是不是 `LIBRARY`）。
    - **只有一条规则：× = 出栈**（`popPanel`）。弹空了容器自己就没了 —— 「退回上一层」不需要特判。
    - **面板开着 = 它在栈上**：`AppSheet` 在 `open` 为真时 `pushPanel`、为假时 `popPanel`。
      这一步**顺带就把容器叫出来了**，所以底栏「倍速」也能把侧栏叫出来；
      **没有** `requestHost` / `claimPanel` / `releasePanel` 那套绕法。
      `followLayout` 的面板因此**永远是托管的**，独立浮层只留给 `center` 确认弹窗（不进栈）。
    - `clearStack()`（关掉整个容器）**要先挨个调面板的 close 再清栈** —— 面板的 `open` 还是 true 的话，
      宿主一没它们就「掉出来」变成独立浮层。为此 `AppSheet` 开着时 `registerPanel` 登记自己的 close。
      `toLibrary()` = 关掉栈里所有面板、只留乐谱库（导入完成后走它）。
    - 命名**去「乐谱库」化**（既然它不再是容器）：`.lib-host/.lib-clip/.lib-panel/.lib-head/.lib-body/.lib-slot`
      → **`.side-shell/.side-clip/.side-frame/.side-head/.side-body/.side-slot`**，`#lib-slot` → `#side-slot`。
      容器是 `<aside class="side-shell">`，横竖屏只换 `as-side` / `as-sheet`。
    - 验证：
      1. 侧栏关着 → 点底栏「倍速」→ 侧栏出现并显示倍速；点它的 × → **侧栏一起消失**，回到看谱。
      2. 开着乐谱库 → 点「设置」→ 点设置的 × → **回到乐谱库**（侧栏不消失）。
      3. 乐谱库的 × → 整个容器关掉，左上胶囊出现。
      4. 宽屏拖到 280 以内松手 → 等价于点乐谱库的 ×（清空栈）。
      5. 上面任意状态下拖窗口改比例 → 只换长相，**栈不动**、面板内容不丢。
      6. 左上那颗「乐谱库」胶囊在容器开着时（哪怕是某个面板占着）**都不显示**。
      7. ⚠️ **不要加层级角标**（`stackDepth` / `.stack-badge`，栈深 > 1 时在头部左上角显示层数）——
         试过，被否掉了。

> **不要加层级角标**（`stackDepth` / `.stack-badge`，栈深 > 1 时在头部左上角显示层数）——
> 代码与样式里都没有它，别再把它加回来。

### 18.30 「整页」把顶部工具栏也算进去 + 四条浮动边距收成一份令牌

90. **「整页」的页高必须把顶部两条胶囊也算进去**：
    `PdfViewer.pageScale()` 只算 `可视高 − reserved`（`reserved` = `.bottom` 底栏胶囊那一段 + 安全区）的话，
    谱面上方还浮着**左上那颗「乐谱库」胶囊**与**右上总览那条三钮胶囊**（都是 `top: var(--glass-inset-t)`、
    高 `--cap-h` ≈ 58）—— 它们盖住的正是页面的最上沿，「整页」模式下页顶的谱号/标题会被遮掉一条。
    - 所以要有一个 `reservedTop`（顶部工具栏的真实底边，`document.querySelector('.back-dock').getBoundingClientRect().bottom`），
      **三处算式一起减掉它**：`pageScale()`（整页的页高）、`measure()` 的上下 padding、`scrollToMeasure()` 里整页的落点。
    - 落点：**统一把这一页完整摆进「两条工具栏之间」那一段并居中**；放不下时页顶仍停在 toolbar 下沿（`Math.max(0, …)` 兜底）。
      末行那一套（露出下一页第一行）保留，只是「可视高」换成 `clientHeight − reserved − reservedTop`。
    - 顶部两条胶囊的高度是**会变**的（工具栏小字开关、进出编辑模式），所以除了原本的 `scroller` / `pages`
      之外，另用一个 `ResizeObserver` 直接盯住 `.back-dock` / `.mini-dock` / `.bottom` 三个元素本身 ——
      它们一变就重新 `measure()`（窗口没 resize，光靠 window 事件抓不到）。
    - **四条浮动边距只有一份令牌**：`main.css` 的 `--glass-inset-t/b/l/r`（= `safe-* + 8/8/12/12`）与
      供 JS 读取的裸数值 `--glass-gap-t/b/l`；`PlayerView` 的 `.bottom` / `.back-dock`、`Minimap` 的 `.mini-dock`
      都读它们。**别在四处各写一遍 8 / 12**（改边距就得四处找）。
    - 验证：
      1. 「整页」模式下**页顶不被左上/右上两条胶囊遮住**，一页完整地待在两条工具栏之间；
      2. 切到「居中」显示方式再切回来、以及切显示方式 → 页面落点都在同一条线上，不跳；
      3. 设置里关掉「工具栏显示文字」（胶囊变矮）→ 不加刷新，整页的页高跟着变大一点；
      4. 拖窗口高度、切横竖屏 → 底栏与顶部胶囊的边距保持 8 / 12（数值不变，只是换来源）。

91. **第一页 / 最后一页也要能居中 —— 用内容外面的空白把边界撑开**：
    「始终居中」**上下各垫了半个可视高的空白**；而 `scrollTop` 是被夹在 `[0, maxScroll]` 里的 ——
    「把第一页往下挪到居中」「把最后一页往上挪到居中」**只能靠内容外面的空白撑出来**，算式再准也够不着。
    - 所以「整页」也在 `paddings()` 里垫空白：`span = 可视高 − 底栏 − 顶栏` 是两条工具栏之间那一段，
      页面本身的显示高 `pageDisplayHeight()` 由 `pageScale` 按 `span − 2×PAGE_PAD` 算出，
      剩下的 `slack = (span − 页高) / 2` **上下平分**垫出去。于是第一页能居中、最后一页也能居中，
      和「始终居中」是同一个道理。
    - **`paddings(h)` 是 padding 与落点算式的唯一来源**：`measure()` 把它写进 `element.style.paddingTop/Bottom`，
      `scrollToMeasure()` 也调它（**别再自己写一遍** `reservedTop` / `reserved`）。
      ⚠️ 两边各写一份、并且差一个 `PAGE_PAD`（padding 是 `reservedTop + 10`、算式只用 `reservedTop`）的话，
      第一页永远偏低 10px。
    - `GAP_TOP` 提成 `PAGE_PAD = 10`，`pageScale()` 与 `pageDisplayHeight()` 共用，不各写一个 10。
    - `scrollToMeasure()` 的整页分支**合并成一条基线** `base = pageTop − padTop`：
      第一行与中间行都走它（空白已在 padding 里平分过，所以直接就是居中位）；
      「本页最后一行」那一支仍在 `base` 上叠加「露出下一页第一行」，并补上底部富余的一半，
      于是它和居中基准在同一条线上。
    - 验证（**重点看边界**）：
      1. 打开**只有一页**的谱 → 这一页完整地居中在两条工具栏之间，上下都不贴边；
      2. 多页谱滚到**第一页** / 点总览「定位」回到开头 → 第一页同样居中，不会缩到顶栏底下；
      3. 翻到**最后一页**（尤其是全文最后一行）→ 这一页也能停在居中位，不会贴在底栏上；
      4. 第一页 / 中间页 / 最后一页**页顶落在同一个高度**（同一个 `span` 下）；
      5. 关掉「工具栏显示文字」「缩放窗口高度」之后仍然如此（`span` 变了，空白会重算）。

### 18.31 拆成「侧栏 + 抽屉」两套逻辑（含进出场平移与两根把手）

92. **「侧栏」和「抽屉」是两套逻辑，不共用一个容器**：
    - **侧栏 = 乐谱库**（`layout.library`）：**横竖屏都是左边那一条**（宽度 `settings.sideWidth`，最多 94vw），
      `<Transition name="bar-io">` 管开 / 关 —— 从左缘滑入、关掉滑回左边、**演完才卸载**
      （所以列表的搜索 / 排序 / 多选状态一直都在）。
    - **抽屉 = 面板**（`layout.panel`，**一次只有一个**）：**横竖屏都是从下往上弹的底部抽屉**，
      装在做页面里的 `#sheet-slot` 里。**互斥**：`openDrawer()` 会替上一个面板把 `open` 置 false，
      于是旧的一边往下落一边压暗（`.drawer-leave-active::after` 那层 `--scrim`），新的升上来。
    - `store/ui.js` 里**没有栈**：只有 `library` 与 `panel` 两个字段，外加
      `openLibrary/closeLibrary/toLibrary/openDrawer/closeDrawer/closeCurrentDrawer/resetLayout`。
      `AppSheet` 里「`hostId` 认槽位、`current` 认轮到我」两个判断，**别合并**。
    - **`AppSheet` 的 `Teleport` 必须带 `defer`**：`#sheet-slot` 和面板是
      **同一次渲染里一起挂的**，而 Vue 是「先建完整棵子树、最后才把根元素 insert 进 document」——
      挂载那一刻 `querySelector('#sheet-slot')` **必然找不到**，Teleport 只在挂载时解析目标，
      找不到就**整块内容永远不挂**（之后 `open` 变 true 也没有槽可进，更新还会 patch 到 `null`
      容器上抛错）。表现就是「点设置 / 信息 / 标签 / 跳转 / 段落 / 反复**没反应**」；
      **有谱之后才挂载的「音频」「倍速」不受影响**（它们在 `v-if="hasScore"` 的底栏里）——
      所以这个坑**只在冷启动时露出来**，HMR 之后一切正常，别被它骗过去。
    - 侧栏与抽屉**互不影响**（乐谱库开着也能弹抽屉）；唯一例外是 `toLibrary()`：导入完成那几处会把抽屉关掉。
93. **横竖屏唯一的差别就在抽屉那个盒子上**（`PlayerView` 的 `slotStyle()`，全部以 CSS 变量递给槽，
    组件自己不知道朝向）：
    - **横屏**：贴左边、宽度与侧栏一致（**侧栏关着就用 `SIDE_MIN`**），跟侧栏同占那一列；
    - **竖屏**：整幅宽、`≤620` 居中（就是常见的底部抽屉）；
    - **高度固定 `85dvh`，不给拖** —— 抽屉上**没有把手**，`settings.sheetHeight` / `SHEET_MIN` / `SHEET_MAX`
      与「拖抽屉高度」那两个文案键都不存在（高度固定 85%）。
94. **抽屉是模态的：外面那层横竖屏都有，点一下就关**（`closeCurrentDrawer()`，走面板登记的 close）。
    - 横屏的抽屉只占左边那一列，所以遮罩**不是平铺的 `--scrim`，而是从左到右的渐变**
      （`.sheet-scrim.fade-x` = `linear-gradient(90deg, var(--scrim), transparent 68%)`：左深右浅、
      往谱面上渐隐），免得把整幅谱面一起抹暗；
    - 竖屏是整幅宽的抽屉，用常规平遮罩；出现 / 消失都走 `scrim-io` 的透明度过渡。
95. **只剩一根把手**：侧栏右边缘（拖宽、夹在 `SIDE_MAX`）。越界提示：拖进 `SIDE_MIN` 以内 →
    **侧栏自己那一块**罩危险色（`.close-veil` 在 `.side-bar` 里，不是整窗）→ **松手才关**；
    只点一下不关、`pointercancel` 不关。时长统一走 `--side-io`（260ms）。
96. 验证（**八条**）：
    1. 横屏点「乐谱库」→ 侧栏从**左缘滑入**；点 × → 滑出去再消失（不是原地消失）。
    2. 竖屏点左上胶囊 → 侧栏同样从左缘滑入（**不再是底部抽屉**）。
    3. 乐谱库开着点「设置」→ 抽屉**从下往上弹、占窗口高 85%**：横屏贴左边、与侧栏同宽；竖屏整幅宽居中。
    4. 抽屉开着再点底栏「倍速」→ **旧的落下去（暗的）、新的升上来**，任何时刻只有一个抽屉。
    5. **横竖屏都点抽屉外面 → 抽屉关掉**：横屏那层是左深右浅的渐变，竖屏是平遮罩。
    6. 拖侧栏右边缘：越界罩红色遮罩、松手才关；**抽屉上没有把手**（高度拖不动）。
    7. 换朝向（拖窗口比例）→ 侧栏与抽屉都不闪、不重挂，搜索词与面板里输入到一半的内容都还在。
    8. **冷启动也要能开**（F5 之后不碰任何别的东西，直接点）：设置 / 信息 / 标签 / 跳转 / 段落 / 反复
       都得弹得出来 —— 允许 HMR 之后能开、冷启动打不开是**不行的**（原因见 92 的 `defer` 那条）。

97. **侧栏不是悬浮的**：它是 `.player` flex 行里的一个子项、**占谱面左边一块宽度**
    （`flex: none` + 右描边 + `padding-top: safe-t`）。
    ⚠️ **别再改回悬浮**（`position: absolute`、不占谱面宽度、贴屏幕左边、只圆右侧两个角、`--shadow-2`）——
    悬浮会盖住谱面左边一块，而乐谱库是要一边看谱一边翻的。

98. **侧栏是「收起 / 展开」两态（和右侧总览同一套），没有「关闭」这个概念**：
    它**常驻 DOM**，收起 = 内联 `width: 0` + `border-right-width: 0` + 过渡（`.collapsed`），
    内容由 `.side-clip`（`overflow: hidden`，内容按固定宽度排版）裁切，所以**列表的搜索词 / 排序 / 多选都留着**。
    - **头部没有 ×**（没有「关闭」就不该有关闭键）；左上那颗胶囊是**收起 / 展开切换钮**：
      收起时是 `grid` + 「乐谱库」，展开时是 `chevronLeft` + 「收起」（和右侧那颗切换钮同一套语义、方向相反），
      而且**一直显示**（收起之后才有点的地方）。
    - **把手照抄右侧那根的三件事**（`startResize`）：宽度 ≥ `SIDE_MIN` 时**跟手**调宽 / 比 `SIDE_MIN` 还窄时
      **不看宽度、只看拖动方向** / 收起状态下它自己贴到屏幕左边缘（`.side-bar.collapsed .side-resizer`），
      点一下（或往右拖）就用上次的宽度展开。
      **没有**「变红 → 松手才关」那一套（`sideClosing` / `sideOver` / `veilOpacity` / `.close-veil` /
      `view.side.closeHint` 都不存在）。
    - **方向模式的正确写法**（踩过坑，别再改回去）：
      - 两个方向都**只改状态、把跟手（`dragging`，总览那边连 `stretching`）关掉**，宽度交给同一段过渡演：
        往展开方向 → `expandLibrary()` 演回记住的宽度，往收拢方向 → `collapseLibrary()` 演到 0。
        **收起和展开必须是同一条动画**。
      - **绝不能「进了方向模式就锁死、不再回到跟手」**：那样从最小宽度拖出来就不跟手了。
        指针一旦回到最小宽度以上（`w >= MIN` 那个分支）就把跟手打开、按绝对位置 1:1 跟随。
      - 判向要留 3px 的基准（`anchorX`），否则手抖会让收起 / 展开来回翻。
      - 拖动里的「展开」走的是 store 的 `expandLibrary`（**只管侧栏**），别用页面上那个
        会顺手收掉抽屉的 `expandLibrary()`。
    - 语义上「关闭」只剩两处内部调用：打开乐谱（`openScore`）与 `resetLayout()`，都只是**收起**。
99. **谱面区有最小宽度了**（`--stage-min-w`，默认 320px）：窗口窄到「侧栏 + 320px」都放不下时，
    谱面**不再继续被压窄**，而是整行超宽、**被挤出浏览器窗口右侧**（`.player` 的 `overflow: hidden` 裁掉它）。
    侧栏是 `flex: none`，所以被挤出去的永远是右边那块。

100. **撤销 banner 的外形与 toast 完全一致**：两条共用全局 `.notice` 那一份外形
      （药丸圆角、`font-size: 14px`、`color: var(--text-soft)`、入场动画 `toast-in`；底 / 模糊 / 描边走 `.glass`）。
      ⚠️ **不能两边各写一套外形、靠注释提醒一起改**：必然走样（撤销条 14px 圆角 + 13.5 字，toast 药丸 + 14 字），
      那正是它们当初不一致的原因。
      - **模板里没有 `trash` 图标**。`src/assets/icons/trash.svg` **保留**（`EditorPanel.vue` 的删除钮还在用它）。
      - 文案是**居中**的：`.undo-text` 用 `flex: 1` + `text-align: center`
        （**不要写 `margin: 0 auto`**：flex 里的 auto 外边距会吃掉全部剩余空间，文字被推到右边贴着按钮）、
        另加 `min-width: 0`（省略号截断的前提）。`overflow: hidden` / `text-overflow: ellipsis` /
        `white-space: nowrap` 三条保留 —— 窄屏上长文案省略号截断，不会把上面的胶囊顶出去。
      - 那颗撤销按钮是 banner **唯一比 toast 多出来的东西**：`.undo-btn` 额外写 `border-radius: 999px`
        （`.btn` 默认是 `--radius-sm` 10，在这条药丸里显棱角），颜色仍是 `--accent` + `--accent-line`。
      - **两条同时出现不会重叠** —— 撤销条在 `--hint-top`、toast 在
        `--hint-top-2: calc(var(--hint-top) + var(--cap-h) + var(--hint-gap))`。
        ⚠️ **`--hint-top-2` 不能写死**：写死一个比 `--cap-h` 小的数，toast 就会压进撤销条里（58 > 52）。
      - **删除操作本身不弹 toast** —— `store/player.js` 的四处删除只调 `notifyUndo()`；
        toast 只在**撤销之后**才报（`store.undone` / `undoDeletions`），那时 banner 已经清掉了。

101. **撤销条的倒计时是环形**：20×20 的 SVG（`.undo-ring`）包两个 `<circle r=9>`，占原本垃圾桶图标的位置。
      - `.undo-ring-bg` = **实线轨道**（`--stroke-strong`）；
      - `.undo-ring-fg` = **主题色弧线**，整圈从 12 点方向转起（`transform: rotate(-90deg)`）；
      - **`:key="player.undoToast.tick"` 必须留着**：连删时靠它重建节点让动画重新跑，
        不重建的话第二次删除**倒计时不会重置**。20px 的纯装饰圆环，不是控件，
        所以不受「可点尺寸两档」约束。
      - **两条都钉在 `--cap-h`(58)**，和底栏 / 左上 / 总览那几条胶囊**同一个高度**。
        为什么不是 46：banner 里那颗撤销按钮是 46（`.btn.sm` = `--tap-min`，触屏规范不许再小），
        **46 的按钮塞不进 46 的盒子** —— 58 是它的固有高度（46 + 上下各 5 + 2 描边）。
        所以 `.notice` 的上下内边距是 **5（`--cap-pad`）而不是 10**：让内容盒正好 46、按钮刚好填满。
        （写 10 的话 banner 会被按钮撑到 68。）
      - **最小长度 = `--tap × 2`（92）**，和 `.chip.tap` 同一条算式：内容短的提示
        不至于缩成一颗小球。**banner 与 toast 都给**（两条永远一样长）。
      - `.undo-banner` 带 **`width: fit-content`**：`.undo-stack` 是 `flex-direction: column`
        的拉伸容器，显式写出来 = 按内容宽度收缩，免得哪天动了 stack 的对齐就把这条拉满。
      - **`.notice` 必须有 `display: flex` + `align-items: center` + `justify-content: center`**：
        ⚠️ **只有 padding 和 `min-height` 不等于垂直居中**（文字会贴着上沿）。
        `.toast` 另带 `max-width: 100%`：flex 化之后文字是匿名 flex 项，
        长提示不给上限会顶破 `.toast-wrap` 的 460px 横着溢出。

102. **环形倒计时由脚本驱动**（`PlayerView` 的 `startRing()` 用 `setInterval`，`RING_FPS` = 15）
     直接算**剩余弧长**、挂到 `stroke-dasharray` 属性上：
     - 值 = `RING_C - Math.min(k * RING_C, RING_C - RING_MIN)`；`RING_C` = 2πr = 56.55、
       `RING_MIN` = 2.5；
     - **`RING_MIN` 是下限保护**：走到头也留一小段弧，所以「空圈」**不可能出现**；
     - ⚠️ **别写成 `Math.max`**：`Math.max(k * RING_C, RING_MIN)` 会把末帧算成 **0**，空圈就回来了；
     - 可复现：进度 0 / .25 / .5 / .75 / 1 → 弧长 56.55 / 42.41 / 28.28 / 14.14 / **2.5**。
     - **`.undo-ring-fg` 里不许出现 `stroke-dasharray` 或 `animation`**：CSS 规则会盖掉
       SVG 属性上的值，两者都写就又回到空圈。`.undo-ring-bg`（`--stroke-strong` 实线轨道）不变。
     - ⚠️ **别在 `.undo-ring` 上挂「走完淡到 0.2」那类透明度动画**：两个圆是「轨道 + 弧线」叠出来的，
       掉透明度会让整圈一起变淡；弧线空掉**本身就是 0**，轨道照样把倒计时那个位置显示出来。
     - 验证（浅深两色都看）：开头**满圈蓝弧**、中段**半圈**、归零时是**一小段可见蓝弧**
       （约 4% 圈）而不是空圈；`stroke-dasharray` 落在 DOM 属性上（`"56.55 56.55" → "28.275 56.55" → "2.5 56.55"`）。
     - 人工复核（只能靠人）：删一个段落 → 环从满圈顺时针走空、**任何时候都看得见蓝弧**；
       连删几下 → 每次都重新从满圈开始（`watch` 盯着 `id` / `tick` / `ms`）；
       触发一条 toast → 文字上下一样高、不贴顶。
       - 横向留白 **环左 17 / 按钮右 17、环→文字 10 / 文字→按钮 10**，两侧对称（对称是要求，不是记数）。
     - 人工复核（**这几条只能靠人看**）：删一个段落 → 左边一圈灰轨道 + 蓝色弧线从满圈开始走，
       6 秒走空后轨道还在、然后整条消失；连删几下计数照涨、弧线每次重置；
       触发一条 toast → 文字上下一样高、不贴顶。

### 18.32 循环框选是谱面灰底，没有循环提示条

103. **框选住的小节是谱面灰底、不描边；「循环播放 第 x–y 小节」那条提示条不存在**。
      - **`.m-sel` 是 `fill: var(--mark-muted-fill)` + `stroke: none`**。
        框选表达的是「这一段在循环」这个**播放状态**，不该跟编辑标记抢主题色；它和「当前小节」靠
        **谱面灰 / 主题色浅底**区分。
        所以 **§6 里没有「框选是谱面上唯一带描边的方框」这条**：谱面上三者都只有底色。
        `--mark-muted-*` 这一组**非编辑模式也有一个使用者**（§2 / §6 已同步）。
      - **圆角按「块」给，不按小节给**：框选不是一格格画直角矩形，而是把**同一行里 `indexInSystem`
        连续的小节合并成一块**——块内相邻小节之间不会出现两个背靠背的小凹口（那读起来像「一节一格」，
        而框选表达的是「一整段」）。块的四角同用 `ACTIVE_RADIUS` **3pt**（与当前小节同一档，§3.2）；
        **跨行时行首 / 行尾保持直角**（右端没连到行尾的块左端直角、左端没接行首的块右端直角），
        所以一段连续循环读起来是一条上下贯通的带子，而不是每行一个孤立的圆角盒。
        相邻行天然共用同一条 `x0` / `x1`，块的侧边本来就齐平。
      - **块之间不合并**：小节号不连续（中间隔着别的行 / 别的页）就是两块 —— 相邻两小节是同一行
        且 `x1` 对上下一格的 `x0` 才算连着，别按小节号连续就并起来。
      - **代价（写清楚，别再当 bug 报）**：编辑模式下只要当前工具不是「行」，行底本身就是同一档灰
        （`.muted .sys-fill`），**框选那几格会和行底糊在一起**。非编辑模式下没有行底，灰底是干净的。
      - `PlayerView` **没有** `.sel-bar`（图标 + 「循环播放 第 1–10 小节」+ 取消钮）、没有 `selectionLabel`、
        没有 `view.loop.*` 三个文案键；**循环本身照旧工作**，只是没有文字提示。
        `src/assets/icons/select.svg` 保留备用（`UI-COMPONENTS.md` 的图标表已标注）。
      - **取消循环只有这三条路**（都还在，别再删）：`PdfViewer.onMeasureTap`「有框选时点任一小节 =
        只取消、不跳转」、`@blank-tap`「点谱面空白」、`PlayerView.onKey` 的 **Esc**
        —— 前两条只在**非编辑模式**有效（编辑模式点谱面是编辑操作），那时用 Esc。
        **没有可见的取消入口**，这是明确接受的取舍。
      - 验证：
        1. 非编辑模式在谱面上拖出一个框选 → 那几小节是**一层灰底、没有蓝框**，同时开始循环播放；
        2. 松手后右下角**没有**任何胶囊条，底栏位置不跳；
        3. 点框选里的任一小节 / 点谱面空白 → 灰底消失、循环停下，且**都不会跳转**；编辑模式下按 Esc 同样取消；
        4. 进编辑模式 → 灰底照旧画着；切到「小节线 / 段落 / 反复」工具时会与行底同色（预期，见上）；
        5. 深浅两色下都看一眼：灰底要**看得见、但不盖住谱子**；

           只有这一块自己的四个外角是圆的；

           左右两侧跟着段首 / 段尾走，两行的侧边**对齐、不突出**。

104. **`.undo-btn` 的常态 / 悬停 / 按下三态都没有底色**：
     - `.btn` 默认铺 `--surface-control`，在这条玻璃药丸里是一块突兀的灰底，所以它
       `background: transparent`，读起来就是「药丸里的一行主题色文字」。
     - **悬停只加下划线**（这是全仓唯一一处不铺 `--surface-hover` 的悬停；§10 那条「悬停铺一档中性面」
       对它让位）：常驻 `text-decoration: underline transparent` +
       `text-underline-offset: 3px`（14px 字下划线和字形黏在一起）+ `text-decoration-thickness: 1.5px`，
       悬停时只把 `text-decoration-color` 从 `transparent` 放到 `currentColor`。
       **`transition` 只写 `text-decoration-color`** —— `text-decoration-line` 不可动画，
       从 `none` 切到 `underline` 是硬切；这就是用「常驻下划线 + 透明色」而不是悬停才加 `underline` 的原因。
       下划线作用在行盒上，**不改变自身盒尺寸**，满足「悬停不改尺寸与布局」。
     - **按下只把字加深一档**：`.undo-btn:active { background: transparent; color: var(--accent-deep) }` ——

       只是这一颗把重量从底色挪到了文字上，是全仓唯一的写法（§5 / §10 各记一条例外）。

       `dist/assets/index-*.css` 里 `main.css` 排在**所有** `[data-v-…]` 组件样式**之后**。
       所以悬停 / 按下这两个状态**各自都得再写一条** `background: transparent`；
       带上伪类后它们是 **0,3,0**，比全局那两条高一档，**dev / build 两条路上都稳赢，跟注入顺序无关**。
       不写就只有常态那条去顶，而它是同分 0,2,0、又排在 `main.css` 前面，`--surface-active` 那块灰底会照铺。
     - **`--accent-deep`**（`main.css` accent 族，深 `#4185d9` / 浅 `#1a5ec8`，约等于 `--accent` 调深 15%）：
       不复用现成令牌的原因：`--accent-strong` 是**填充控件**的悬停色，
       深色下（`#7ab7ff`）比 `--accent` 还**亮**，方向正好相反；`--accent-mid` 是半透明**底色**，
       当文字色压在玻璃药丸上会糊成一片。
     - 颜色不做过渡：按下 / 松开都是硬切，反馈更干脆。
     - ⚠️ `.undo-btn` 上写 `border-color: var(--accent-line)` **单独是没用的** ——

     - 验证：删一个段落（同时让 toast 冒出来，例如删完再点撤销）→ 顶部两条**上下分开、中间留一条缝**，

106. **环形倒计时由脚本驱动，不用 CSS 动画**。
     - ⚠️ **CSS 动画那条路不能走**：它要「动画名 + 关键帧 + 内联 `animationDuration`
       + `fill-mode`」四件事同时对上，任何一环出问题都是同一个症状（**只有一个灰色空圈**），
       而且**没法自证是哪一环坏的**（同一份代码会给出互相矛盾的读数）。
       走完停在「一点不剩」的那版只对「刚好在那 6 秒里看」的人成立。
     - 现在由 `PlayerView` 的 `startRing()` 用 `setInterval`（`RING_FPS` = 15）直接算
       **剩余弧长**、挂到 `stroke-dasharray` 属性上：
       - 值 = `RING_C - Math.min(k * RING_C, RING_C - RING_MIN)`；`RING_C` = 2πr = 56.55、
         `RING_MIN` = 2.5；
       - **`RING_MIN` 是下限保护**：走到头也留一小段弧，所以「空圈」**不可能出现**；
       - 可复现：进度 0 / .25 / .5 / .75 / 1 → 弧长 56.55 / 42.41 / 28.28 / 14.14 / **2.5**。
     - ⚠️ **别写成 `RING_C - Math.max(k * RING_C, RING_MIN)`**：`Math.max` 把末帧算成 **0**，空圈就回来了。
     - `.undo-ring-fg` 里**不许出现 `stroke-dasharray` 或 `animation`**：CSS 规则会盖掉
       SVG 属性上的值，两者都写就又回到空圈。`.undo-ring-bg`（`--stroke-strong` 实线轨道）不变。
     - 验证（浅深两色都看）：开头**满圈蓝弧**、中段**半圈**、归零时是**一小段可见蓝弧**
       （约 4% 圈）而不是空圈；`stroke-dasharray` 确实落在 DOM 属性上
       （`"56.55 56.55" → "28.275 56.55" → "2.5 56.55"`）。
     - 人工复核（只能靠人）：删一个段落 → 环从满圈顺时针走空、**任何时候都看得见蓝弧**；
       连删几下 → 每次都重新从满圈开始（`watch` 盯着 `id` / `tick` / `ms`）。

### 18.33 全站禁用文字选择

107. **界面上的文字一律不许选中**。触屏上划行 / 拖滑杆 / 拉把手时扫过文字尤其容易误选。
      - **只有一处实现**（`main.css`）：

        ```css
        html { user-select: none; -webkit-user-select: none; -webkit-touch-callout: none }
        ```

        `user-select` 的生效值沿 DOM 往下传（子元素自己不写就是不可选），写在 `html` 上一条就覆盖全站；
        ⚠️ **不要在 `button` 里、`ScorePage` / `AudioOffsetPicker` / 两个 `.dragging` 里再各写一份**
        （留着就是第二套实现）。
      - **唯一例外：`input` / `textarea` 保持可选中**（`user-select: text` + `-webkit-touch-callout: default`）
        —— 改乐谱标题 / 加标签 / 改段落名时，框里要能选字、双击选词、局部替换；全禁掉就只能整段重打。
        `NumberPad` 那个只当显示用的框也落在这个例外里，它本来就不接收原生编辑（§18.22），不受影响。
      - **代价（写清楚，别再当 bug 报）**：`-webkit-touch-callout: none` 是全局的，iOS 上长按乐谱库封面图
        **不再弹「存储图像」**；封面可以在「乐谱信息」里重新生成或换图。
      - **已知边界**：CSS 只挡「用指针选不中」；`Ctrl+A` / `Ctrl+C` 是浏览器的文档级快捷键，
        它拦不住。要连复制一起挡得加 JS 的 `selectstart` / `copy` 监听 —— **目前没做**（按「不预留用不上的 API」处理）。
      - 验证：
        1. 桌面：在乐谱库标题、标签胶囊、面板说明文字、信息面板的「页数 / 时长」那几行上按住拖动、
           双击、三击 → **一个蓝底都不出现**；
        2. 桌面：搜索框、乐谱标题输入框、标签输入框、段落名输入框里拖动 / 双击 → **照旧能选中**，
           `Ctrl+A` 后打字能整段替换；
        3. 触屏 / iOS：长按任意界面文字 → 不出选择手柄、不弹系统菜单；长按封面图 → 也没有「存储图像」（见代价那条）；
        4. 拖侧栏右边缘 / 总览左边缘把宽度拉到最窄再拖回来 → 全程没有文字被选中；
        5. 谱面（划行 / 框选）与音频频谱的拖动表现**不变** —— 这两处本来就是禁的。

### 18.34 全项目不用右键

108. **卡片动作只有一个入口：右侧那个 `.icon-btn.flat` 的「⋯」** ——
     `LibraryPanel` 卡片上**没有** `@contextmenu` 处理器。
     规则本身写在 §9（触屏优先那节），因为它是**通用约定**，不是乐谱库一处的实现细节。

     - `openMenu(rec, x, y)` 的 `x` / `y` 表示「贴住触发点」，**不等于「指针位置」**。

### 18.35 播放时隐藏顶栏（上下平移，不是淡出）

110. **设置里的「播放时隐藏顶栏」开关**：`LibrarySettings` 的第五行，
     `settings.hideTopBar`（布尔，默认关，跟着其余偏好一起落 localStorage）。
     - **什么时候藏**：`player.playing && !player.editMode`，也就是「**走带中**」而不是「按过一次播放」——
       暂停 / 播完 / 预览试听停下都会自己回来。编辑模式下**不藏**（行 / 小节线 / 段落 / 反复四个工具就在
       那条胶囊里，藏了就编不了）。
     - **藏的是四条**：左上 `.back-dock`、右上 `.mini-dock`、乐谱库侧栏（`.side-bar` 走它本来就有的
       收起动画、`collapseLibrary()`）、顶部两条提示（`.undo-stack`，撤销条与 toast 都按 `--hint-top` 摆，
       把它整体挪到屏幕上方外面，`--hint-top` 等令牌不用动）。
       **底栏那对胶囊不动**：播放 / 停止还得按得到。
     - **动画一律是「上下平移出屏幕」**，不是淡出：
       顶上的三条 `translateY(-100% − 边距 − 8px)` 往上走、侧栏照旧往左收；
       时长统一 `--side-io`(260ms) + `--ease`，与侧栏 / 抽屉的进出场同一套。
       ⚠️ **偏移量必须比自身高度还多**：`.back-dock` / `.mini-dock` 是绝对定位在 `--glass-inset-t` 上的，
       只写 `-100%` 的话还会在屏幕顶上露出 `8 + safe-t` 那一条。
     - **`.side-bar` 必须显式写 `transform: translateX(-100%)`**（不能只让它走收起动画）：收起后它虽然
       宽度为 0，但 `top: -15px` 的把手与 `bottom: -15px` 的小竖条是画在裁切层**外面**的，
       不整块挪走就会在屏幕左边缘留下一段浮空的把手。
     - **顶栏藏起来时，谱面「可视区」仍然按顶栏在的时候算**（`PdfViewer` 的 `reservedTop` 不归零）：
       归零等于每次开关顶栏都按新的可视高重排整本谱 —— 字会跟着变大变小、滚动位置也会跳。
       藏起来只是**把这些控件从眼前挪开**。回来时 `barsObserver` 量到胶囊的新位置、`reservedTop`
       自动补回真实值（`translateY` 会改 `getBoundingClientRect().bottom`，所以这一路是自动的）。
     - ⚠️ **类名一律用 `.top-hidden`，绝不要写成 `.hidden`**：
       `PlayerView` 末尾有一个**给隐藏文件输入用的 scoped `.hidden { display: none }`**。
       Vue 的 scoped 编译规则是「只有首尾两截都带标记才保留」—— `.side-bar.hidden` 里 `.side-bar`
       是静态类、`.hidden` 来自 `:class` 绑定，于是被削成**裸 `.hidden`**，那条 `display: none`
       正好命中所有同名的顶栏元素：**直接消失、连过渡都看不见**（右上不中招只是因为它在
       `Minimap` 那个 scope 里）。换一个词就永远不会再撞 —— 全仓 `.hidden`
       只剩「隐藏文件输入」那一处使用。
     - 实现上**没有另一套机制**：`.back-dock` / `.mini-dock` 早就在 `PdfViewer` 的
       `barsObserver` 观察名单里，侧栏收起用的是 `collapseLibrary()`，提示条挪的是 `.undo-stack`。
     - 验证：
       1. 设置里打开「播放时隐藏顶栏」→ 按播放：左上「收起 / 设置」胶囊、右上总览胶囊、
          乐谱库侧栏、顶部的撤销条 / toast **一起平移出屏幕**（能看清是往上 / 往左走，不是淡出）；
          **四条的动画要一致** —— 只有「左上那颗瞬间消失、其它三条在滑」就是 `.hidden` 撞名复发；
       2. 暂停、播完、拖进度到末尾 → 四条**一起平移回来**，位置与播放前一致；
       3. 走带中谱面**不重排**：页的大小、上下留白跟播放前一模一样（只是顶栏让开了）；
       4. 走带中点进编辑模式 → 顶栏回来（工具要用）；退出编辑仍在播放 → 再藏回去；
       5. 关掉这个开关 → 播放时顶栏一直留在原地；
       6. 底栏那对胶囊（播放 / 跳转 / 倍速 / 音频）**全程都在**，播放中能正常暂停。

### 18.37 总览胶囊的「抓手 / 指针」：谱面手势可切换

109. **总览那条三钮胶囊的中间一颗是「抓手 / 指针」**。语义以下面这一张表为准。     - **状态**：`store/player.js` 的 `player.mode`（`'pan'` 抓手 **默认** / `'pointer'` 指针），
       配 `setMode(mode)` 与派生 computed `pointerMode`。它**不进 meta、不写 localStorage**，
       而且 `open()` 与 `close()` 都显式归位 `'pan'` —— 这就是「每次打开乐谱都默认是抓手」
       （刷新、换谱、重开都回到抓手）。
     - **完整语义（唯一权威表；实现全在 `ScorePage.vue` 头部的「手势策略」）**：

       | | 鼠标（**两种模式完全一样**） | 触屏 · 抓手 | 触屏 · 指针 |
       | --- | --- | --- | --- |
       | 非编辑 | 点 = 跳转 / 取消框选；拖 = 框选循环 | **滑 = 原生滚谱**；点 = 跳转（**拖不出框选**） | 按下即跟手，拖 = 框选；**不滚页** |
       | 行工具 | 点 = 删行；拖 = 划出这一行 | 滑 = 滚谱；点 = 删行（**拖不出行**） | 同上（按下跟手、松手落实） |
       | 小节线 / 段落 / 反复 | 点 = 标记 / 打开；拖 = 跟手预览、松手落实 | **点 = 标记**；**滑 = 滚谱** | 按下跟手、松手确认；不滚页 |

       一句话：**这个开关只对触屏有意义；抓手 = 这一层完全不接管拖动（滑动就是滚谱、只认点一下），
       指针 = 按下就归我们。触屏上要框选 / 划行 / 放线，就切到指针模式。**
     - **实现要点**：
       · 「这一笔归不归我们」只算一次 —— `own = e.pointerType !== 'touch' || props.pointerMode`
         （鼠标恒为真，触屏看模式），存进 `drag.own`；后面所有分支都只看它，**不再有第二个判据**。
       · `touch-action` 只有两档（`.no-gestures` = 抓手 → `auto`，否则 `none`）。
         ⚠️ 抓手那条 `auto` 会被 `html` 上一条**全站级**的 `touch-action: pan-x pan-y` 收窄
         （生效值沿祖先链取交集，见 §18.40）—— **双指缩放全站禁用，滚谱照旧**。
         ⚠️ **它只在 touchstart 那一刻定值、中途改无效** —— 所以「先让它滚、中途再抢回来」这类
         玩法在这个类上做不到，**别再往这个方向试**（见下面那条长按方案的警告）。
       · 不归我们的那一笔**只当点按处理**（`onPointerUp` 里那条 `!d.own` 分支：抬手前位移 ≤
         `TAP_SLOP` 才算点了一下，动过就什么都不补），其余整个交给浏览器；
         `onTouchMove` 也只在 `own` 时才 `preventDefault`，否则谱面就再也滚不动了。
       · `PdfViewer`：抓手模式下 `autoScrollAllowed()` 为假 → 跟随播放、切显示方式、进编辑模式
         这几处**自动滚动全停**（它们都走 `scrollToY`，而它会 `cancelAnimationFrame`，
         撞上用户自己正在跑的滚动就会打架）；**用户自己滚照旧**（滚轮 / 触控板 / 拖总览）。
         那几个 watch 里 `measure()` / `observeAll()` 照做 —— 页高与预留变了就必须重量。
     - ⚠️ **别给触屏抓手加「先长按 400ms 再拖」**：那种手势要靠「比浏览器早到点的计时器 + `preventDefault` 抢手势」
       才成立，而抓手模式下 `touch-action: auto`（原生滚动的代价），浏览器随时可能先滚起来并发
       `pointercancel` 抢走这一笔 —— **这是一场赢不了的竞速**（`HOLD_MS` = 400 抢在 Android 自己的
       ~500ms 长按前面、`navigator.vibrate(15)` + 整页大框 `.hold-frame` 做反馈，都救不回来）。
       **要加「长按」这类手势，先决定是否放弃原生滚动**（改成自己接管 `scrollTop`，像 `Minimap`
       的轨道那样），否则同样会输。
     - **`@contextmenu.prevent` 留着**（`ScorePage` 模板根节点）：它与长按手势无关，
       是挡 Android 的系统菜单（`-webkit-touch-callout: none` 只对 iOS 有效）——
       手指在谱面上停久一点也不该弹出「下载图片 / 全选」。对上 §9「全项目不用右键」
       （另有两处浮层也挡）。
     - **指针监听两种模式都挂**（模板上那六个 `@pointer*` / `@touchmove` 都无条件）：
       抓手模式虽然不接管拖动，但**要靠 `pointerup` 收「点一下」**，所以不能不挂。
     - **没有顺手关掉编辑模式**：切到抓手时**只**清框选 / 停循环（一条顺手的便利 ——
       抓手模式下点谱面照样能取消框选，不是非清不可），**不碰 `editMode` 与 `tool`**：
       那两样各有自己的入口（右上「编辑 / 完成」、四种标记工具），这颗钮隔着半个屏幕去改它们，
       就成了一个隐形的编辑模式开关。
     - **鼠标指针不变**：谱面**不加任何 cursor 声明**，全程是系统默认箭头 —— 两个模式说的是**手势归谁**，
       不是鼠标长什么样。⚠️ 模板上那个 `tool-*` 类名（`tool-play` / `tool-row` / `tool-barline` /
       `tool-segment` / `tool-repeat`）一直在绑，但**全仓没有对应的 CSS**，是个没落地的挂点：
       **保持原样**，别顺手补成 `grab` / `crosshair` 那几档。
     - **图标**：`src/assets/icons/hand.svg`（Lucide `hand`）与 `mouse-pointer.svg`
       （Lucide `mouse-pointer-2`）。图标同时表达当前模式（和「整页 / 居中」那颗一样），
       文字是「抓手 / 指针」，文案是 `minimap.gesturePan` / `gesturePointer` / `gestureAria`。
     - **没有的东西**（别再加回来）：「定位」那颗钮、`PdfViewer` 的 `onLocate()` 与
       `@locate` 监听、`minimap.locate` / `locateAria` 两条文案。
       要「回到当前播放的小节」在**指针模式**下点谱面上的小节即可（跳转本来就是这个手势）；
       `select.svg`（框选）与 `target.svg`（定位）两个图标文件**留在目录里备用**，
       不是「死文件」，别按 §15「没被引用的图标要删掉」把它们删了 —— 锚点 / 框选语义以后还会用到。
     - **已知取舍**：抓手模式下**没有「回到当前播放小节」的按钮**，也不跟随播放 ——
       谱面归用户自己滑，这正是「抓手」的定义。
     - 验证（**鼠标与触屏要分别过**；触屏请在真机或 DevTools 的触屏模拟下走，鼠标模拟不出来）：
       1. 打开任意乐谱 → 总览胶囊中间那颗是 **`hand` +「抓手」**；**鼠标指针始终是系统默认箭头**
          （谱面上不会变成手形 / 十字）；
       2. **鼠标（重点：两种模式必须没有区别）**：
          · 抓手模式下：点小节 → **照样跳转**；按住拖 → **照样框选并循环播放**，**谱面不会被拖着滚**；
          · 切到指针模式：以上两条逐字重复一遍，**行为完全一致**；
       3. **触屏 · 抓手**：手指在谱面上直接滑 → **谱面跟着滚**（原生惯性；双指缩放已在 §18.40 全站禁用，
         这里只滚不缩）；
          在谱面上怎么拖都**不会出框选、也不会划出行**（dragging 应该完全没反应，只剩滚页）；
          轻点小节 → 跳转；**长按不动 → 什么都不发生**（不震、不出现任何框，
          只是 Android 上不会弹系统菜单 —— 那是 `@contextmenu.prevent` 在挡）；
       4. **触屏 · 指针**：手指在谱面上拖 → **跟手出框选**（不是滚页）；轻点小节 → 跳转；
          无论怎么滑，**谱面都不滚**（要滚只能拖右侧总览）；
       5. 播放时在抓手模式下**谱面不再自动翻页**（跟随播放停）；切回指针模式播放 → 又跟着翻了；
       6. 点中间那颗 → 图标与文字换成 **`mousePointer` +「指针」**（**鼠标指针仍然不变**）；
       7. **切到抓手时正在循环** → 灰底框选立刻消失、循环停下；
       8. 切到指针、划出框选后**关掉乐谱再打开** → 回到抓手、没有框选；
       9. **编辑模式也按同一张表**（重点验证）：
          · 触屏 + 抓手 + 四种工具**都一样**：滑 = 滚谱；点 = 那一下的点按语义
            （行 = 删行、小节线 = 加 / 删线、段落 / 反复 = 添加 / 打开设置）；
            **抓手下在触屏上划不出行、也放不了线** —— 要拖就切指针；
          · 触屏 + 指针 +「小节线 / 段落 / 反复」：按下跟手（小节线跟随、段落 / 反复高亮候选线）、
            **松手才落实**，且**谱面不滚**；
          · 鼠标：以上在**两种模式下逐字一致**（拖 = 划行 / 放线，点 = 删 / 标记）；
       10. 抓手模式下点右上「整页 / 居中」切显示方式 → 页高与预留正常重排、**谱面不自己跳**；
           此时滚轮 / 触控板 / 拖右侧总览都还能滚（编辑模式下同样成立）。

### 18.38 抽屉的圆角按朝向分：横屏只圆右上角

111. **横屏的抽屉只圆右上角，竖屏是上边两个角**。
     - 横屏的抽屉**贴左边、与侧栏同占一列**（§18.31 第 93 条），它的上边和右边都是**贴着屏幕 / 侧栏那一列的实边**，
       不是「悬在纸上的卡片边」—— 所以「上边两个角」在横屏是自相矛盾的：
       左上角圆着，会和侧栏那条直边对不上；真正跟侧栏一致的是**右上角**那颗（它才是这一列的收口）。
     - **落地**：`PlayerView` 给 `#sheet-slot` 多挂一个 `.landscape`（判据就是 `syncOrientation()` 那一个，
       宽度 / 位置本来也读它），`AppSheet` 里一条 `.sheet-slot.landscape .drawer-box { border-radius: 0 var(--radius-lg) 0 0 }`。
       **竖屏那条 `.drawer-box` 一个字不动**（仍是 `--radius-lg --radius-lg 0 0`）。
     - ⚠️ **朝向必须从槽递进去**：抽屉是 Teleport 到 `#sheet-slot` 的，它的父链在页面上，
       而 `AppSheet` 的样式全是 scoped 的 —— 组件内写 `.landscape .drawer-box` 匹配不到。
       槽自己带 `.landscape`、被 Teleport 进去的根带本组件的数据属性，两段选择器正好接得上。
       也**别用 `border-top-left-radius` 单独覆盖**：那条声明排在 `.drawer-box` 的简写**前面**、同分比顺序，会被简写整个盖掉。
     - 验证：
       1. 横屏弹一个抽屉（设置 / 跳转 / 段落…）→ **只有右上角是圆的**，左上角是方角、与侧栏那条边连成一条直线；
       2. 拖窗口比例换成竖屏 → 同一个抽屉（不重挂）**上边两个角都变回圆角**，回横屏再变回只有右上角；
       3. 抽屉右边缘那根把手（只有横屏有）在右上角圆角处不悬空、拖动调宽照旧。

### 18.39 反复标记：两次点击成一对（§16.11）

反复工具那张卡只有「点一条小节线」这一个动作，**点完不弹任何面板**。一对反复 = **两次点击**。

1. **第一次点**某条小节线 → 谱面上立刻出现一条「反复开始」，并弹 toast：
   「反复起点已落在这里（第 n 小节线）—— 再点右边一条小节线成为一对」。**这时它还没进 json。**
2. **在它右边再点一条**（与已有反复不重叠）→ 两条线**这时才一起写进 json**，成为一对反复，toast 报出小节范围。
3. **第二次点得不合法**（点在起点左边 / 同一条线 / 与已有反复重叠）→ 什么都不加，起点**被取消**，toast 说明原因。
4. **切工具 / 退出编辑模式** → 那个还没成对的起点**自动消失**（它本来就没进 json）。
5. **已成对的区间里再点一条** → 这是「**房子起点**」（细竖条），房子 1 的括号从它往右画到结束线、
   房子 2 的括号在结束线右边**只占一格**。一对里只能有一个房子起点，再点别处会被拒绝并提示。
6. **再点一下房子起点** → **只删掉这一条**（括号随之变回去），反复还在。
7. **点开始线或结束线** → **整段反复一起消失**（另一条 + 房子一起删），底部出现可撤销的删除提示。
8. **点最后一条小节线**（曲末，它后面没有小节）→ 不添加，弹「这条小节线后面没有小节，无法标记」。
9. **删掉一条小节线 / 一行的整个标记层** → 挂在上面的反复（含房子）跟着消失，不会留下孤儿标记。
10. **触屏 + 抓手模式**下这一套同样成立（点一下就有 / 就删，不需要拖）。

### 18.40 播放按反复走 + 跳跃提示持续闪 + 进编辑模式停播

113. **播放按反复展开的顺序走**：
     - **没房子**的反复两遍走一样的内容；**有房子**时房子那段只有第一遍走，第二遍**碰到房子起点直接跳到反复结尾之后**
       （`‖: 1 2 [3 4] :‖ 5 6` → `1 2 3 4 | 1 2 5 6`）；
     - 验证：标一对反复播一遍，听/看播放头在**终点跳回起点**、以及有房子时**从房子起点跳到结束线之后**。
114. **跳跃闪烁：两种**（别混成一个），都是**渐变换色**地闪（不是两色硬切）。
     底色用 `--accent-weak`（当前小节的底色），所以落地时无缝接上、不会闪出第三种颜色。
     - **跳转前闪烁**（自动跳：终点跳回起点 / 房子跳转）：**每拍闪一次、重复一整个小节**
       （4/4 @120BPM 就是 `0.5s × 4`；跟着拍号与 BPM 走），判据是「下一小节的起点就是落点」，
       从**跳跃前那一小节**开始闪；
     - **跳转后闪烁**（**手动跳转：点小节 / 跳段落 / 跳转浮层** / **自动跳落地**）：在落点上**闪一下**就完
       （一次渐变、约一拍，`1 forwards` 停在透明上）。
       ⚠️ **判据是「播放头跳转那一刻」，不是「真正开始播放那一刻」**：
       手动跳转 / 框选起播 = `seek` 之后当刻（打了预备拍也在点击那一刻闪，**不等倒数演完**）；
       **循环回跳 = `seek(region.start)` 之后当刻，然后才数预备拍**；自动跳 = 落地那一拍。
       实现与四个入口的次序见 §18.40 第 137 / 138 条，别挪到「开始播放」那一步；
     - 所以**一次反复跳转会看到两段**：上一小节里每拍闪一下 → 落地那一下再闪一次 → 播放头走出落点后收掉；
     - **同时**：同一个落点连着重跳两次 → 每次都从头闪（`:key` 带 tick）。
115. **三样播放态的东西，显示条件拆开**：
      **当前小节底色与播放头（那条竖线）「有位置就画」**（暂停 / 停止 / 预备拍都画，只有编辑模式不画），
      **闪烁是「播放中 + 预备拍中才画」**（暂停 / 停止不画），而且**预备拍里主动点亮落点**
     （跳转预备拍 = 你点的那一小节、循环段预备拍 = 框选的起点，每拍闪一下）。
     - 编辑模式是硬门槛：进去之后谱面上只剩标记，不该再混着「播到哪了」；
     - **跳转后闪烁**照旧是例外：它是「刚刚跳到了这里」的一次性事件，手动跳转多半发生在没在播放时，
       跟着播放态一起藏掉就等于手动跳转永远不闪 —— 所以它只要状态在就画。
116. **手动跳转「视作还没反复过」**：播到反复中间时点第 2 小节 → 从**第一遍**的第 2 小节接着走，
     后面的反复照走（不是「跳到第二遍的第 2 小节」）。跳段落（`GotoDialog` 的列表）同理。
117. **进编辑模式自动停止播放**：播放中点右上角「编辑」→ 声音立刻停（位置留着）；退出编辑再按播放从原地继续。
     - 另外三个进编辑模式的入口（导入 JSON、打开没有任何标记 / 没有音频的乐谱自动进、Esc 退出）行为一致。

### 18.41 段落编辑器只剩四个字段 + 段落标记改成「拍上的线 + 圆饼上方的横向名牌」

112. **段落面板裁到只剩字段本身**：
     - **没有的东西**（别再加回来）：顶部的 chip 摘要行（位置 / BPM / 拍号三颗）、每个字段下面那几行
       详细说明（拍号那句「例如 4/4、3/4、6/8…」、位置那句「整数部分是小节…」与「标记线位于第 n 小节」、
       锚点那句说明）、**「位置」下面的整块设置**（分割线 + 时间锚点按钮组 + 时间轴 / 「播放位置定位到此处」
       那块 `.info`）、位置旁边那颗「**用线位置**」（`segment.position.useAuto`）、
       拍号分母按钮右侧那颗 `arrow-down-right` 箭头。
     - 面板从上到下只有：**段落名称 / BPM / 拍号（分子九宫格 + 分母短单选钮）/ 位置**。
       格式说明在各自九宫格键盘里（`hint`：`4.03 = 第 4 小节第 3 拍`、`可输入小数`…）。
     - **删的只是入口，不是数据**：时间锚点 `seg.time` 仍在 schema 里、`buildTimeline` 照旧按它对齐，
       `captureSegmentTime()` / `clearSegmentTime()` 也留在 store 里 —— 只是面板不提供那两个按钮。
       i18n 里没有 `segment.summary` / `meter.desc` / `position.{useAuto,note,headNote,autoNote}` /
       `anchor.*` / `timeline` / `seekHere` / `seeked` 这一批文案。
     - 验证：打开任一段落 → 字段下面**一行说明都没有**；位置那一栏右边**没有「用线位置」这颗钮**；
       点拍号分母 → 按钮上**只有一个数字**，菜单照旧贴按钮弹出；改完值照旧即时生效（没有保存按钮）。
113. **编辑面板的 footer 只有「删除」独占整行**（`EditorPanel` 是外壳，
    现在只有段落面板在用它）：**没有「完成」**——它和头部 × 是同一个动作（关闭只是导航），留着只是把删除挤成半行。
     `canDelete` 为假时（「开头」段落）**连 footer 都不给**（`<template v-if="canDelete" #footer>`），
     免得留一条空边框。关闭走右上 × / Esc / 点遮罩。
114. **段落标记 = 「小节线一样的线 + 拍上的落点 + 横向左对齐的名牌」**：
     - **线 = 长得和小节线一样的一条竖线**（同色同粗细），但**位置落在段落 `position` 的「拍」上**。
       **拍点 = 小节按「每小节拍数 + 1」等分后的内部那几条分割线**：
       4 拍的小节五等分，第 1～4 拍落在 `1/5、2/5、3/5、4/5` 处 ——
       `x = 小节 x0 + 小节宽 × 拍 / (每小节拍数 + 1)`（分母取段落自己的 `beatsPerBar`）。
       于是**第 1 拍也不压在小节线上**、两端各留一格，`4.03` 画在第 4 小节 3/5 处。
       ⚠️ 播放进度线**不是**这套网格（它从行首 0 线性扫到行尾 1，表达「这一小节走了几成」）——
       两者说的不是一件事，别顺手调成一样。
     - 线的**上端穿过小节号圆饼、一直伸到名牌底边**（像一根挑着牌子的杆），下端仍是行底。
     - **名牌横排、左对齐**：左边缘贴住线、向右展开；牌宽按估算字宽收放（`SEG_MAX` 封顶、超长截断加省略号），
       快到纸右边时整块左移不越出纸面。字号 13，底与字是实色 `--accent` + `--on-accent`（同小节号圆饼那套，见 §18.40）。
     - **名牌挂在圆饼上方**（行顶往上依次是：圆饼 → 2pt 缝 → 名牌），所以圆饼**不需要避让** ——
       `barNumberMarks` 里**没有**「有段落就把圆顶上去」的逻辑，圆永远贴着行顶。
       （房子括号在名牌**再往上一层**，见 §18.40。）
     - 落在哪一小节由 **`segmentStartMeasure()`（domain/timeline.js）** 定：**位置优先**，
       没写位置才退回 `barId` 那条线（与 `resolveSegments` 同一条规则），
       谱面那条线与总览那根蓝线因此说的是同一件事。位置指到别的页就在那一页画；
       位置越界（例如挂在曲末那条线上）退回画在那条小节线上。
     - **命中判定是「按画出来的那条线」**（`hitSegmentMark`，竖直范围从名牌顶边到行底）：
       线既然不在小节线上了，就不能再拿「最近的小节线上有没有段落」判 —— 那样点 `4.03` 的标记
       会在别处新增一条。`segment-open` 事件因此抛**段落 id**（不是 barId）。
     - **横向命中 = 线的左右 12pt，或者整块名牌的矩形**（`left … left + w`，名牌那块矩形不额外放容差，
       免得同一小节里 4.01…4.04 几块牌子互相抢）。点名牌上的字必须打开它自己的设置 ——
       牌子是这块标记上最显眼的一块，只认那条细线等于「点着名字没反应」。
       ⚠️ 名牌挂在**行顶上方**，所以 `handleEditTap` 里**段落这一路必须排在 `if (!system) return` 前面**：
       先按行筛的话，点名牌那一下 y 已经出了行（`hitSystem` 只给 8 CSS px 空隙），会被静默吃掉。
     - 验证：把某段落的位置改成 `4.03` → 那条线落在第 4 小节的 **3/5** 处（不是小节线上）、
       名牌仍在圆饼上方且横向左对齐；点这条线**或名牌上的字** → 打开的是它自己的设置，
       而不是在旁边新增一条；同一小节里排 `4.01 / 4.02 / 4.03 / 4.04` 四条 →
       线正好落在把这一小节**五等分**的那四条分割线上（两端各空一格）。

### 18.43 音频起点那一屏：数值用文字色、没有微调箭头、「添加弱起小节」开关
116. **起点数值只用文字色**：`.center-val` 是 `--text-strong` —— 它是个**值**，不是一个可点的强调项。

       拍号更少的段落（例如 1 拍）。**`order` 里找不到 `startPosition` 时不提前**，
       免得把整首曲子的时长当成弱起小节。

### 18.44 标记列表（再点一次已选中的标记工具）

四条设计选择：**行做父节点挂各种标记** / **删行连子标记一起删（可整段撤销）** /

界面**照乐谱库那套来，别自成一套**（见 125 与 127）。

121. **入口 = 同一个标记工具再点一次**（`PlayerToolbar.setTool`）：点**另一个**工具仍然只是切工具

     （`AppSheet` + `position="center"`、**不传 `follow-layout`** —— 与「删除乐谱」那个确认同一个形态，
     标题「删除标记」、正文「确定删除选中的 N 处标记吗？」、footer 是「取消 + 删除（危险色）」；
     **N 是真正会被删掉的项数**：勾了整行时它下面的子标记不重复计）。
     确认之后才落库，**整批只压一个撤销点**（`snapshotUndo()` + 四个删除函数全部 `snapshot = false`），
     顶部那条撤销 banner 因此也只弹一次；`removeSegment` 有 `!seg` 的兜底。
     两处收尾细节：**条数要在动手之前数好**（`rows` 是 meta 的 computed，删完再读只会得到 0）、
     **确认框开着时面板自己的关闭动作让位**（`AppSheet` 的 Esc 挂在 window 上，两个都开着时
     一下 Esc 会同时命中它们 —— 拦一下才是逐层关）。
128. **缩进与 hover：三条「看着像没写」的坑**：
     · **缩进的两层原因**：「除了行（父节点），下面的东西都要缩进一格」。
       ① 规则**必须写成 `.tree-children .tree-node`（两段）**：单类的 `.child-node` 与 `.tree-node`
       同为 (0,1,0)，而 `.tree-node` 里的 `padding: 6px 8px` 简写排在后面，会把单类的 `padding-left`
       整个盖掉 —— 缩进没生效的真正原因就是它。
       ② **值必须明显越过父节点文字的起点**：父节点那一行的文字从 **34px** 起
       （8 内边距 + 16 箭头 + 10 间距），写成 `34`（= 与父节点文字对齐）看着就跟没缩进一样；
       现在是 **`58`**（34 + 24 的台阶，行高只有 46，台阶再大就只剩空白了）。
     · **hover / 按下**：父节点的常态底色 `.marks-list > li > .tree-node` 是 (0,3,0)，
       比 `.tree-node:hover` / `:active`（(0,2,0)）重 —— 所以**「行」那一排永远不变底**，
       而子节点看着正常（它们的常态底色是 `none`）。修法是把重的那个选择器再写一遍
       （`.marks-list > li > .tree-node:hover`），乐谱库的 `.card.current:hover` 也是这么处理的。
     · 通用教训两条：**给「已经有更高优先级状态色」的元素写 hover 时，别只看自己那一条**；
       **「对齐到同级文字」与「缩进」是两件事** —— 缩进要的是肉眼可见的台阶。

### 18.45 段落编辑器：BPM / 位置占满一行（`NumberPad` 上的 `class` 必须透传）

名称那一栏本来就是整行（`.text-input` 是 `width: 100%`），BPM 与位置也要整行；
底下是**两个原因叠在一起**，修的是根因 —— 不是给这两处单独打补丁。

129. **`NumberPad` 的根节点必须是单个元素，`class` 才落得到 `.nfield` 上**。
     如果模板把 `<Teleport to="body">`（九宫格键盘）与根 `div.nfield` **并排**写，
     Vue 会把这个组件的根节点当成 Fragment，**非 prop 属性一律不往元素上落** ——
     dev 控制台会看到「Extraneous non-props attributes (class)… because component renders
     fragment or text **or teleport root nodes**」。那时调用方写的 `class="wide"` **静默失效**
     （`SegmentEditor` 的 BPM / 位置、`GotoDialog` 的小节 / 拍都中招），本地 `.wide` 规则永远匹配不上。
     **Teleport 要放在根 `div.nfield` 里面**：DOM 结果一模一样（键盘仍旧渲染到 body），
     根节点回到单元素，`class` 恢复透传。`NumberPad.vue` 里那条注释写明了「别把它挪回外面」。
130. **「占满一行」这一档由 `NumberPad` 自己定义**：`.nfield.wide { display: flex; width: 100% }`，
     调用方只写 `class="wide"`、**不各写一份本地规则**（`SegmentEditor` 的 `flex: 1`、
     `GotoDialog` 的 `width: 100%` 两条都不存在）。**默认的 `.nfield` 仍是窄框**
     （inline-flex + `min-width: 76px`）：它经常和别的控件并排（拍号的分子、跳转面板的小节 / 拍），
     所以「占满一行」必须是显式一档，**别把 `.nfield` 改成默认 100% 宽**。
     `SegmentEditor`「位置」那一栏外面那层单孩子的 `.row` 不存在 —— BPM 与位置结构完全对称。
131. **验证（手工，UI 改动不跑自动化）**：
     1. 打开任一段落 → **名称 / BPM / 拍号 / 位置四栏左右边界全部对齐**，BPM 与位置的框不缩成一小块；
        点框里任意位置照旧弹九宫格。
     2. **拍号那一行**：分子与分母仍是并排的两个控件（别被「一律占满一行」带跑）。
     3. **跳转面板（小节 · 拍）也是宽的** —— 那两处本来就写着 `class="wide"`，是同一个坑的另一处表现。
     4. 浏览器控制台**没有**那条 `Extraneous non-props attributes (class)` 警告。
     5. 九宫格键盘位置不变：贴在触发框正下方贴右对齐，滚页面 / 转屏时跟着框走。

### 18.46 页面缩放全站禁用：捏合与双击都放大不了

132. **「移动端双指缩放页面」整条禁掉**。先分清是谁在放大 —— 这里有**两层**，缺一层就等于没禁：
     - **页面级**：`index.html` 的 viewport 写着 `maximum-scale=1.0, user-scalable=no`，
       **Android 上的 Chrome 认这两档**；但 **iOS Safari 从 10 起直接无视它们**（Apple 为无障碍故意忽略，
       至今如此），所以 iPhone / iPad 上照样能捏合放大 —— 手机上最常见的就是这一条。
     - **谱面级**：`ScorePage` 的 `.score-page.no-gestures`（抓手模式，默认）声明 `touch-action: auto`
       （§18.35），抓手那条 `auto` 的作用是把这一层的滑动交还给浏览器，浏览器顺手把捏合也一起给了。
     - **落地（两处，一起写才是全平台）**：
       · `main.css`：在 `html` 那条规则上加 `touch-action: pan-x pan-y`。
         **`touch-action` 的生效值沿祖先链取交集**，所以这一条会把下面所有层一起收窄
         （谱面那条 `auto`、`Minimap` / `AudioOffsetPicker` 的 `none`、按钮的 `manipulation`），
         效果就是**只允许单指平移** —— 捏合与双击放大都没了，单指滚动 / 惯性 / 各组件自己的拖动完全不受影响。
         这是**唯一一处**收窄点：**别**去 `body`、`#app` 或各组件再抄一遍。
       · `main.js`：`gesturestart` / `gesturechange` 上 `preventDefault()`（Safari 专有手势事件），
         兜住 `touch-action` 支持不全的老 iOS。
     - ⚠️ **不要加**「document 上挂非 passive 的 `touchmove`、多指就 `preventDefault`」这条常见兜底：
       它是文档级非 passive 监听，会让浏览器对整页滚动做保守处理（掉帧 / 惯性变差），
       而它多兜住的只是「既没有 gesture 事件、`touch-action` 也不认」的浏览器 —— 现在不存在。
     - **拦不住的残余（网页关不掉、也不该关）**：iOS 地址栏「AA → 网页缩放」、
       Android 无障碍里的「强制缩放」、桌面浏览器 Ctrl+滚轮。所以准确说法是「给误触加了一道闸」，
       不是「保证不能放大」。
     - **代价（写明白，别再当 bug 报）**：WCAG 1.4.4 要求能放大到 200%。这个 App 是固定
       `100dvh` + `overflow: hidden` 的壳，谱面页宽 / 页高顶满、**没有自己的缩放控件** ——
       双指捏合是手机上**唯一能放大谱面的手段**（指针模式下连它都没有）。禁掉之后视力不好的
       用户只剩系统放大镜。**真要给谱面放大，就得做 App 内的第三态缩放**（`scrollMode` 整页 / 居中之外），
       那是另一件事。
     - 验证（**真机或 DevTools 触屏模拟**，横竖屏都过一遍；鼠标侧应当完全无感）：
       1. 谱面（抓手模式，默认）：两根手指捏合 → **一个字都不动**（不放大也不缩小），
          单指滑动照旧滚谱、惯性照旧；
       2. 同一个谱面切到**指针模式**再捏合 → 同样不动（这一层本来就是 `touch-action: none`）；
       3. 乐谱库 / 设置抽屉 / 标记列表：捏合都不动，**单指滚动与列表滚动惯性照旧**；
       4. 快速双击谱面 / 列表项 → **不放大**（双击放大与捏合是同一套 `pan-x pan-y` 挡的）；
       5. 总览（`Minimap`）拖动、音频频谱拖动、侧栏把手拖动**完全不受影响**；
       6. iPhone 上如果还能放大，先看是不是从 iOS 地址栏「AA → 网页缩放」放的（那是系统功能，预期仍在）；
       7. 桌面浏览器 Ctrl+滚轮 / 触控板捏合仍会放大 —— **预期**，那是浏览器自己的缩放，不是页面手势。

### 18.47 「开头」段落在编辑模式里也画一条标记

133. **固定的「开头」段落（`head`）在段落工具下也画出来**：位置固定在第一小节第一拍；
     如果没有小节就先隐藏。
     ⚠️ **它不能是全谱唯一一条不画标记的段落**：那样用户在谱面上看不到它、也无从点开它改 BPM，
     只能靠「在第 1 小节那附近新增段落」这条绕路（`addSegmentAt` 里 `auto <= 1` 那一支）。
     - **落点由 `segmentStartMeasure()` 给**：`head` 直接算**第 1 小节**（**不看它自己的 `position`** ——
       哪怕数据被手改坏了，也照样画在开头）。线段本身仍走那套「拍上等分」的规则，
       所以 `position = 1` → 第 1 拍 → `x = 小节 x0 + 小节宽 × 1/(拍数+1)`，
       就是**第 1 小节第 1 拍**（不压在小节线上，与其余段落一致）。

       并且 `ScorePage.segmentGeometry` 里对 `head` **不许退回 `barId` 那条线** ——
       它的位置是固定的，不该因为还挂着一条小节线又冒出来。
     - 只在 `editMode` 下画（`ScorePage` 的 `.lyr-segments` 本来就只在编辑模式渲染），
       配色 / 线形 / 名牌与别的段落**完全一样**（形状是标记之间的区分手段，不给它单开一档）。
     - **不进「标记列表」**（`domain/marks.js` 里 `seg.head` 跳过：删不掉，
       列出来只会让人试着去删它）；总览那根蓝线跟着一起有了（同一个 `segmentStartMeasure`）。
     - 点它 = 打开它自己的设置（`SegmentEditor` 对 `head` 没有 footer 的「删除」；
       位置栏锁在第 1 小节）—— 与 `addSegmentAt` 在开头那一支的行为一致，没有新增入口。
     - 单测：`scripts/unit-test.mjs` 有三条（固定第 1 小节 / `position` 被改坏也照样 /
       没有小节时没有落点）。
     - **验证（手工，UI 改动不跑自动化）**：
       1. 已标好小节的谱 → 段落工具下，**第 1 小节第 1 拍上**出现「开头」名牌，
          与其它段落长得一样；点它 → 打开的编辑器**没有删除键**、位置锁在第 1 小节；
       2. 把「开头」的 BPM 改成别的 → 它是默认速度，改完别处没有段落的段落跟着变；
       3. **没有小节**的谱（只有一行、不到两条小节线 / 还没标行）→ 段落工具下**看不到「开头」那条标记**；

### 18.48 行顶往上的竖向层序：圆饼 → 名牌 → 房子括号

134. **房子括号在「段落名牌的上方」**（从上到下分别是房子、名牌、小节圆饼）。
     ⚠️ 旧写法 `行顶 − 15` 正好落在小节号圆饼（圆心 `行顶 − 11`、半径 9）的竖直范围里 ——
     「1. / 2.」和数字圆饼会互相压。
     - **定死的三层栈**（从下到上）：**小节号圆饼 → `SEG_GAP` 2pt 缝 → 段落名牌（`SEG_H` 18）→
       `HOUSE_GAP` 2pt 缝 → 房子括号（`HOUSE_H` 12）**。这条层序对「房子」与「段落」两类标记都成立：
       两者在同一行上各自占自己那一层，**不互相避让**（`barNumberMarks` 那边没有任何抬高逻辑）。
     - **落地全在 `ScorePage.vue` 的几个常量里**：`DISC_R` / `DISC_UP` / `DISC_TOP_UP`、
       `SEG_H` / `SEG_GAP`、`HOUSE_H` / `HOUSE_GAP`，房子那个 `y` 由 `HOUSE_UP`
       （= 饼顶 + 缝 + 名牌 + 缝 + 括号）算出来。**别再往模板里写裸数字**；
       改圆饼或名牌的尺寸，房子跟着一起挪。
     - **模板里 `y + 2` / `y + 9` / `y + 12` 那三个偏移**（括号横线 / 两侧短竖 / 标签基线）
       是 `HOUSE_H = 12` 的来源 —— 改模板要同时改常量。
     - **代价**：第一行上方的占用从 40pt 变成 54pt。行距够的谱（示例数据 ~128–160pt / 行、
       首行页边距 ≥ 85pt）看不出差别；行距极紧的页上，页首那一行的房子可能与页边撞上，
       由原有的 `Math.max(0, …)` 兜住（顶到 y = 0 就不再往上）。
     - **验证（手工，UI 改动不跑自动化）**：
       1. 标一对反复 + 一个房子起点 → **房子括号在名牌上方、名牌在圆饼上方**，三者不重叠，
          「1.」不再压在任何一个数字圆饼上；
       2. 同一行同时有段落与房子 → 名牌与房子各占一层，互不遮挡；
       3. 翻到页首那一行（该行有房子）→ 房子仍在纸面内，没有被裁掉半截。

### 18.49 标记本体常态就是实色 `--accent`

135. **标记本体的常态就是实色 `--accent`**（不是「半透明常态 + 悬停变实色」）：
     ⚠️ **自造 `--accent-line-focus` 那条路不要走**，`main.css` 里没有这个令牌。

       谱面标记是 JS 命中，悬停靠**加粗 + 放大 + 行底**表达，与那一条不冲突。

### 18.50 弱起比音频里那段长：位置从负数走起、音频等到 0 秒
121. **问题**：配了「添加弱起小节」（`startPosition = 2`）后，第 1 小节整段落在音频 0 秒**之前**
     （记谱的弱起小节比音频里那段弱起长）。点第 1 小节时 `seek()` 把负数夹到 0，于是落点在小节的半截上 ——
     现象就是**从后半小节开始播放**。
122. **规则：位置不夹，从负数走起**，`<audio>` 钉在 0 秒，
     等位置走到 0 秒再起播。负数位置寄存在 `clock.leadPos`（`OutputClock.now` 优先读它），所以底层时钟
     仍然只看得到 ≥ 0；前导循环在 `store/player.js`（`startLead` / `leadTick` / `stopLead`），
     前导期间 `player.playing` 为真、谱面 / 节拍器 / 进度都按时间轴走。详见 `docs/concepts.md` §3「弱起前导」。
123. **连带的三处**（都在 `store/player.js`，别再各写一份）：
     - `player.seek()` **下限不夹 0**（只夹上界 = 总时长）；负数走 `clock.leadPos` 分支，并顺手把还在响的
       `<audio>` 停住（带 `suppressRewind`，否则那次内部 pause 会触发「回退到小节开头」）。
     - `pausePlayback()` 里 `stopLead()`：**暂停只停走时**，位置留在那个负数上，再按播放从那儿接着走。
     - `engine.on('time')` 在前导期间**直接 return** —— `<audio>` 那时每帧还在报 0，会把负数位置顶掉。
124. 验证（手工，UI / 交互改动不跑自动化）：
     1. 弱起比音频里那段长时点第 1 小节：谱面从 **1.01** 开始走（不从 1.03 之类跳进去），
        音频在 1.5 秒（举例）那个负数段走完之后**才出声**，第 2 小节仍然精确落在设的音频起点上；
     2. 前导期间按暂停：停在当时那个负数位置上；再按播放**从那儿接着走**（不是从头重来）；
     3. 跳到第 2 小节 / 往后任意小节：一切照旧，没有前导；
     4. 节拍器开着时：前导那几拍**照点**（`clock.leadPos` 是负数，节拍器跟着负数拍点排程）。


### 18.51 打开后的默认位置 = 谱面真正的开头（含「无音频 + AudioContext」那条时钟分支）
125. **打开乐谱后的默认位置是谱面真正的开头**：`open()` 末尾 `seek(timelineStart.value)`
     （`timelineStart` = 时间轴第一拍的 `time`，有弱起时是**负数**），配合 §18.40 的弱起前导，
     按播放会先把整个弱起小节走完、音频等到 0 秒才出声。
     ⚠️ **不能取固定的 0 秒**（= 音频开头）：有弱起时那是第 1 小节的中段，「打开 → 按播放」就从后半小节开始。
     规则写进 `docs/invariants.md` §7 与 `docs/concepts.md` §5。
126. **`OutputClock` 的上下文分支**（无音频、节拍器建起了 AudioContext 时的走带）按
     `origin + (ctx.currentTime − _ac) × rate` 算。⚠️ **符号写反**（`ctx.currentTime - _ac - origin`）
     的后果：`seek(6)` 之后读数一直贴着 **0**，要等 12 秒才追到 6；症状是没有音频时（只响节拍器）
     **跳小节 / 暂停一下，位置就归零**。三件事必须一起成立：
     · **倍速乘在读数上**（漏了的话 2× 走带位置按 1× 爬，和节拍器对不上）；
     · **暂停时读 `origin`**（AudioContext 是节拍器共用的，暂停期间它照样在走）；
     · `_ac` 在 **`seek` / `play` / `pause` / `resync` 四处重新钉住**，且 `resync()` **先折 `origin` 再钉基准**
       （只重钉 `_ac` 的话，中途拉一下节拍器音量位置就会弹回上一次 seek 的落点）。
     规则写进 `docs/concepts.md` §3 与 `src/domain/audio-engine.js` 头部注释；单测 `npm run test:unit` 的 `[15]`。
127. 验证（手工）：
     1. 有弱起的乐谱：打开 → 位置就停在 **1.01**（不是 1.03 之类），按播放先走完弱起（静音那几拍仍在走带），
        音频在 0 秒处才出声，第 2 小节落在设的音频起点上；
     2. 没有音频、节拍器开着的乐谱：跳第 5 小节 → 位置**就是第 5 小节**（不显示第 1 小节 / 不归零）；
        播放中点暂停 → 位置冻住不回零；2× 倍速下位置走得和节拍器一样快；
     3. 有音频的乐谱一切照旧（有音频那条分支没动）。


### 18.52 非播放也显示「当前小节 + 播放头」；预备拍里点亮落点

128. **三样播放态的东西，规则拆开**（取代 §18.40 第 115 条那一版「三样一律只在播放中出现」）：
     - **当前小节底色 + 播放头（那条竖线）**：只要**有位置**就画 —— 播放、暂停、停止、预备拍、点小节 /
       跳段落跳过去之后都画。**判据是「有没有 `activeNo`」，不是「在不在播」**（`ScorePage` 模板里的
       `v-if="!editMode && activeMeasure"` / `v-if="!editMode && progressLine"`）。
       右边总览（`Minimap`）那条蓝线本来就不分播放态，两边一致。
     - **进编辑模式一律不画**（`editMode` 是硬门槛）：谱面上只剩标记，不混「播到哪了」。
     - **闪烁分两道，显示条件不同**（见 §18.40 第 138 条）：`jumpFlash`（跳转前，每拍一下）
       在**播放中与预备拍中**画，`jumpAfter`（跳转后，落点闪一下）**只要状态在就画**；进编辑模式两道都不画。
     - **预备拍里主动点亮落点**：倒数这几拍，**落点每拍闪一下**（`jumpFlash`）：
       · **跳转预备拍**（`countInJump`）= **你点的那一小节**（同一个落点连着跳两次也从头闪）；
       · **循环段预备拍**（`countInLoop`）= **框选的起点**（框选起播 / 循环回跳都一样）；
       · **播放预备拍**（`countInPlay`）= **播放头现在那一小节**（播放就是从那会儿接着走的，
         所以它也有闪烁）；它没有跳跃，**不闪「跳转后」**；
       · **闪烁落在当前小节上时，当前小节那层常亮浅底要让位**（`ScorePage` 的 `flashOnActive`）：
         闪烁本身就是 `--accent-weak` 在 `opacity 0 → 1 → 0` 之间走，两层半透明底叠在一起看到的是
         「一直亮着、峰值只深一点点」，**不是空白 ↔ 底色之间的一下一下** —— 预备拍那几拍必须
         和「跳转前闪烁」长得一模一样。撤掉那层底之后峰值与当前小节同色，落点该亮的时候照样是主题色浅底。
         （**只管「跳转前」那一道**：它持续时间最长；「跳转后」是盖在上面一闪而过的，单独出现时底下那层要留着，
         见 §18.40 第 114 条。）
       · 倒数演完：**不再补闪「跳转后」** —— 手动跳转 / 框选起播的那一下在**点击那一刻**就闪过了
         （§18.40 第 137 条）；循环回跳交给落地那个 watch 把「跳转前」换成「跳转后」（见 §18.40 第 114 条）；
       · **取消预备拍**（暂停 / 进编辑模式 / 离开乐谱）要撤掉「跳转前」这道，别留到下次播放莫名其妙地闪
         （「跳转后」不撤：它是「刚刚跳到了这里」的一次性事件提示）。
129. **`player.cueing`（预备拍进行中的可反应镜像）+ `startCountIn(landing, onDone)`（参数是**落点那一拍**）**：
     `metronome.countInActive` 是读定时器的 getter，**Vue 追不到它**（预备拍开始 / 结束时没有任何别的东西会
     触发重渲染），而谱面要按它决定显不显示那道闪烁，所以 `store/player.js` 里预备拍统一走 `startCountIn()`：
     排程时置 `player.cueing = true`、**`player.playing = true`（预备拍算播放中，见 §18.40 第 139 条）**，倒数结束的回调里置回 `false`；
     `pausePlayback()`（取消预备拍）与 `close()`（离开乐谱）一起归位。几处调用（无音频 / 有音频的播放与跳转
     预备拍、循环段预备拍）**全走它，别再各写一份 `metronome.countIn`**。
     `close()` 要 `metronome.cancelCountIn()` —— 否则那条挂着的倒数在离开乐谱后还会把播放拉起来。
     另外 `flashBeforeJump(sample, force)` 有个 `force`：预备拍这条路**每次换新 tick**（同一个落点连着打两次
     预备拍也要从头闪），watch 那条路去重。
       ⚠️ **预备拍打几下、每下多长，与落点闪烁的节奏在 §18.40 第 141 条合成了一份**（`countInTiming`）；
      **打预备拍先停声源**、**倒数演完撤掉落点那串闪烁**、**按暂停当刻静音的倒数闸门**
      （`Metronome` 的 `cueGate`）也都在那儿（第 140 / 141 条）。
130. 验证（手工，UI 改动不跑自动化）：
     1. 播放中点暂停 / 停止：**当前小节浅底与播放头留在原地**（不一起消失），闪烁收掉；
     2. 打开乐谱（还没播过）：当前小节与播放头就画在时间轴起点上；点别的小节 → 立刻跟过去；
     3. 进编辑模式：三样都不画；退出来又都在；
     4. **跳转预备拍**：开着「跳转预备拍」点别的小节 → **点下去那一下落点就闪「跳转后」**，
        随后倒数这几拍里**每拍再闪一下**、闪的是**空白 ↔ 主题色浅底**（不是「亮着不动、峰值只深一点」——
        那说明 `flashOnActive` 那层让位丢了）；倒数期间播放键是「暂停」；
     5. **循环段预备拍**：开着「循环段预备拍」框选一段 → 松手那一下**框选起点就闪**、同时开始倒数；
        播到末尾回跳时同样先闪起点、跳完再闪一下；
     6. **播放预备拍**：开着「播放预备拍」按播放 → 倒数这几拍**把当前这一小节点亮、每拍一下**
        （定位「马上要从哪儿开始」），**不闪「跳转后」**，数完从原地接着播；
        ⚠️ 顺带：**按暂停当刻停**，剩下的几下不会再响（`Metronome` 的倒数闸门，见 §18.40 第 140 条）；
     7. 预备拍中途按暂停 / 进编辑模式：闪烁与「预备拍中」一起收掉，再按播放不会莫名闪起；
     8. 标一对反复、播到反复前那一小节：自动跳的「跳转前闪烁」照旧（每拍一下），落地闪一下。
     （「跳转预备拍」的前提、「跳转后」闪烁的时机、预备拍算不算播放中，见 §18.40 第 137–139 条；
     节奏同源与两道闸在第 140 / 141 条。）


### 18.53 框选的灰底在拖动过程中就亮

136. **框选循环段时，在框的过程中就把选中的小节标灰，而不是松手才标灰**。
      ⚠️ 只有**松手**那一下才发 `select`、灰底（`.m-sel`）要等 `props.selection` 回来才出现的话，
      拖动全程只有那个半透明框，看不出「到底选中了哪几小节」。
     - **实现**：`ScorePage` 里把命中的算法抽成 `measuresInBox(box)`（返回 `{ from, to }`），
       **拖动中的预演与松手落下的区间共用这一支** —— 各算一份的话，「拖的时候亮这几格、
       松手却循环另外几格」迟早会发生。预演由 `dragMode`（字符串 ref）+ `dragRange`（computed）
       驱动，`selectedMeasures` 在拖动期间优先取 `dragRange`，渲染、样式、坐标全走原来那一套，
       **没有新增任何一层几何或一档颜色**。
     - **只在「框选」这一路成立**：编辑模式的行带（`row`）是「将要落下的那一行」的预览，
       不是框选，`dragRange` 会把它挡掉（`box.row` 那一判）。
     - **松手不闪**：`dragMode` 与 `marquee` 同帧清空，而 `props.selection` 由父组件在同一轮里设上，
       所以「松手 → 循环开始」之间灰底**不断档、也不叠两层**。
     - 验证（手工，UI 改动不跑自动化）：
       1. 非编辑模式在谱面上慢慢拖一个框 → **手指还在拖**，盖住的那几小节就已经是灰底了，
          而且范围跟着手指实时变；
       2. 松手 → 灰底留在原处（不闪一下、不换几格）、循环从那一段开始；
       3. 进编辑模式用「行」工具划一条行 → **不会**顺手点灰任何小节（那是行带，不是框选）；
       4. 拖到谱面空白处（一个小节都没盖住）→ 全程没有灰底，松手也不循环。


### 18.54 预备拍与「预备拍闪烁」同源；**先数完预备拍才跳**；预备拍算播放中

137. **规则（别再来回挪）**：
     · **所有带预备拍的地方：先数一小节，数完才把播放头跳过去**（手动跳转 / 框选起播 / **循环回跳**
       都一样）。倒数这一小节里**播放头一动不动**（还在你原来那一小节），**只有落点那串「跳转前」在闪**
       （每拍一下、连闪一整小节）；数完才 `seek` → 闪「跳转后」→ 起播。
       ⚠️ **别在点击那一刻就跳**，也**别在点击那一刻就闪「跳转后」**。
     · **「跳转后闪烁」的时机 = 播放头跳转那一刻**，不是点下去那一刻、也不是真正开始播放那一刻
       （`flashAfterJump` 的注释里写着这条规则）。上面那套次序之下，它自然落在**倒数演完之后**；
       没打预备拍的那几条路（暂停着点跳转、预备拍关着 / 音量为 0）就是 `seek` 之后当刻。
     · **播放预备拍（工具栏那颗播放键 + `countInPlay`）也要闪**：它没有跳跃（`from` 为 null），
       落点就是**播放头现在那一拍** —— 倒数这几拍把「马上要从哪儿开始」那一小节点亮，和跳转那几条路
       长得一模一样；因为没跳，**不闪「跳转后」**。
     · **预备拍也算播放中**：倒数期间**播放键显示「暂停」**，点它就是暂停 / 取消倒数。
     · **「要不要接着走带」与「要不要打预备拍」分开判**（`seekToPosition`）：
       **走带 = 「跳转自动播放」开着 或 此刻本来就在走带中**（`player.playing` —— 预备拍期间也为真）；
       **预备拍 = 「跳转预备拍」开着 且 上面那条成立**。
       于是：**播放中点跳转、即使没开自动播放也要数一小节再接着走**；
       **暂停着 + 没开自动播放 = 既不自动播、也不打预备拍**（只跳到落点、闪一下「跳转后」）。
       「要不要播」判在 `seekToPosition`；`startPlayback` 只管「打不打预备拍」。
138. **两种闪烁各占一个槽位**（`player.jumpFlash` / `player.jumpAfter`，`ScorePage` 画**两层** `<rect>`）：
     一个槽位里两种相位只能轮流出现，而这两道**可能在同一小节上前后脚出现**（倒数时闪「跳转前」，
     数完那一刻换成「跳转后」），合成一个槽位就会互相顶掉。
     · `jumpFlash`（**跳转前**）= 每拍一下、**时长就是它所在的那一小节**（预闪按当前小节算：
       `beforeJumpTiming`；预备拍那一道按预备拍自己的节奏：`countInTiming`）：
       **自动跳**的预告（下一小节的起点就是落点）、**循环区间回跳**的预告
       （走进区间最后一小节就点循环起点，见 §18.42），以及**预备拍倒数**期间点住落点；
       `ScorePage` 里**只在播放 / 预备拍里画**，`flashOnActive`（当前小节那层浅底让位）**只看它**；
     · `jumpAfter`（**跳转后**）= 落点上闪一下就完：**播放头跳转那一刻**点亮
       （`startPlayback` / `handleLoopEnd` 的收尾里、`seek` 之后当刻；自动跳是落地那一拍由 watch 点亮）；
       **只要状态在就画**。
     两道进编辑模式都不画；暂停只撤「跳转前」那道（「跳转后」是「刚刚跳到了这里」的一次性提示）。
139. **预备拍 = 播放中**：`startCountIn` 里除了 `cueing` 还置 **`player.playing = true`**
     （起始是暂停也必须置真 —— 「暂停着点跳转 + 开了跳转自动播放」就是这一路）；
     `engine.on('pause')` 开头 `if (suppressRewind) return` —— 预备拍开头那次「停」是上层刻意压住的
     （只是把音乐停下来数拍子），不退出播放态。于是倒数期间：播放键（`PlayerToolbar` 读 `player.playing`）
     显示「暂停」、点它 → `togglePlay` → `pausePlayback()` 取消倒数；`topHidden`（走带中藏顶栏）也算数。
     真暂停走 `pausePlayback()`：它**先**把 `suppressRewind` 置假再 pause，所以还是会停、会回退到小节开头。
140. **按暂停 = 当刻停，不许把预备拍剩下的几下打完**：`Metronome` 里给倒数加了一道
     **闸门**（`cueGain → cueGate → master`）：`countIn()` 一次把一整小节都排进 Web Audio，撤是撤不掉的，
     所以 `cancelCountIn()` 除了清定时器，还把闸门 `setValueAtTime(0, ctx.currentTime)` **当刻静音**；
     下一轮 `countIn()` 再开闸。**音量与闸门是两个节点**（`setCueVolume` 写 `cueGain.gain`）。
141. **预备拍与落点闪烁同源 + 打预备拍先停声源**：
     · `countInTiming(sample)` 一份节奏：`beats` = 预备拍打几下 = 落点闪几下，`beatMs` = 每下多长 =
       每下渐变多长（下限 160ms；一拍长度走 domain 的 `beatDuration()`，与时间轴 / 节拍器同一支算式）。
       ⚠️ **预备拍与闪烁不能各取一套节奏**：预备拍走 `tempoAt(segments, pos.no)`、
       闪烁走 `samples.find(no === 落点 && beat === 1)` 的话，改过 BPM / 拍号就会一个快一个慢。
     · `startCountIn(landing, onDone)`：参数是**落点那一拍本身**。跳转那条路用 `countInSample(from)`
       （按落点**时刻**取时间轴记录 —— `from` 是 `posToTime` 算出来的，天然是**这一遍**那条；
       反复里同一个小节有好几条，按小节号取会取到第一遍那条）；播放预备拍用播放头现在那一拍。
     · **倒数演完顺手撤掉落点那串「跳转前」**（`startCountIn` 的回调里）：它正好演满一小节，
       状态留着会一直让「当前小节那层浅底让位」（`flashOnActive`）生效 —— 闪烁早透明了，
       落点那一小节看着却像没有「当前小节」的底。**自动跳**那串不是在这儿点的，不受影响。
     · 打预备拍前 `stopSources()`：倒数这一小节播放头**钉在原地不动**（否则音乐压在倒数底下继续放，
       位置还会走开、把落点那串闪烁收掉）。循环回跳那条路的 `stopSources()` 要**同步**先做
       （`_startTicker` 下一帧还会再看一次循环末尾，元素还在播就会再叫一次 `onLoopEnd` = 两条倒数叠一起）。
142. **两道闸：倒数期间谁也别动落点那串提示**（别拆）：
     · `engine.on('time')` 在 `player.cueing` 期间**一律忽略** —— 倒数这几拍位置本来就该钉在原地，
       真机 `<audio>` 的异步 seek / 位置上报都不算数（顺带不会有「当前小节先跳回去再跳回来」）；
     · 那条 watch 开头 `if (player.cueing) return`：**倒数期间的落点提示归预备拍管**。
       `cueing` 在 `startCountIn` 的回调里**先**置假，所以倒数演完后那一次 `seek` 照旧走正常判定。
143. 验证（手工，UI 改动不跑自动化）：
     1. **播放中点别的小节**（自动播放关、预备拍开）→ 音乐停住，**播放头留在原处不动**（当前小节底不动），
        落点每拍一下地闪、连闪一整小节，倒数期间**播放键显示「暂停」**、点它 → 倒数当刻停
        （剩下的几下不再响）、停在原处；数完 → **播放头跳到落点** + 落点闪「跳转后」+ 接着播；
     2. **暂停着**点别的小节（同样配置）→ 只跳过去、落点闪一下；**不播也不数**，播放键仍是「播放」；
     3. 「跳转自动播放」开着、**暂停着**点别的小节 → 直接开始倒数（播放键是「暂停」），
        数完才跳过去 + 闪「跳转后」+ 起播；
     4. 预备拍音量拉到 0（= 预备拍关闭）→ 播放中点跳转**立刻**跳过去接着播（不数拍、落点闪一下），
        暂停时点仍然只跳不播；
     5. **框选一段循环**（循环段预备拍开）→ 松手后先数一小节（框选起点每拍一下），数完才跳过去 + 闪「跳转后」；
        **播到末尾回跳时同样**：倒数这一小节里播放头还在循环末尾，数完才跳回起点；
        （**反复区间里面**的循环段同样要闪 —— 那是 `countInSample` / `landingSample` 修掉的那半）；
     6. **工具栏播放键起播**（播放预备拍开、没有跳跃）→ 倒数这几拍**把当前这一小节点亮、每拍一下**，
        **不闪「跳转后」**，数完从原地接着播；
     7. 预备拍中途按暂停 / 进编辑模式：「跳转前」与「预备拍中」一起收掉、声音当刻停，再按播放不会莫名闪起；
     8. **跳转浮层**（底栏「小节 · 拍」那颗钮）按小节 + 拍跳、点段落行跳 → 与在谱面上点小节**完全一样**；
     9. 标一对反复、播到反复前那一小节：自动跳的「跳转前」照旧（每拍一下），落地那一拍换成「跳转后」。


### 18.55 循环回跳必须走上层的 `seek()`
144. **规则：循环回跳一律走上层的 `seek()`** —— `handleLoopEnd` **两条路都返回 `true`（= 已接管）**。
     ⚠️ **不能有一条路 `return false` 让时钟 / `<audio>` 自己回跳**
     （`OutputClock.tick` 的 `this.seek(region.start)`、`AudioEngine._startTicker` 的
     `this.el.currentTime = region.start`）：这两处**只认 ≥ 0**，而弱起区间的起点是负数（见 §18.40）——
     被夹到 0 之后就落在小节的半截上（听感上「从音频位置开始，不是从头」）。
145. **没开预备拍的那条路**：`suppressRewind = true` → `seek(region.start)` → `playFrom()` →（还原 `suppressRewind`）。
     · 负起点由此重新起弱起前导（音频等位置走到 0 秒再出声），和其他回跳完全一条路；
     · `seek()` 要 `metronome.reset()`，回跳后不补发过期拍子；
     · `suppressRewind` 压住回跳那次内部 pause（负起点会让 `<audio>` 先停住）——不压的话它会触发
       「回退到小节开头」，而那是按 `posToTime(no)` 取**第一遍**的落点，反复里就跳错遍了。
     「跳转后」那一下由 `handleLoopEnd` 自己点（`flashAfterJump(loopStartSample)`）——
     这条路上播放头多半不换小节号，末尾那条 watch 跑不起来（见 §18.42 第 150 条）。
146. 验证（手工，UI / 走带改动不跑自动化）：
     1. 弱起乐谱（第 1 小节起点在音频之前）框选**从第 1 小节开始**的一段、**关掉循环段预备拍** →
        播到末尾回跳：从**第 1 小节开头**重新走（音频晚一段才出声），不从音频位置切进去；
     2. 同一段**开着**循环段预备拍 → 数完一小节才跳，落地位置同样是第 1 小节开头；
     3. 框选一段**不**在弱起里的（起点是正数）→ 回跳无缝、不卡顿、不重数拍；
     4. 反复区间里框选一段再回跳 → 落在**这一遍**的起点上（不会跳去第一遍）。

### 18.56 圆钮里的小字对齐 + 贴紧

**要满足的两条**：

1. 同一条胶囊里几颗 `.cap-btn` 的**小字必须在同一条水平线上** —— 「跳转」「倍速」（上面是 15px 的
   `.cap-value` 数值）的小字不能比「播放」「音频」（上面是 21 / 24 的图标）**低一截**；
2. 对齐之后**图标与小字之间不能空一大截**。

**根因（两问同源）**：`.cap-btn` 是 `flex-direction: column` + `justify-content: center` 的整列居中。
小字的 y 于是等于「(46 − 整列内容高) / 2 + 上面那一行的高」—— **上面那一行有多高，小字就浮到哪**。
而上面那一行正好有三种高度：图标 24、图标 21、`.cap-value` 的 15px 文字（行高 1.15 ≈ 17.25）。

**做法（两个令牌各管一件事，别再耦在一起）**：

| 令牌 | 值 | 管什么 |
| --- | --- | --- |
| `--cap-icon-h` | `24px` | **只管对齐**：上面那一行的固定高度（`.cap-btn > .icon, .cap-btn > .cap-value`）。取 24 = 这套控件里最大的图标尺寸，所以 21 与 24 的图标都装得下、不会被压扁 |
| `--cap-label-gap` | `2px` | **只管贴多紧**：小字的 `margin-top` |

于是小字的 y **只由「圆钮高 − 小字 − 间距」决定**，与上面放的是图标还是文字完全无关。

**⚠️ 别用 `margin-top: auto`**：`auto` 把小字**钉在圆钮底**、图标在**剩下的空间里居中** ——
两者被耦在一起，**槽越小、间距越大**（槽 24 → 盒间距 11.56px，槽 21 → **15.5px**）。
用固定值之后间距与槽高解耦：盒间距 = `--cap-label-gap` = **2px**，小字顶边极差 **0px**。

**`.cap-label` 的 `line-height` 是 1**。1.1 那点多余的半铅字高全落在**行盒上沿**，视觉上就是
「图标与小字之间空了一截」；收到 1 之后行盒贴着字形，`--cap-label-gap` 才是所见即所得的间距
（`line-height` 只改行盒、不改字号）。

**图标不统一成一个尺寸**：按视觉重量各取 21 / 24（播放键的三角比工具图标大一点）。
**固定的是「槽」，不是图标**。

**`.no-labels`（关掉文字）不需要额外兜底**：小字一 `display: none`，内容槽就是唯一子项，
父级仍是 `justify-content: center`，图标天然居中。
（`artifacts/cap-btn-nolabels-nofallback.html` 故意不加兜底，图标仍压在圆钮中线上。）
所以**不要**加 `margin-top: 0` —— 加了就是死代码（§1 第 5 条）。

**影响范围**：`.cap-btn` 是全局类，三处悬浮胶囊一起生效 —— 底栏那对（`PlayerToolbar`）、
左上「乐谱库」（`PlayerView` 的 `.back-dock`）、右上总览（`Minimap` 的 `.mini-dock`）。
`--cap-h` / `.cap-w1` / `.cap-w4` 那些**宽度算式不受影响**（圆钮仍是 46×46，两个令牌都只是圆钮内部的布局）。

**验证**（UI 改动不跑自动化）：
- 小字顶边必须**对齐**（极差 0px）、盒间距必须是 `--cap-label-gap`（2px）、
  「图标盒底 → 小字盒顶」= 2px；
- `artifacts/cap-label-geometry2.html` **在页面里打出真实 DOM 盒模型**（量的是盒而不是墨迹）——
  ⚠️ 逐像素那套工具在**笔画细、阈值不好取**时会碎段（图标被量成 2px），数字别全信 ——
  **先看几何、再看像素**；
- 人工确认：底栏普通态（播放 / 跳转 / 倍速 / 音频）与编辑态（行 / 小节线 / 段落 / 反复）
  小字各成一条线、且贴着图标；关掉「工具栏显示文字」后图标仍在圆钮正中。


### 18.57 「能预见要跳就闪跳转前」；时长只有一小节；重叠时点循环起点

148. **只要是能够预见性地要发生跳转，就有「跳转前闪烁」**。这条规则把三种来源收进同一句：
     · **自动跳**（反复 / 房子）：跳跃前那一小节（判据「下一小节的起点就是落点」）；
     · **循环区间回跳**：**走进循环区间的最后一小节**就点亮循环起点 ——
       **只要这次回跳不打预备拍就要闪**；
     · **预备拍倒数**：倒数这几拍点的就是落点（`startCountIn` → `flashCountInLanding`）。
     三种都是「每拍一下」的同一套节奏。
149. **⚠️ 时长只有一个小节，别提前闪**：
     · 预闪讲的是「**本小节**走完就要跳了」，所以拍数 / 拍长按**当前正在播的这一小节**算
       （`beforeJumpTiming` → `measureDuration(...) / 每小节拍数`），**不能按落点那一小节算** ——
       两边拍号 / 速度不同就会闪多，一多就跨到下一小节去了；
     · **这次回跳要打循环段预备拍时，预闪一律不点**（`armLoopLandingIfLastMeasure` 里的开关）：
       预备拍自己会在**下一小节**的位置上点落点，这边再预闪一小节就是**闪两小节** ——
       那种情况**只在预备拍里闪**。
     · 预备拍那一道的时长跟着预备拍自己（`countInTiming`：打几下 = 闪几下 = 那一小节的拍数），
       与预备拍的点子严格同源。
150. **重叠时点循环起点，不点反复记号**（`loopingToLastMeasure` 那一支排在反复预报**前面**）：
     循环区间的末端压在反复结束线（`:‖`）上时，**实际发生的是循环回跳**，
     所以闪烁必须点**循环起点**，不能点反复要跳去的那一小节 —— 那一跳根本不会发生。
     **循环优先 = 行为优先 + 闪烁跟着行为走**，两件事必须一致。
     ⚠️ **「本小节末尾要回跳」（`loopingToLastMeasure`）与「谁来闪」（`armLoopLandingIfLastMeasure`）
     是两件事**：打了预备拍时前者**照样成立**（所以反复那一跳的预报必须被挡掉），只是闪的人换成预备拍 ——
     这两件混成一件就会漏出「预备拍那条路上蹦出个反复落点的预闪」。
151. **实现上两个坑**（别踩回去）：
     · **判据要用「本小节的起始拍」，不能用「当前这一拍」**：播放头掉帧时会落在小节中间，
       拿当前拍比会漏判（`while (i > 0 && samples[i].beat !== 1) i--` 退回第 1 拍再比）；
     · **循环区间要取「引擎手里那一份」（`clock.loop`），不能用 `loopRegion` computed 重算**：
       那个 computed 的 `nearTime` 跟着**当前播放头**走，反复里同一个小节有好几遍时，
       播放头一走到区间后半段就会选到**下一遍**的记录 —— 于是落点点到另一遍上、下标对不上
       （该点是循环起点那一遍的记录，却点到反复那遍的）。
     另外**三处要主动补点**，只靠末尾那条 watch 会漏：
     · `setSelection` 框选起播那一刻 —— `player.playing` 还没被置真（`engine.play()` / `clock.play()`
       都是异步之后才发事件），watch 会被「不在播放也不在预备拍」那一句挡掉；
     · `handleLoopEnd` 跳完那一下 —— **单小节循环**不换小节号，watch 根本不会跑；
     · watch 里「落地那一拍」把「跳转前」让给「跳转后」之后 —— 单小节循环这一遍马上又要回跳，要补回来。
152. 验证（手工，UI / 走带改动不跑自动化）：
     1. 反复 1–2 的谱子上**只框第 2 小节**（区间末端正好压在 `:‖` 上）、**关掉循环段预备拍** →
        从第 2 小节起播时落点就闪、每拍一下、**只闪这一小节**；播到末尾回跳：闪的是
        **第 2 小节（循环起点）**、**不是第 1 小节**；而且**每回跳一次都从头闪**；
     2. 同上但**开着循环段预备拍** → 播这一小节时**不预闪**，只在**倒数那一小节**闪（点在循环起点上），
        数完才跳回去 —— **总共只闪一小节**，不是两小节；
     3. 反复 1–2 上框**第 1–2 小节**（多小节循环）、关预备拍 → 播到第 2 小节时开始闪**第 1 小节**
        （走进区间最后一小节才亮预告），回跳到第 1 小节开头再闪一下「跳转后」；每遍如此；
     4. 同上但**开着循环段预备拍** → 第 2 小节不闪，倒数那一小节闪第 1 小节（循环起点）；
     5. 不涉及反复的普通循环 → 预告 + 回跳闪一下；
     6. 反复跳转（自动跳）那条路不受影响：跳跃前那一小节每拍一下、落地闪「跳转后」。
