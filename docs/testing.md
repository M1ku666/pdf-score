# 测试与验证 · PDF Score

---

## 1. 改动内容 → 该跑什么（自动化默认不主动跑）

**默认：AI agent 不主动跑任何自动化测试**（`test:unit` 也不跑，e2e 本来就没有）。改完只说明「改了哪些文件、期望看到什么」；**要跑之前先问用户**。

**唯一例外是动算法时给一句提醒**：碰了 `src/domain/*`（结构、时间轴、拍号、反复、峰值、zip、OMR）就在回复末尾加一句「这次碰了算法，建议跑 `npm run test:unit`（纯 node，几秒钟，不用起服务）」——**只提醒，不擅自跑**，跑不跑由用户决定。

| 改动内容 | 该跑 | agent 默认行为 |
| --- | --- | --- |
| `src/domain/*`（结构、时间轴、拍号、反复、峰值、zip、OMR） | `npm run test:unit` | 不跑，**提醒一句** |
| UI / 交互 / 组件 / 触屏布局 | **不要自己跑**，交回用户手工验证（见下） | 说明期望效果，交用户 |
| 构建、路由、依赖、pdf.js 资源、`netlify.toml` | `npm run build && npm run preview` 后手工点一遍 | 不跑；仅在**准备合入 / 发布 / 改构建配置**时问一次 |

**为什么这么定（别把它当默认项又打开）**：代价要认：`src/domain/*` 的错误**从界面看不出来**（错的是小节 ↔ 时间映射、反复该跳哪里，谱面照常滚），拖到手工点谱面时才暴露，且那时往往叠了好几处改动，定位更贵。所以动算法那**一句提醒**是关键，别省。

- `npm run test:unit` 覆盖：结构推导、调速时间轴、小节 ↔ 时间、反复与房子展开、**反复区块配对与房子跨度（`matchRepeatBlocks` / `deriveRepeatBlocks`）**、psz / zip 打包、边界、**谱面识别（合成墨点图上找谱表 / 合行 / 找小节线）**、**节拍器前瞻排程（倍速 > 1 时不重复排同一批拍子；暂停后不再排）**。

## 2. 没有端到端测试

**没有端到端测试，也不要引回来**：UI / 交互改动一律说明「改了哪些文件、期望看到什么」，交给用户手工验证。

## 3. 触屏审计阈值

可点元素 **≥ 36px**（比设计规范 `--tap-min: 46px` 宽松，作为回归下限）、不横向溢出、不重叠、文字不截断，并覆盖**横屏 / 平板 / 桌面**三种视口。

**hover 只在桌面（鼠标）生效：手机上点完任何控件都不应残留悬停态。**
